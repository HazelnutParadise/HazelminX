**Epic:** API 代理（`epic:api-proxy`）  
**User Story:** 管理員可以把內部 API 交給特定人使用

**Status:** blocked

## What it delivers

20.1 契約（URL Token 辨識、Bearer、X-Infra-Token-Source、403／404）、服務／使用者／Token 管理、入口端政策快照與 5 分鐘離線有效期、轉送語意、上游驗證分離、用量與失敗分類、限速、拒絕目標（metadata／內網／管理 API）、長連線撤銷政策。

## Acceptance criteria

- [ ] **API-001** 管理員可以新增、修改、停用服務與指定代理目標。 — 完成條件：可選主機服務、容器、叢集服務或明確允許的外部 HTTP 位址。
- [ ] **API-002** 管理員可以管理使用者、Token、到期日與授權服務。 — 完成條件：停權及撤銷對新請求生效；離線代理的生效界線與政策版本可查。
- [ ] **API-003** 客戶端可以沿用既有路徑、驗證方式與回應碼。 — 完成條件：以相容測試覆蓋有效、過期、停權、誤判路徑、缺服務與 Bearer 強制指定。
- [ ] **API-004** 客戶端可以正確轉送方法、路徑、query、上傳與串流。 — 完成條件：編碼、重複 query、尾斜線、取消及大型 body 不被意外改寫；逐跳專用 Header 正確處理。
- [ ] **API-005** 管理員可以設定上游驗證與 Header 規則。 — 完成條件：代理驗證 Token 與上游 API Key 分開；不把機密出現在 URL 或錯誤文字。
- [ ] **API-006** 管理員可以查看每人、每 Token、每服務的使用量與失敗。 — 完成條件：分開驗證拒絕、上游連線、HTTP 錯誤及傳輸未完成，不以 200 保證內容送完。
- [ ] **API-007** 管理員可以設定限速、用量上限與允許的方法／路徑。 — 完成條件：限制範圍與時間窗明確；多節點限速不是各自算完卻宣稱全域上限。
- [ ] **API-009** 管理員可以查代理目標被拒絕的原因。 — 完成條件：防止未授權存取管理 API、metadata、任意內網與重新導向後的禁用目標。
- [ ] **API-010** 管理員可以決定既有長連線在撤銷後的處理。 — 完成條件：新請求立即依有效政策拒絕；現有連線可設定中止或排空，不隱瞞撤銷延遲。
- [ ] 相容測試覆蓋有效、過期、停權、誤判路徑、缺服務與 Bearer 強制指定
- [ ] 所有 Token 在日誌、WAF、診斷包與分析進庫前遮罩
- [ ] （API-001 細化，2026-11-08 使用者提問）目標是容器或部署單元的服務時，分兩步選：先選容器或服務，再從它的 Port 清單選一個。Port 清單合併映像 EXPOSE、compose 的 ports／expose，以及容器內實際監聽的 Port，每個標出來源與探測結果（HTTP 回應碼、是否 TLS）；UDP 與探測不是 HTTP 的 Port 照樣列出但不能選，並寫出原因。一個代理服務對一個 Port，要開放同一容器的多個 Port 就建多個服務。目標是有多個副本的服務時，請求分散到健康的副本，不綁定單一容器。容器重建或 IP 改變後，目標依服務身分重新解析，不綁死舊 IP。
- [ ] （API-001 細化，2026-11-08 使用者新增）API 代理可以設定專屬網址，經 Zentinel 對外並自動申請憑證：整體網址（例如 `api.example.tw`）照 20.1 的 `/use/<服務>/…` 與 `/api/` 路徑運作；服務專屬網址（例如 `ollama.api.example.tw`）直接對應單一服務，不必寫 `/use/<服務>`，只接受 Bearer，不支援把 Token 放在路徑。一個服務可以有多個網址；DNS 沒指向入口時寫出要加的紀錄。回應碼與 20.1 相同（路徑錯誤 400、服務不存在 404、Token 無效／過期／使用者停權 403）。

## Acceptance tests（第 42 章）

- **T-097** 請求 URL、Cookie、body 含測試秘密。 → 日誌、錯誤、分析、匯出與支援包不洩漏。
