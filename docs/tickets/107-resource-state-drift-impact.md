## What it delivers

所有受管資源共用的狀態模型與依賴圖：控制者、現場與平台記錄不同（漂移）、觀測時間、鎖；漂移的採納、還原、保留唯讀；寫入前從同一份依賴圖算出影響；名稱、主機名、IP 歷史；偵測同主機的其他管理工具。畫面上以資源狀態條與影響預覽兩個共用元件呈現。細化 ARC-005 與規格 34.2。

## Acceptance criteria

- [ ] **ROB-001**（增補 03）維運者可以在每個受管資源看到控制者、漂移、觀測時間與鎖（細化 ARC-005、34.2）。 — 完成條件：四件事出現在同一條資源狀態條，適用 51.2 機制一列出的所有資源類型；漂移列出差異欄位。同一資源偵測到兩個控制者時（例如 certbot 與 Zentinel 都在續同一張憑證），狀態條標「控制者衝突」並寫出實際生效的是哪一方。
- [ ] **ROB-002**（增補 03）維運者可以對任何資源類型的漂移選擇採納、還原或保留唯讀（把 34.2 推廣到所有資源類型）。 — 完成條件：平台不自動改回現場。還原走變更計畫與差異預覽。現場資源已不存在時，採納會把平台記錄標為「已在平台外移除」。保留唯讀後，可依 CTR-009 再接管。
- [ ] **ROB-003**（增補 03）系統在寫入前，從 51.2 機制二定義的單一依賴圖算出受影響的對象並呈現。 — 完成條件：下列動作全部使用同一份圖：停止、重啟、刪除、升級、重開機、進入維護、移除引擎、撤銷權杖、改 Port、停用模組；新增的寫入動作也必須接上。被引用的資源，刪除鈕停用並列出引用者。
- [ ] **ROB-006**（增補 03）系統保留資源的名稱、主機名與 IP 歷史，並區分邏輯資源與執行實例。 — 完成條件：改名或換 IP 後，歷史與告警仍連到同一資源。平台部署或還原時重建的容器，歷史掛在同一個服務上。平台以外建立的同名容器視為新資源。
- [ ] **ROB-012**（增補 03）系統可以偵測同一主機上的其他管理工具，並標出它們控制的資源。 — 完成條件：依各工具的已知特徵判定：systemd 服務、資料目錄、Compose 工作目錄、容器標籤，判定規則寫在各工具的 adapter。例如 Compose 工作目錄位於 1Panel 安裝目錄的 `apps/` 底下，就判定由 1Panel 控制。判斷不出來的資源標為「未接管」，不猜。被其他工具控制的資源，在接管前保持唯讀。

## Acceptance tests

- **T-157** 在主機上用 `docker rm` 刪掉平台管理的容器。 → 下次觀測時標為漂移。提供還原（走變更計畫）、採納（平台記錄標「已在平台外移除」）、保留唯讀；平台不自動重建。
- **T-158** 主機上裝著 1Panel（預設安裝目錄），它用 Compose 部署了 3 個應用容器。 → 節點的元件矩陣列出 1Panel。這 3 個容器的控制者標 1Panel、保持唯讀，直到依 CTR-009 接管。
- **T-159** 停止 Zentinel 前查看影響。 → 影響預覽列出所有依賴它的站點與憑證；與刪除、重開機時看到的影響來自同一份依賴圖。
- **T-162** 節點改主機名並換 IP。 → 仍是同一個節點；顯示曾用名與曾用 IP；舊告警仍連到它。
- **T-169** 一個由平台部署的服務重新部署（容器重建）。 → 服務的歷史、告警與站點路由連續，不被當成新資源。
