# 017 — 使用者可以在主導覽、全域搜尋與工作中心之間完成日常操作

**Epic:** 基礎建設（`epic:foundation`）  
**User Story:** 使用者可以在一致的介面完成日常管理  
**Milestone:** M1 單機主機管理  
**Blocked by:** [005 使用者可以開啟 React 介面並切換語言與淺深色](005-web-skeleton.md), [008 使用者可以提交工作後關閉頁面，之後仍能查到進度、證據與結果](008-job-engine.md), [010 整合者可以用 /management/v1 的分頁、版本條件與工作回應操作資源](010-management-api-contract.md)  
**Status:** ready  
**規格章節:** 07｜介面與操作體驗  
**Issue:** [#17](https://github.com/HazelnutParadise/hazelminx/issues/17)  

## What it delivers

7.1 的主導覽、資源永久識別碼的跨頁連結、工作中心與事件串流接續、權限過濾搜尋、載入／空／錯誤／部分／離線狀態元件、錯誤四段式呈現、大型表格與日誌的虛擬捲動與取消查詢。

## Acceptance criteria

- [ ] **UI-002** 使用者可以在服務頁直接查看節點、引擎、連接埠、網域、資料、日誌與版本。 — 完成條件：不必複製容器 ID 到其他頁手動搜尋才能完成基本工作。
- [ ] **UI-003** 使用者可以從任何頁面回到進行中的工作。 — 完成條件：重新整理或關閉瀏覽器不取消伺服器端任務；重新登入可接續看進度。
- [ ] **UI-004** 使用者可以搜尋自己有權限的資源。 — 完成條件：搜尋不洩漏無權查看的名稱、IP、機密或節點存在與否。
- [ ] **UI-007** 使用者可以知道載入、空資料、錯誤、部分結果與離線的差別。 — 完成條件：沒資料不能顯示成零；過期資料顯示觀測時間；錯誤保留輸入內容。
- [ ] **UI-011** 使用者可以讀懂主要錯誤，不需先懂錯誤代碼。 — 完成條件：顯示「發生什麼、影響什麼、證據、下一步」；底層日誌可展開。
- [ ] **UI-012** 使用者操作大型表格與日誌時不會讓整頁失去回應。 — 完成條件：分頁或虛擬捲動；可取消查詢；有資料量與截斷提示；保留篩選狀態。
- [ ] 重新整理或關閉瀏覽器不取消伺服器端任務；重新登入可接續看進度
- [ ] 搜尋不洩漏無權查看的名稱、IP 或節點存在與否
- [ ] 對話框依 DESIGN.md「對話框關閉規則」：有輸入或未儲存變更時點背景不關閉，Esc 與關閉鈕改問「儲存／不儲存／取消」；執行中不可中斷的對話框沒有關閉，只能「在背景繼續」到工作中心。
- [ ] **ROB-004**（增補 03）使用者可以知道平台與各節點目前是否降級，以及還能做什麼。 — 完成條件：依機制四全文運作，包括表格的進入與解除門檻、時間來源規則、同時降級的優先順序、資料庫唯讀時的稽核與工作處理；平台層級出現頂端降級列，節點與引擎環境層級只出現在該節點頁與相關資源狀態條；不能做的動作畫面停用並寫出原因，API 依錯誤代碼表拒絕。
- [ ] **ROB-005**（增補 03）管理員可以為節點與專案環境標示用途等級（專案環境沿用 34.1 的正式／測試，另加實驗；節點為新增）。 — 完成條件：有效等級依機制三計算，顯示在頁面標題區、資源狀態條與終端機分頁；UI-006 的高風險確認與 ENG-005 的變更計畫批准畫面，對正式等級資源寫出等級與目標名稱；未標示時不顯示徽章。
- [ ] **ROB-007**（增補 03）使用者看到的不可信文字完整且安全（細化 36.3）。 — 完成條件：名稱類欄位的控制字元、方向控制字元、零寬字元以可見符號顯示；非 UTF-8 檔名可以顯示、改名、下載並檢視原始位元組；超長名稱換行不截斷；日誌的 ANSI 色碼轉成顏色，其他控制序列移除並標出。
- [ ] **ROB-008**（增補 03）每個列表與查詢宣告其邊界，並在超出時說明。 — 完成條件：`/management/v1` 列表回應的中繼資料與 UI 表格底部寫出每頁筆數、查詢上限、逾時；超過上限顯示「可瀏覽前 N 筆／總數 M」；逾時顯示「總數未知」；兩者都可以改成背景工作。
- [ ] （增補 03 51.6）設計時決定並寫進本票：Core 時間不可信時對 TOTP、TLS、權杖到期的影響與替代登入；背景查詢結果的上限、呈現與保存；磁碟不足時允許的清理與搬移工作清單；只有一邊標示用途等級時的比較；節點時間來源連不上的判定；並補上降級解除、未設定時間來源、ANSI 日誌、零寬字元與 emoji 例外的驗收案例。
- [ ] 資源狀態條、影響預覽、降級列、用途等級徽章、套用確認倒數是共用元件，所有資源頁面與列表使用同一組元件（增補 03 51.1）。
- [ ] （設計規則，2026-11-08）所有檔案、資料夾與清單選擇器：不能選的項目照樣列出，呈現不可選的樣式（降低不透明度、鎖頭、`aria-disabled`），滑過或聚焦顯示原因；不得直接隱藏。
- [ ] （設計規則，2026-11-08）所有可編輯的畫面：有未儲存的變更時，底部固定儲存列（未儲存數量、生效條件、寫出結果的主按鈕、捨棄、⌘S），分頁有未儲存圓點，離開前詢問；沒有變更時不出現、儲存鈕停用。
- [ ] **ROB-013**（增補 03）使用者在平台依賴的元件停止時，仍能開啟依賴它的頁面，並一鍵重啟該元件（2026-11-08 使用者新增）。元件指平台安裝或接管、其他功能要靠它運作的 systemd 服務或容器，例如 Zentinel（systemd 服務）、cloudflared、Ollama、內建推論 runtime、平台管理的資料庫。橫條寫出元件是 systemd 服務還是容器，重啟用對應的方式（systemctl 或引擎）。 — 完成條件：頁面照常開啟，不出現空白頁或錯誤頁。頁首顯示元件停止橫條，寫出：哪個元件、在哪台主機、停止多久、最後的退出碼與原因（例如 OOM）、受影響的功能。橫條有「重啟」主按鈕與「看日誌」，日誌預設顯示停止前最後 50 行。重啟是一個工作，結果回到同一條橫條；連續失敗時顯示失敗次數與最後的錯誤，不在背景無限重試。頁面其他資料以上次觀測值呈現並標時間；需要該元件的動作停用並寫出原因，跟它無關的部分照常可用。重啟需要的權限與該元件的操作權限相同；沒有權限的人看得到橫條，按鈕停用並寫出要找誰。

## Acceptance tests（第 42 章）

- **T-119** 資源與日誌數量達壓測規模。 → 分頁、取消、搜尋、事件串流仍符合目標。
- **T-160** 平台資料庫變成唯讀，稽核附加檔可寫入。 → 出現頂端降級列；可以登入；寫入按鈕停用並寫出原因，對應的 API 回 `PLATFORM_DEGRADED`；可以下載診斷包；資料庫恢復後，稽核附加檔的紀錄補回資料庫。
- **T-161** 節點標正式、專案環境標測試，部署政策要求預覽與批准，對該專案環境部署。 → 有效等級為正式；部署預覽與批准畫面寫出「正式」與專案環境、節點名稱。
- **T-163** 資料夾裡有非 UTF-8 檔名。 → 可以列出、改名、下載，並可檢視原始位元組。
- **T-164** 查詢 1 萬筆容器事件時逾時。 → 顯示已取得筆數與「總數未知」；改成背景工作後，在工作中心看到完整結果。
- **T-171** 100 台節點中有 1 台離線。 → 不出現頂端降級列；該節點頁顯示離線；對它的新工作進入排隊，不立即執行；其他節點不受影響。
- **T-174** 從終端機開啟一台標為正式的節點。 → 終端機分頁顯示正式等級徽章。
- **T-175** 有一個檔名含 U+202E 方向控制字元，另一個容器標籤值含換行與控制字元，還有一個長度超過 100 字元的合法容器名。 → 方向控制字元與控制字元以可見符號顯示；長容器名完整換行，不截斷。
- **T-179** 平台資料目錄所在檔案系統剩 3%。 → 出現頂端降級列；可以新增清理工作；排程觸發的備份被擋下並記錄，之後依 JOB-005 處理；上傳停用。
- **T-180** 節點與時間來源相差 150 秒。 → 該節點頁標時間偏差；該節點的平台計畫任務暫停執行但可編輯；ACME 續期暫停；其他節點照常。
- **T-181** 某引擎環境的 Docker 服務停止。 → 連續 3 次探測失敗後，該環境的容器操作停用，API 回 `SCOPE_DEGRADED`；仍可讀日誌並執行授權的修復。
- **T-182** 查詢結果有 25,000 筆（超過預設上限 10,000）。 → 顯示「可瀏覽前 10,000 筆／總數 25,000」，不能再往後翻頁，提供改成背景工作。
- **T-185** Core 與時間來源相差 90 秒。 → 出現頂端降級列並告警；所有操作照常；變更計畫的批准期限仍依實際經過時間到期。
- **T-186** 平台資料磁碟滿，資料庫也因此寫入失敗。 → 降級列以「資料庫唯讀」為準；網頁上不能新增任何工作，包括清理；可用 CLI 清理。
- **T-187** 資料庫唯讀，稽核附加檔也寫不進去。 → 拒絕新的網頁登入；已登入的工作階段轉為只能讀取；降級列寫出「稽核無法寫入」；CLI 救援的稽核出現在系統日誌。
- **T-231** 在 tw-01 停掉 Zentinel（systemd 服務 zentinel.service）後，開啟「網站與入口」。 → 頁面照常開啟；頁首寫出 Zentinel 已停止、停止時間、退出碼與「所有站點目前無法連線」；站點清單顯示上次觀測的值並標時間；新增站點、套用設定停用並寫出原因，憑證清單與存取日誌照常可看；按「重啟」後 Zentinel 啟動，橫條消失。
- **T-232** Ollama 容器因記憶體不足（OOM，退出碼 137）反覆停止，開啟 AI 頁。 → 橫條寫出 OOM 與退出碼 137；重啟兩次都失敗後，橫條顯示失敗次數與最後的錯誤，平台沒有在背景繼續重試；只有唯讀權限的使用者看到停用的重啟鈕與要找誰。
