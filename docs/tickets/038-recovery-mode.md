## What it delivers

Core 啟動時資料庫遺失或損壞進入復原狀態；需宿主機控制權或復原金鑰的本機重設登入；每次救援有紀錄；Docker／K3s 停止時仍可登入、讀日誌與修復。

## Acceptance criteria

- [ ] **IAM-008** 擁有者可以使用離線救援方式重設登入。 — 完成條件：需要宿主機控制權或復原金鑰；不得提供匿名網頁重設入口。
- [ ] **SEC-012** 管理員可以使用緊急本機復原方式。 — 完成條件：必須具有作業系統授權；每次救援有紀錄；不能存在全球通用的後門密碼。
- [ ] **ARC-001** 管理員可以在 Docker 或 K3s 停止時繼續登入及診斷主機。 — 完成條件：Core、Agent 與管理資料不依賴故障引擎；實際停止引擎後仍能讀取原因。
- [ ] **PKG-006** 管理員可以在容器引擎故障時管理主機。 — 完成條件：Docker／K3s 停止仍能登入、讀日誌與執行獲授權的修復。
- [ ] **INS-007** 管理員可以在沒有 Docker／K3s 時使用主機管理。 — 完成條件：停掉容器引擎後 Core 與 Agent 仍可查日誌、修復套件及管理主機。
- [ ] 不存在全球通用的後門密碼
- [ ] 不自動建立空白庫假裝全新安裝

## Acceptance tests（第 42 章）

- **T-012** Core 啟動時管理資料庫遺失或損壞。 → 進復原狀態，不自動建立空白庫假裝全新安裝。
- **T-120** 關閉 Core、Docker 或 Zentinel 各自測試。 → 故障影響限於合理邊界，管理救援與既有流量分開判斷。
