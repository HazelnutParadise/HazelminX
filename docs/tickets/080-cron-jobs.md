# 080 — 管理員可以建立計畫任務，設定重疊、錯過、重試、依賴、通知與腳本庫

**Epic:** 計畫任務（`epic:jobs`）  
**User Story:** 管理員可以安排工作  
**Milestone:** M4 資料庫、AI、備份與監控  
**Blocked by:** [008 使用者可以提交工作後關閉頁面，之後仍能查到進度、證據與結果](008-job-engine.md), [017 使用者可以在主導覽、全域搜尋與工作中心之間完成日常操作](017-ui-shell.md)  
**Status:** blocked  
**規格章節:** 28｜計畫任務與工作執行  
**Issue:** [#79](https://github.com/HazelnutParadise/hazelminx/issues/79)  

## What it delivers

Cron 與時區與接下來五次、任務種類（備份／腳本／URL／清理／維護）、立即執行／暫停／取消語意、重疊與錯過政策、安全重試、依賴與清理、通知與靜音、腳本庫版本、夏令時間、離線預授權工作去重補報。

## Acceptance criteria

- [ ] **JOB-001** 管理員可以用常見頻率或 Cron 建立排程。 — 完成條件：顯示所用時區與接下來五次執行時間，避免誤讀。
- [ ] **JOB-002** 管理員可以建立備份、腳本、URL、清理、維護及自訂工作。 — 完成條件：指定節點、執行者、工作目錄、環境、秘密、逾時與資源限制。
- [ ] **JOB-003** 使用者可以立即執行、暫停、恢復與取消工作。 — 完成條件：取消分成要求取消、已安全停止、不能在此步驟取消，不以 UI 消失代替停止。
- [ ] **JOB-004** 管理員可以設定重疊政策。 — 完成條件：同任務前次未完成時，明確跳過、排隊或允許並行；預設不並行。
- [ ] **JOB-005** 管理員可以設定錯過排程的處理。 — 完成條件：重開機後選擇跳過或補一次，不把一週錯過的備份瞬間全部重跑。
- [ ] **JOB-006** 管理員可以設定失敗重試。 — 完成條件：只自動重試已知安全步驟；不確定是否完成的付款、刪除、格式化或 migration 不盲重試。
- [ ] **JOB-007** 使用者可以看每次工作進度、輸出與結果。 — 完成條件：日誌與狀態持久保存；前端斷線不丟工作；同一工作有穩定 ID。
- [ ] **JOB-008** 管理員可以設定任務依賴與失敗處理。 — 完成條件：停寫、備份、恢復服務等步驟順序固定；失敗後應做的清理仍被執行。
- [ ] **JOB-009** 管理員可以設定通知與靜音時段。 — 完成條件：成功、失敗、部分成功與取消分開；未送達有重試及站內可查記錄。
- [ ] **JOB-010** 管理員可以管理腳本庫與版本。 — 完成條件：看到作者、版本、權限與內容；更新腳本不悄悄擴大已批准工作範圍。
- [ ] **JOB-011** 平台可以處理夏令時間與時鐘偏差。 — 完成條件：重複或不存在的當地時間使用明確策略；工作識別以排程實例而非僅文字時間。
- [ ] **JOB-012** 管理員可以設定節點離線期間的本地工作。 — 完成條件：只有預先授權且未過期的工作可執行；回連後去重補報，不重複發通知。
- [ ] URL 任務不能讀取未授權內網或主機 metadata
- [ ] （JOB-002 細化，2026-11-08 使用者新增；套件更新本身由票 021 的 SYS-002、SYS-003 提供）計畫任務有「升級套件」類型：選主機（可多台）、只套安全更新或全部、排除的套件、需要重開機時的處理（不重開、排進維護時段、立即），執行時沿用票 021 的更新流程與影響圖示；主機已啟用 unattended-upgrades 或 dnf-automatic 時，建立前提醒會重複。

## Acceptance tests（第 42 章）

- **T-114** 排程遇夏令時間重複小時與漏掉小時。 → 依已選政策只補跑允許次數，顯示時間解讀。
- **T-115** 同一排程重疊或 Core 重啟。 → 依禁止重疊／排隊政策執行，不重複跑破壞性工作。
- **T-116** Agent 離線執行預先授權備份後恢復。 → 回報原工作 ID 與完整結果，不當成新工作再跑。
