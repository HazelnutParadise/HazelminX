# 037 — 管理員可以用離線包安裝，並解除安裝平台而保留應用與移交維護

**Epic:** 安裝、更新與卸載（`epic:install`）  
**User Story:** 管理員可以安裝與啟動平台  
**Milestone:** M1 單機主機管理  
**Blocked by:** [013 管理員可以一行安裝單機模式、重開機後登入，且安裝不需要任何編譯器](013-one-line-install.md), [113](113-host-change-ledger.md)  
**Status:** blocked  
**規格章節:** 08｜安裝、更新、開機自啟與解除安裝、39｜跨功能流程：從按鈕到真正完成  
**Issue:** [#37](https://github.com/HazelnutParadise/hazelminx/issues/37)  

## What it delivers

離線包完整性清單、安裝時偵測 1Panel／Portainer 的雙重管理風險、按需安裝額外能力的預覽、卸載選項（平台／平台資料／選配元件）、維護缺口移交、只清除可證明屬於自己的變更、本機報告。

## Acceptance criteria

- [ ] **INS-011** 管理員可以使用離線安裝包。 — 完成條件：包含選定功能需要的執行檔、映像、規則、授權及完整性清單；缺少檔案在變更前指出。
- [ ] **INS-012** 管理員可以解除安裝平台，選擇是否保留管理資料。 — 完成條件：預設保留應用與持久資料；不移除原本就存在的 Docker、資料庫或共用套件。
- [ ] **INS-014** 安裝程式可以識別已有 1Panel、Portainer 或其他控制工具。 — 完成條件：告知相同資源的雙重管理風險；沒有移交批准不停止它們或修改其資料。
- [ ] **PKG-003** 管理員可以按需安裝額外能力。 — 完成條件：安裝前顯示新增套件／服務／版本／來源；取消不造成變更。
- [ ] **UN-001** 管理員可以移除平台但留下應用。 — 完成條件：原有容器、資料庫、模型、掛載與持久資料不被刪除或重建。
- [ ] **UN-002** 管理員可以選擇是否清除平台資料。 — 完成條件：刪除清單先呈現；保留資料有位置與用途說明；不把保留狀態稱為完全清空。
- [ ] **UN-003** 管理員可以知道卸載造成的維護缺口。 — 完成條件：Zentinel、Token 驗證、WAF、憑證續期、備份與磁碟保護的影響都列出並處理。
- [ ] **UN-004** 卸載器可以只清除可證明屬於自己的變更。 — 完成條件：不移除共用套件、不恢復過時防火牆規則、不沿符號連結誤刪其他路徑。
- [ ] **UN-005** 管理員可以在 UI 消失後取得結果。 — 完成條件：本機報告或 CLI 仍可查卸載結果；需要重開機或人工處理時明確列出。
- [ ] 不移除原本就存在的 Docker、資料庫或共用套件
- [ ] 符號連結與重新解析點不把刪除導向別處
- [ ] **UNX-003**（增補 07）管理員可以從三種移除方式中選擇，並看到逐項預覽。 — 完成條件：依 55.2 的表處理每一筆；預設是只移除平台；預覽寫出每一項的處理方式、原因與帳本來源。
- [ ] **UNX-004**（增補 07）完全移除只移除帳本證明是平台安裝、而且沒有其他東西在用的項目，並把平台改過的既有設定還原成安裝前的值。 — 完成條件：平台安裝但仍在被使用的、使用者後來改過的，列出讓使用者決定；既有的不動；不沿符號連結刪除其他路徑（UN-004）。
- [ ] **UNX-005**（增補 07）使用者資料只有在逐項勾選後才刪除。 — 完成條件：預設保留；每項可以先匯出；刪除要輸入主機名稱確認。
- [ ] **UNX-006**（增補 07）管理員可以移除一台主機，或移除整個平台；主機連不上時可以用離線移除包。 — 完成條件：移除一台主機不影響其他主機；離線移除包只靠本機帳本就能完成，並寫出本機報告。
- [ ] **UNX-007**（增補 07）移除後平台比對安裝前快照並留下報告。 — 完成條件：報告列出相同、不同（含原因）與需要重開機的項目；保存在 `/var/log/hazelminx-uninstall-<時間>.txt` 並可用 CLI 再看；不含機密值。

## Acceptance tests（第 42 章）

- **T-002** 安裝到已有 1Panel 與正式容器的主機。 → 偵測衝突並提出計畫；未批准前不改舊服務。
- **T-010** 使用完整離線包安裝。 → 不默默連外抓缺少元件；缺件時列清單。
- **T-011** 解除安裝 HazelminX，選保留應用。 → 應用與資料不刪；已移除與保留項目可核對。
- **DEP-T09** 普通卸載平台，主機原本就有 Docker 和資料庫。 → 原有套件、資料、容器及帳號權限未被誤移除。
- **DEP-T10** 欲移除正在為網站服務的 Zentinel／WAF。 → 先列網站與授權影響；未批准不停止入口、不降低保護。
- **DEP-T11** 應用開機依賴 Agent 的資料磁碟檢查。 → 卸載前完成保護移交或明確停用依賴的自動啟動，不留下不安全配置。
- **DEP-T12** 檔案目錄內放符號連結或 Windows 重新解析點。 → 卸載不越界刪除；被使用者修改的設定先比對再處理。
- **T-244** 在一台全新的 Debian 主機安裝平台（平台順帶裝了 Docker 與 Zentinel），部署一個應用，接著選完全移除，應用與資料都勾選刪除。 → 報告寫出與安裝前快照相同；Docker、Zentinel、平台的 apt 來源與金鑰、`hazelminx` 使用者、平台的 systemd 單元與防火牆表都不存在；監聽中的 Port 與安裝前相同。
- **T-245** 安裝前主機已有 Docker 與一個使用者自己的容器，journald 已設 `SystemMaxUse=500M`。安裝平台後選完全移除。 → Docker 與使用者的容器都還在；journald 維持 500M；平台加的 `daemon.json` `log-opts` 被還原成安裝前（不存在）。
- **T-246** 平台裝了 Docker，之後使用者用 CLI 自己建了一個容器。選完全移除。 → Docker 沒有被移除，預覽寫出「有使用者自己建的容器在用」，讓使用者決定。
- **T-247** 平台寫過 `/etc/ssh/sshd_config.d/50-hazelminx.conf`，使用者後來手動改了這個檔案。選完全移除。 → 這個檔案列為「使用者改過」，讓使用者選還原或保留，沒有被直接刪除。
- **T-248** 選完全移除，但沒有勾選刪除 shop-db 的資料。 → shop-db 的資料目錄與儲存卷都還在；報告列出它們的位置與「使用者選擇保留」。
- **T-249** 移除整個平台時，hazel-jp-02 連不上。 → 其他主機照常完成；jp-02 產生離線移除包；在 jp-02 上執行後完成移除並寫出本機報告。
- **T-251** 移除過程中，移除 Zentinel 這一項失敗。 → 其他項目照常完成；報告最後列出 Zentinel 移除失敗與原因；報告沒有宣稱與安裝前相同。
