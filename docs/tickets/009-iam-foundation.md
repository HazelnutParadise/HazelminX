## What it delivers

登入工作階段（HttpOnly Cookie、CSRF 防護）、5.1 的角色預設、資源範圍、權限預設拒絕的中介層、稽核紀錄（操作者、前後摘要、工作編號、遮罩）、登入嘗試限制。

## Acceptance criteria

- [ ] **IAM-001** 擁有者可以建立帳號、角色與資源範圍，權限預設拒絕。 — 完成條件：對未授權節點手動呼叫 API 也遭拒絕，不只隱藏按鈕。
- [ ] **IAM-006** 稽核者可以查誰在何時改了什麼。 — 完成條件：同一操作能連回變更前後摘要、工作編號、節點與結果，機密保持遮罩。
- [ ] **IAM-012** 系統可以限制登入與復原碼嘗試。 — 完成條件：不洩漏帳號存在與否；按帳號與可信來源限制，不能讓攻擊者簡單永久鎖死所有管理員。
- [ ] 專案 A 使用者猜專案 B 的資源 ID 時，查詢、下載、搜尋與事件串流都不洩漏
- [ ] 不洩漏帳號存在與否；限制不能讓攻擊者永久鎖死所有管理員

## Acceptance tests（第 42 章）

- **T-013** 唯讀帳號直接呼叫變更 API。 → 後端拒絕，不只隱藏 UI 按鈕。
- **T-014** 專案 A 使用者猜專案 B 的資源 ID。 → 查詢、下載、搜尋、事件串流都不洩漏內容。
