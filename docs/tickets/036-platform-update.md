## What it delivers

自動檢查與下載、批准或維護時段套用、版本目錄切換、資料格式相容檢查、Agent 安全點等待、健康檢查失敗復原、UI 與 API 版本不相容時要求重新載入。

## Acceptance criteria

- [ ] **INS-009** 管理員可以更新 HazelminX，保留設定與資料。 — 完成條件：更新前檢查版本路徑與資料格式；切換失敗能回到相容舊版本或進入明確復原流程。
- [ ] **INS-010** 管理員可以指定版本、更新通道與維護時段。 — 完成條件：不因查到更新就自動重啟；舊版有安全風險時提示，不自行改變策略。
- [ ] **REL-003** 管理員可以自動檢查與下載更新。 — 完成條件：不因查到版本而重啟服務；依其核准策略才套用。
- [ ] **REL-004** 系統可以在 GitHub 異常時保留服務。 — 完成條件：限流、斷線、過期驗證或找不到檔案不刪除現有版本，並支援可信離線包。
- [ ] **REL-005** 管理員可以在安全點更新。 — 完成條件：工作排程、Agent 更新與資料庫升級不互相破壞，狀態可追溯。
- [ ] **REL-006** 管理員可以取得正確的復原結果。 — 完成條件：不能降版的資料格式會阻擋盲目切回；失敗、已復原與待人工處理分開顯示。
- [ ] **REL-007** 管理員可以看到外部元件版本與依賴。 — 完成條件：不分別抓取不相容的最新版本；簽章與建置來源可驗證。
- [ ] **DAT-006** 維護者可以升級資料格式。 — 完成條件：先備份與檢查相容性；不能直接用舊執行檔開啟已不相容的新資料。
- [ ] 不因查到版本而重啟服務
- [ ] GitHub 限流或斷線不刪除現有版本並支援離線包
- [ ] 協定不相容、被 Core 拒絕連線的 Agent，可以經已驗證的升級路徑更新到相容版本；更新完成前，該節點不接受其他變更（SEC-011 的升級路徑，需求由票 007 擁有）

## Acceptance tests（第 42 章）

- **T-008** 更新後新服務健康檢查失敗。 → 執行可用復原，顯示原更新失敗與復原結果。
- **T-009** 資料格式升級後要求直接降版。 → 先檢查相容性，拒絕不安全開啟新資料。
- **DEP-T04** 下載中斷、成品被修改或 CPU 不相符。 → 在替換現有檔案前失敗；舊版保持可用。
- **DEP-T05** GitHub API 限流或下載服務中斷。 → 重試有上限，現有服務不受影響，可使用已驗證離線包。
- **DEP-T06** UI 與 API 版本不相容。 → 阻止不相容操作並要求更新頁面，不送出含義錯誤的命令。
- **DEP-T07** 備份／資料庫升級進行中要求更新 Agent。 → 等待安全點或經驗證移交，不直接殺掉工作。
- **DEP-T08** 更新服務未通過健康檢查。 → 依資料相容條件復原；不能復原則明列保護狀態與原因。
