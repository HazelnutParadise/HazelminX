**Epic:** 節點與 Agent（`epic:nodes`）  
**User Story:** 管理員可以把主機納入管理  
**Milestone:** M1 單機主機管理

## What it delivers

註冊碼（期限、次數、群組）、節點身分與指紋、憑證輪替與撤銷、複製 VM 身分衝突偵測、心跳與過期顯示、維護模式、移除節點的四種語意、重連退避與對帳。

## Acceptance criteria

- [ ] **NOD-001** 管理員可以用短效、單次註冊碼加入節點。 — 完成條件：碼使用後失效；註冊可核對主機身分；重複使用不建立第二個節點。
- [ ] **NOD-005** 管理員可以命名、標記、分組與搜尋節點。 — 完成條件：節點身分使用持久 ID／金鑰，不以會改變的 IP 或主機名稱作唯一識別。
- [ ] **NOD-006** 管理員可以撤銷、輪替與重新註冊節點憑證。 — 完成條件：被撤銷節點不能接受新工作；複製磁碟產生的重複身分會被阻止或要求重新註冊。
- [ ] **NOD-007** 管理員可以知道節點離線、資料過期與局部故障。 — 完成條件：顯示最後聯絡時間；離線不等於所有應用已停止；不偽造即時數值。
- [ ] **NOD-008** 管理員可以讓節點進入維護模式。 — 完成條件：阻止新的衝突工作，列出受影響服務；維護結束重新檢查能力與健康。
- [ ] **NOD-009** 管理員可以移除節點而不刪除其應用。 — 完成條件：明確分開「不再管理」「移除 Agent」「移除叢集節點」「刪除工作負載」。
- [ ] **SEC-001** 管理員可以使用一次性碼加入節點。 — 完成條件：過期、已使用、錯群組與撤銷的碼不能重用；重試不產生多個節點。
- [ ] **SEC-002** 系統可以輪替節點憑證。 — 完成條件：先驗證新憑證可用，再撤回舊憑證；有到期告警，時鐘誤差明確顯示。
- [ ] **SEC-003** 管理員可以撤銷節點。 — 完成條件：撤銷後不能收新命令或讀新秘密；現有連線依政策關閉；記錄傳播延遲。
- [ ] **SEC-004** Agent 可以拒絕不屬於自己的操作。 — 完成條件：其他節點、錯誤資源範圍、過期或舊控制世代的命令均被拒絕。
- [ ] **SEC-008** 管理員可以在連線中斷後恢復節點通道。 — 完成條件：使用有上限的重試與等待，不造成連線風暴；重連後先對帳工作，不盲目重送。
- [ ] 40 秒內顯示狀態過期，不斷言主機已關機
- [ ] 被撤銷節點不能接受新工作；離線節點顯示待同步
- [ ] （增補 03 51.6）設計時決定並寫進本票：節點頁「元件清單」的內容與資料來源（銜接 NOD-003、NOD-011）。

## Acceptance tests（第 42 章）

- **T-016** 重用過期與已使用加入碼。 → 不建立節點、不延長有效期。
- **T-017** 複製含相同 Agent 私鑰的 VM 同時上線。 → 辨識身分衝突，要求重新註冊，不混合資料。
- **T-019** 撤銷在線節點後繼續送命令。 → 依撤銷政策切斷或拒絕，顯示完成時間。
- **T-020** 撤銷離線節點或其使用者權限。 → 顯示待同步範圍；重連後不執行舊命令。
- **T-022** Agent 連線進行中輪替憑證。 → 新身分驗證成功再切換；失敗可保留安全通道。
