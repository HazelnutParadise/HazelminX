# 070 — 使用者可以瀏覽與編輯 PostgreSQL 與 MySQL 的結構與資料並執行 SQL

**Epic:** 資料庫（`epic:database`）  
**User Story:** 使用者可以在平台內管理資料庫  
**Milestone:** M4 資料庫、AI、備份與監控  
**Blocked by:** [069 管理員可以安裝或接管資料庫服務，管理帳號、連線、健康與對外開放](069-database-services.md)  
**Status:** blocked  
**規格章節:** 24｜資料庫管理中心  
**Issue:** [#69](https://github.com/HazelnutParadise/hazelminx/issues/69)  

## What it delivers

結構瀏覽、結構變更預覽 SQL 與鎖定風險、分頁資料列編輯（NULL／JSON／時區／二進位）、主鍵定位、併發衝突、SQL 執行（權限由資料庫角色限制）、匯入匯出限制與公式注入防護、資料變更紀錄。

## Acceptance criteria

- [ ] **DB-003** 使用者可以在 HazelminX 內瀏覽及編輯受支援的資料。 — 完成條件：不要求另開 pgAdmin／Redis Commander 才能完成基本資料管理。
- [ ] **DB-006** 使用者可以查詢、匯入與匯出資料。 — 完成條件：有資料量、時間及記憶體限制；長工作可取消；CSV 匯出處理試算表公式注入風險。
- [ ] **DB-009** 稽核者可以查詢資料變更紀錄。 — 完成條件：記錄操作者、目標與操作摘要；預設不複製完整敏感資料列到平台日誌。
- [ ] **PG-001** 使用者可以瀏覽資料庫、Schema、資料表、View、索引與欄位。 — 完成條件：型別、預設值、主鍵、外鍵、限制與註解顯示正確；識別名稱安全引用。
- [ ] **PG-002** 授權者可以新增、修改與刪除資料庫結構。 — 完成條件：執行前顯示將產生的 SQL、影響物件與鎖定風險；危險變更另外確認。
- [ ] **PG-003** 使用者可以篩選、排序、分頁及編輯資料列。 — 完成條件：NULL、空字串、JSON、時區、二進位與大型欄位不混淆；不一次載入整張表。
- [ ] **PG-004** 使用者可以安全修改指定資料列。 — 完成條件：以主鍵或已確認唯一鍵定位；沒有可靠定位條件時禁止假裝精準的單列更新。
- [ ] **PG-005** 使用者可以知道資料是否被其他人同時修改。 — 完成條件：更新檢查原版本或原值；衝突不直接覆蓋，顯示重新讀取與比較。
- [ ] **PG-006** 使用者可以執行 SQL 並查看結果。 — 完成條件：讀寫權限由資料庫角色及後端共同限制，不靠是否以 SELECT 開頭判定安全。

## Acceptance tests（第 42 章）

- **T-098** PostgreSQL 無主鍵資料表編輯一列。 → 要求可靠識別方式或阻止不安全更新，不改到多列。
- **T-099** 兩個使用者同時改相同資料列。 → 衝突可辨識，不靜默覆蓋。
- **T-100** 唯讀 DB 帳號送出會寫入的 SQL。 → 由實際資料庫權限拒絕，不只看字串是否以 SELECT 開頭。
