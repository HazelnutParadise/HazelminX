## What it delivers

docs/baseline/ 內的機器可讀清單：上游路由／畫面、功能、角色、正常流程、例外、對應票號與測試編號、狀態（保留／替代／擴充／經批准移除），以及上游安全修補追蹤表。

## Acceptance criteria

- [ ] **PAR-001** 驗收者可以查每項上游功能的對應位置與狀態。 — 完成條件：清單包含上游版本、路徑、功能、角色、正常流程、例外與測試編號。
- [ ] **PAR-002** 使用者可以在 React 介面完成原有 OSS 工作。 — 完成條件：沒有對應畫面或只剩手動命令，不算功能保留完成。
- [ ] **PAR-003** 管理員可以看到「保留、替代、擴充、經批准移除」四種狀態。 — 完成條件：移除必須有批准紀錄；未做完不得標成「不需要」。
- [ ] **PAR-004** 開發者可以保留成熟 Go 業務邏輯，將宿主機執行轉由 Rust。 — 完成條件：Go 不直接呼叫任意宿主機 shell 來偷偷避開 Rust 邊界。
- [ ] **PAR-007** 維護者可以追蹤上游安全修補。 — 完成條件：每次發布附已合併／替代／不適用的修補紀錄與理由。
- [ ] 清單由 1Panel 原始碼路由與前端路由交叉產生，不只抄選單
- [ ] 每次發布附已合併／替代／不適用的修補紀錄
