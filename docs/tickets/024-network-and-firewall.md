## What it delivers

網卡／IP／DNS／路由／主機名稱／時間服務變更與逾時回復；防火牆規則與 Docker／Podman／K3s 鏈的責任邊界；外部可達性測試。

## Acceptance criteria

- [ ] **SYS-008** 維運者可以管理網卡、IP、DNS、路由、主機名稱及時間服務。 — 完成條件：變更前列明可能斷線影響；連通性未確認時依逾時規則恢復可逆設定。
- [ ] **SYS-009** 維運者可以管理主機防火牆及容器對外暴露。 — 完成條件：顯示系統規則、Docker／Podman／K3s 規則的責任邊界，不清空引擎管理的鏈。[S09](#source-S09)
- [ ] 連通性未確認時依逾時規則恢復可逆設定
- [ ] Docker 發布的連接埠被 UFW 顯示拒絕時，外部測試能發現實際暴露
- [ ] （SYS-009 細化，2026-11-07 使用者決定）維運者可以封鎖或限制容器發布到外部的 Port：完全封鎖外部、只允許指定來源、或改綁 127.0.0.1（後者要重建容器，走工作）。
- [ ] 攔截規則只寫在引擎留給使用者的位置：Docker iptables 後端用 `DOCKER-USER` 鏈；Docker nftables 後端（29 起實驗）用平台自己的 nftables 表與 forward hook；firewalld 用 policy。不修改、不清空 Docker 自己的鏈。
- [ ] 規則帶平台標記可追溯；Docker 重啟、容器重建後仍有效；套用後從外部重測，畫面顯示實測結果而不是「已封鎖」的假設。
- [ ] 新部署預設發布 Port 綁 127.0.0.1、對外只走 Zentinel；要直接開放主機 Port 必須明確選擇。
- [ ] rootless Podman 的 Port 由使用者空間轉發、會經過主機防火牆，畫面標示攔截方式為「主機防火牆」；K3s NodePort／ServiceLB 先顯示與外部實測，攔截導向 K8s 頁。
- [ ] **ROB-010**（增補 03）可能切斷管理路徑的變更，套用前檢查、套用後確認（細化 SYS-008、SYS-009、SSH-003、SET-002、SET-003、HSM-011）。 — 完成條件：見增補 03 51.3「ROB-010 規則」的明細。

## Acceptance tests（第 42 章）

- **T-037** 修改網路後無法回連。 → 可逆部分在核准逾時政策下復原，顯示事件。
- **T-038** Docker 發布服務但 UFW 顯示拒絕。 → 外部測試能發現實際暴露，不虛報已封鎖。
- **T-167** 對 Core 主機套用一條會擋掉管理入口的防火牆規則（預設 60 秒）。 → 套用前警告。套用後 Core 關閉既有管理連線；60 秒內沒有從新連線送出確認，由 Core 主機本機自動回復。
- **T-178** 管理入口網域改成新網域。 → 只有經新網域建立的連線送出的確認有效；10 分鐘內沒有確認就自動回復。
- **T-184** 修改 sshd 的 Port，但新 Port 被主機防火牆擋住。 → 套用前警告；套用後測試帳號的 SSH 登入測試失敗，60 秒內沒有確認，自動回復成原本的設定。
