## What it delivers

網站與網域模型、路由衝突與目標健康驗證、19.2 的服務發現（受控回送 Port、引擎事件更新）、設定語法與語意驗證、套用與回復前一版、內網專用與公開網站、子網站與共用環境歸屬。

## Acceptance criteria

- [ ] **WEB-002** 使用者可以建立靜態網站、反向代理網站與受支援的語言執行環境網站。 — 完成條件：基線可用網站類型有可用替代，不因移除 OpenResty 就默默消失。
- [ ] **WEB-003** 使用者可以綁定多網域、路由到服務與特定 Port。 — 完成條件：驗證網域、Host、路由衝突與目標健康；容器重建後仍正確找到服務。
- [ ] **WEB-009** 管理員可以安全套用設定或回復前一版。 — 完成條件：語法與語意驗證、候選設定、原子切換與生效檢查都有工作記錄。
- [ ] **WEB-011** 管理員可以設定內網專用網站與公開網站。 — 完成條件：不以綁定網域自動開防火牆；公開操作有授權與實際可達性提示。
- [ ] **WEB-014** 系統可以驗證網站設定真的生效。 — 完成條件：先做選定版本支援的設定檢查，再用實際請求驗證；未知／被忽略欄位不得靜默成功。
- [ ] **WEB-015** 使用者可以建立子網站及共用執行環境的網站。 — 完成條件：網域、目錄、存取權與資源歸屬清楚；刪一個網站不誤刪共用環境或另一站資料。
- [ ] 容器 IP 改變後根據已驗證服務發現更新，不綁死舊 IP
- [ ] 未知／被忽略欄位不得靜默成功

## Acceptance tests（第 42 章）

- **T-080** 原生 Zentinel 代理容器，容器 IP 改變。 → 根據已驗證服務發現更新，不永久綁死舊 IP。
- **T-128** Zentinel 設定有未解析變數或不生效欄位。 → 驗證與實際請求可抓到，不能只憑程序啟動判成功。
