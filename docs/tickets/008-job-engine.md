# 008 — 使用者可以提交工作後關閉頁面，之後仍能查到進度、證據與結果

**Epic:** 基礎建設（`epic:foundation`）  
**User Story:** 使用者可以安全執行長時間操作  
**Milestone:** M0 基礎與設計  
**Blocked by:** [003 管理員可以啟動 hazelminx-core 並通過健康檢查](003-core-skeleton.md)  
**Status:** blocked  
**規格章節:** 33｜工作引擎：按一次按鈕後，如何可靠完成  
**Issue:** [#8](https://github.com/HazelnutParadise/hazelminx/issues/8)  

## What it delivers

工作引擎：33.1 的狀態機、請求識別碼去重、資源鎖（認同一磁碟／掛載／父子路徑）、持久事件序號、取消語意、狀態不明對帳、資源預算、每類工作的完成檢查介面。

## Acceptance criteria

- [ ] **ENG-001** 使用者可以關閉頁面後再查工作。 — 完成條件：工作不隨 HTTP 連線消失；進度與證據可重新讀取。
- [ ] **ENG-002** 系統可以辨識重複要求。 — 完成條件：同一識別碼、相同內容回同一工作；相同碼不同內容回衝突。
- [ ] **ENG-003** Agent 可以在重新開機後恢復工作紀錄。 — 完成條件：不把所有執行中工作重設成功或從頭重跑；先核對步驟與現場狀態。
- [ ] **ENG-004** 系統可以鎖住互相衝突的操作。 — 完成條件：同磁碟格式化與搬移、同資料庫升級與還原無法同時執行。
- [ ] **ENG-006** Agent 可以在執行前再次檢查環境。 — 完成條件：預檢後被別人占用的連接埠或換掉的磁碟會阻擋操作。
- [ ] **ENG-007** 使用者可以取消工作。 — 完成條件：可取消步驟停止；不可安全中止的步驟清楚顯示等待原因；不以強殺當作保證。
- [ ] **ENG-008** 系統可以區分失敗、已復原及狀態不明。 — 完成條件：注入斷線、磁碟滿與復原失敗時，三者狀態正確不同。
- [ ] **ENG-009** 使用者可以看到完整但受控的診斷。 — 完成條件：顯示原始錯誤摘要、相關日誌、系統狀態與建議；沒有證據時不捏造根因。
- [ ] **ENG-011** 系統可以對不同工作設定資源預算。 — 完成條件：備份、建置、解壓縮不能耗盡管理程序所需 CPU、記憶體與空間。
- [ ] **ENG-012** 維護者可以驗證真正的完成條件。 — 完成條件：每類工作有獨立的完成檢查；必要檢查未通過不能標成功。
- [ ] Agent 重開機後不把執行中工作重設成功或從頭重跑
- [ ] 注入斷線、磁碟滿與復原失敗時，失敗／已復原／狀態不明三者顯示不同

## Acceptance tests（第 42 章）

- **T-025** 網頁對同一安裝要求連按或重送。 → 相同請求只形成一個工作。
- **T-026** 相同請求 ID 改成另一個磁碟目標。 → 拒絕衝突，不沿用原批准。
- **T-027** 工作執行中關閉瀏覽器。 → 工作繼續；重新登入可接續進度。
- **T-028** Agent 做完操作，但回傳前斷線。 → Core 顯示不明；重連對帳，不再次執行破壞性步驟。
- **T-029** 磁碟格式化中要求取消。 → 不承諾可撤回；在安全點停止並說明結果。
- **T-031** 預檢後讓連接埠被另一程序占用。 → 執行前再檢查並停止，不殺別人的程序。
- **T-033** 原操作與復原都失敗。 → 顯示需要處理、殘留與證據，不標已復原。
- **T-034** 大量日誌輸出淹沒通道。 → 關鍵心跳與撤銷仍可處理，截斷／遺失明示。
