# 規格增補 05｜內建 Hugging Face 模型 runtime 與模型庫

- **狀態**：已核定。2026-11-08 使用者決定以下幾件事：
  - 平台內建可以跑 Hugging Face 模型的 runtime。
  - 平台內建模型庫，可以直接在面板搜尋與下載模型。
  - 模型庫可以有多個，每個都能指定放在哪顆磁碟。
- **位置**：本增補是第 53 章，接在增補 04（第 52 章）之後。v1.1 原檔與 `SHA256SUMS.txt` 不改。需求 ID 以 `HFM-` 開頭，驗收案例從 `T-221` 開始編號。
- **細化的既有需求**：AI-001～AI-011。Ollama 的安裝、接管與模型管理照舊；本章新增的是 Hugging Face 模型這條路，兩條路共用同一個 AI 頁、同一套 GPU 檢查（AI-006）與 API 代理（AI-009）。
- **用詞**：
  - 「模型庫」指主機上一個存放模型檔案的資料夾，由平台管理。
  - 「runtime」指實際載入模型、提供推論 API 的程式，以平台管理的容器執行。
  - 「推論服務」指一個 runtime 載入一個模型後的執行個體。

## 53.1 內建的 runtime

| runtime | 適用的模型格式 | 硬體 | 為什麼選它 |
|---|---|---|---|
| vLLM | Hugging Face 的 safetensors 模型（transformers 架構） | NVIDIA GPU | 對 Hugging Face 模型支援最完整，提供 OpenAI 相容 API |
| llama.cpp（llama-server） | GGUF 量化模型 | CPU，或 NVIDIA、AMD、Apple GPU | 沒有 GPU 的主機也能跑，量化後記憶體需求小 |

- **不內建 Hugging Face TGI**：TGI 官方文件標示已進入維護模式，只接受小修正。
- **以容器執行**：runtime 用平台釘選版本的官方映像，更新依 AI-010 的方式，先核對再換版。
- **模型唯讀掛載**：runtime 容器以唯讀方式掛載模型庫，不能改模型檔。
- **對外**：推論服務預設只綁本機，要對外一律走 API 代理（AI-009），不直接發布 Port。
- **GPU**：沿用 AI-006 的四段檢查（驅動、容器工具、裝置權限、實際推論）。選 vLLM 但主機沒有可用的 NVIDIA GPU 時，畫面直接停用 vLLM 並寫出原因。

## 53.2 模型庫

- **一台主機可以有多個模型庫**，每個模型庫有名稱、所在磁碟、路徑與配額。
- **預設位置**：每顆資料磁碟都有一個預設位置 `<掛載點>/hazelminx/models`，第一次使用才建立。使用者也可以用資料夾選擇器自己選路徑，不能選的資料夾照全系統規則列出但不可選。
- **磁碟身分**：模型庫綁定磁碟的 UUID，不綁裝置名稱。磁碟沒掛上時，模型庫標「磁碟不在」，用到它的推論服務不啟動，不會把模型寫到根目錄。
- **目錄結構**：沿用 Hugging Face 的快取結構（`hub/models--<組織>--<名稱>/`），同一個檔案只存一份。使用者在主機上用 Hugging Face 工具下載到同一個位置時，平台也認得。
- **配額**：每個模型庫可以設上限。下載前檢查剩餘配額與磁碟空間，不夠時在開始前就擋下（沿用 AI-003）。
- **搬移**：模型庫可以搬到另一顆磁碟。搬移是一個工作，先複製、核對 sha256，再切換推論服務，最後才刪除舊位置。
- **刪除模型庫**：裡面還有推論服務在用的模型時，不能刪除，列出是哪些服務。

## 53.3 搜尋與下載

- **搜尋來源**：Hugging Face Hub 的公開 API。可以依關鍵字、任務、格式（GGUF 或 safetensors）、參數量與授權篩選，依下載數、按讚數或更新時間排序。
- **搜尋結果要顯示**：
  - 模型名稱、組織、授權、參數量、最後更新。
  - 可用的檔案或量化版本，以及各自大小。
  - 適用哪個 runtime。
  - 放不放得下：依選定主機的 GPU 記憶體或系統記憶體，以及模型庫剩餘空間，標「放得下」「GPU 記憶體不夠，可改用 CPU」或「放不下」。估算方式寫在提示裡，標明是估計。
  - 需要同意條款的模型（gated）標出來。
- **Hub 連不到時**：照 AI-004，提供「直接輸入模型名稱」，不顯示假的清單。
- **Hugging Face Token**：下載需要同意條款的模型或私有模型時，使用者在平台設定一組 Hugging Face Token，存在機密庫。Token 只用來下載，不會傳進 runtime 容器。
- **下載是一個工作**：
  - 有進度、速率與剩餘時間，關掉頁面照常進行，可以取消。
  - 中斷後可以續傳。
  - 每個檔案下載完都核對 Hub 提供的 sha256，核對失敗不標成可用。
  - 同一個模型的 GGUF 只下載使用者選的那個量化檔，不整個 repo 一起拉。
- **版本**：下載時記下 commit。之後 Hub 上有新版時標「有更新」，不自動更新。

## 53.4 部署推論服務

- **建立流程**：選模型 → 選 runtime（只列出適用的）→ 選主機與 GPU → 設定（context 長度、並行數、GPU 記憶體比例或 CPU 執行緒）→ 預檢 → 啟動。
- **預檢**：GPU 四段檢查、記憶體估算、模型庫磁碟在不在、Port 衝突。
- **啟動後**：顯示載入進度、實際使用的 GPU 記憶體、每秒 token 數與首字延遲，可以直接在 AI 頁的測試對話使用（AI-007）。
- **停止與刪除**：停止服務會釋放 GPU 記憶體但不刪模型檔；刪除模型檔要另外在模型庫操作，而且有服務在用時不能刪（AI-005「卸載不等於刪除」）。

## 53.5 要求

| ID | 誰可以做什麼與必要行為 | 可檢驗的完成條件 |
|---|---|---|
| HFM-001 | 管理員可以在主機上建立多個模型庫，指定磁碟與路徑。 | 每顆資料磁碟有預設位置，第一次使用才建立；可以用資料夾選擇器選其他路徑；模型庫綁磁碟 UUID，磁碟不在時不寫入根目錄；可以設配額。 |
| HFM-002 | 使用者可以在面板搜尋 Hugging Face 模型。 | 依 53.3 篩選與排序；結果顯示檔案大小、適用 runtime、放不放得下與是否需要同意條款；Hub 連不到時改為直接輸入名稱，不顯示假清單。 |
| HFM-003 | 使用者可以把模型下載到指定的模型庫。 | 是一個工作，有進度、可取消、可續傳；每個檔案核對 sha256；配額或空間不夠時開始前擋下；GGUF 只下載選定的量化檔；記下 commit。 |
| HFM-004 | 管理員可以設定 Hugging Face Token。 | 存在機密庫；只用於下載；不進入 runtime 容器；稽核只記錄使用，不記錄值。 |
| HFM-005 | 管理員可以用內建的 vLLM 或 llama.cpp 部署推論服務。 | 只列出適用該模型格式與硬體的 runtime；通過 GPU 四段檢查才啟動；模型唯讀掛載；預設只綁本機，對外走 API 代理。 |
| HFM-006 | 使用者可以看到推論服務的狀態並直接測試。 | 顯示載入進度、GPU 記憶體、tok/s 與首字延遲；可以在 AI 頁測試對話。 |
| HFM-007 | 管理員可以搬移或刪除模型庫，以及刪除模型。 | 搬移先複製並核對再切換；有服務在用的模型與模型庫不能刪，並列出使用中的服務。 |
| HFM-008 | 使用者可以看到 Hub 上的新版本並自己決定是否更新。 | 下載時記錄 commit；有新版時標示；不自動更新。 |

## 53.6 驗收案例

| ID | 情境 | 預期 |
|---|---|---|
| T-221 | tw-01 有兩顆資料磁碟 `/mnt/data` 與 `/mnt/fast`，第一次在 `/mnt/fast` 建立模型庫。 | 建立 `/mnt/fast/hazelminx/models`；`/mnt/data` 還沒用過，沒有建立資料夾；模型庫顯示綁定的磁碟 UUID。 |
| T-222 | 把 `/mnt/fast` 卸載後重新開機。 | 模型庫標「磁碟不在」；用到它的推論服務沒有啟動；根目錄沒有多出 `hazelminx/models`。 |
| T-223 | 搜尋 `qwen2.5 7b`，格式選 GGUF，主機選 lab-mini（沒有 GPU，記憶體 16 GiB）。 | 結果列出各量化檔與大小；Q4_K_M 標「放得下 · CPU」；vLLM 不在可用 runtime 裡，並寫出「需要 NVIDIA GPU」。 |
| T-224 | 下載一個需要同意條款的模型，平台沒有設定 Hugging Face Token。 | 下載前擋下並說明要設定 Token 與到 Hub 同意條款；設定後下載成功；runtime 容器的環境變數裡沒有這組 Token。 |
| T-225 | 下載 9 GiB 的模型時中斷網路 2 分鐘。 | 工作暫停並顯示原因；網路恢復後從中斷處續傳；完成後 sha256 全部相符才標成可用。 |
| T-226 | 模型庫配額剩 5 GiB，要下載 9 GiB 的模型。 | 開始前擋下並寫出差多少；沒有下載任何部分檔案。 |
| T-227 | 用 llama.cpp 在 lab-mini 部署 GGUF 模型，再用 vLLM 在 tw-01（L4 GPU）部署 safetensors 模型。 | 兩個推論服務都啟動；模型目錄在容器內是唯讀；兩者都只綁本機；從 API 代理可以呼叫；AI 頁顯示 tok/s 與首字延遲。 |
| T-228 | 刪除一個正被推論服務使用的模型。 | 擋下並列出使用中的服務；停止並刪除該服務後才能刪除模型。 |
| T-229 | 把模型庫從 `/mnt/data` 搬到 `/mnt/fast`，搬移期間推論服務持續接請求。 | 複製並核對 sha256 後才切換；切換後服務重新載入新位置；舊位置在切換成功後才刪除。 |
| T-230 | Hub 連不到。 | 搜尋顯示「連不到 Hugging Face」與原因；提供直接輸入模型名稱；不顯示快取或假造的清單。 |
