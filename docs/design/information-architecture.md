# 資訊架構：東西放在哪裡

這份文件記錄 HazelminX 管理介面的頁面組織方式、依據，以及和其他產品的取捨。規則摘要在 `DESIGN.md` 的「資訊架構」一節，本文件說明為什麼這樣定。

## 要解決的問題

HazelminX 同時管很多台主機，每台主機上又有很多種東西。介面要讓使用者回答兩種問題：

- **跨主機的問題**：全部專案現在怎樣、哪些容器 Port 對外開著、哪個備份失敗。
- **單一主機的問題**：jp-02 上有哪些套件要更新、tw-01 的 `/mnt/data` 裡有什麼、這台的程序誰最吃 CPU。

改版前的介面把這兩種問題混在一起，造成以下狀況：

| 狀況 | 例子 |
|---|---|
| 側欄項目指向「某台主機的功能」，卻沒說是哪台 | 側欄的「檔案」「服務模組」，點進去要再挑節點 |
| 機群頁放了單一主機的區塊，還在頁中間切換節點 | 主機與節點頁的「主機工具 · hazel-tw-01」「程序 · hazel-tw-01」 |
| 同一份資料在兩頁各做一份 | Docker 直通 Port 同時出現在主機與節點頁和安全頁 |
| 兩個側欄項目指到同一頁 | 「儲存」和「備份與還原」 |
| 分組名稱裝不下裡面的東西 | 「事件與告警」「日誌」「平台設定」放在「入口與安全」底下 |
| 沒有清單頁，專案一多無處可挑 | 專案頁直接打開 shop，其他專案和環境擠在同一排分頁 |
| 清單沒有對應的詳細頁 | 容器列點下去沒有容器詳細頁 |

## 其他產品的做法

| 產品 | 組織方式 | 值得學的 | 會遇到的問題 |
|---|---|---|---|
| 1Panel | 單機設計，側欄約 12 項，每項都是「這台主機的某功能」 | 功能齊全，入口好找 | 多台主機時，檔案、終端機、防火牆不知道是在指哪台 |
| Portainer | 先選環境，側欄才換成那個環境的功能 | 環境卡片把狀態、版本、統計放在一張卡上 | 看不到跨環境的東西；切換環境後很容易在錯的環境裡操作 |
| Komodo | 側欄依資源類型分，伺服器是一種資源，點進去才有分頁 | 撐得住很多台；伺服器清單可切換成帶統計欄位的表格 | 伺服器詳細頁預設停在設定分頁，第一眼看不到狀態 |
| Cockpit | 每台主機一組分頁：總覽、日誌、儲存、網路、帳號、服務、更新、終端機 | 單機分頁完整、分類清楚 | 機群視角很弱，要一台一台看 |
| Railway、Coolify | 專案 → 環境 → 服務 | 部署類工作的路徑很自然 | 只管應用，不管主機 |

來源：1Panel v2.4.1 前端路由與選單（`docs/research/1panel-frontend.md`）、Portainer CE 前端（`docs/research/portainer-ui.md`）、Komodo UI（`docs/research/komodo-ui.md`）。Cockpit、Railway、Coolify 的描述依各自官方文件與介面。

## 決定

### 三層位置

1. **側欄放跨節點的資源**：每個清單都標出資源在哪台、在哪個環境，做法跟 Komodo 一樣按資源類型分。
2. **節點工作區放單一主機的東西**：分頁是概況、系統、容器、檔案、日誌、終端機，分類方式參考 Cockpit。
3. **全站都會用到的放最上方或頂列**：工作中心、事件與告警、⌘K 搜尋、終端機。

我們不採用 Portainer 的「先選環境」，因為跨節點的問題是 HazelminX 的主要用途。

### 側欄

```
總覽
工作中心          3
事件與告警        4
應用      專案與服務、應用商店、網站與入口、資料庫、AI、API 代理
基礎設施  主機與節點、容器、Kubernetes、儲存與備份、計畫任務
安全與紀錄 安全防護、流量分析、日誌
管理      身分與存取、平台設定
```

側欄從 21 項減為 19 項，四個分組各自裝得下裡面的東西。

### 每個頁面放什麼

| 頁面 | 放什麼 | 不放什麼（改到哪） |
|---|---|---|
| 主機與節點 › 節點 | 節點表格（可排序、勾選、內嵌量表）、引擎環境、跨節點資源、元件版本 | 主機工具（改到節點 › 系統）、程序（改到節點 › 概況）、Port、SSH（改到安全防護） |
| 主機與節點 › 服務模組 | 模組 × 節點矩陣、單一模組的設定與版本 | — |
| 節點工作區 | 概況（硬體、指標、程序、GPU）、系統（套件、服務、使用者、網路、掛載、時間、主機工具）、容器、檔案、日誌、終端機 | 跨節點的儲存與備份 |
| 專案與服務 | 環境清單（一列一個環境） | 單一專案的拓撲與部署（改到專案詳細） |
| 專案詳細 | 環境分頁、拓撲、服務、指標、部署歷史 | 其他專案 |
| 容器 | 環境範圍、容器表、映像、網路、儲存卷 | — |
| 容器詳細 | 設定、CPU 與記憶體、Port、掛載、環境變數、最近日誌 | 修改設定（導回專案） |
| 安全防護 | 對外曝露（容器 Port、Port × 節點、主機防護、SSH）、網站防護（WAF） | — |

## 任務走查

用同樣六個任務走一遍改版前後的路徑。

| 任務 | 改版前 | 改版後 |
|---|---|---|
| 半夜收到「jp-02 失聯」 | 鈴鐺連到總覽的卡片，側欄沒有事件入口 | 鈴鐺或側欄「事件與告警」，再從卡片的「查看節點」進節點工作區 |
| 改 tw-01 上 wiki 的 `.env` | 側欄「檔案」，再在範圍列挑節點 | 主機與節點，點 tw-01 那列的檔案圖示，直接打開 tw-01 的檔案分頁 |
| 部署 shop 最新 commit | 專案頁預設打開 shop production，staging 和 wiki 擠在同一排分頁 | 專案清單 › shop › production 分頁 › 部署最新 commit |
| 查 5432 為什麼對外 | 主機與節點和安全頁各有一張矩陣，數字可能不一致 | 安全防護 › 對外曝露，第一張表就是可直接封鎖的容器 Port |
| 看 shop-api 為什麼慢 | 容器列沒有詳細頁 | 容器 › shop-api-1：CPU、記憶體、最近日誌放在同一頁 |
| 清 jp-02 的磁碟空間 | 主機與節點頁中間的「主機工具 · tw-01」，要先切成 jp-02 | 節點 jp-02 › 系統 › 主機工具 › 可清理空間 |

## 改版時一併修掉的問題

- **圖表只畫在面板左側三分之一**：根因是圖表內容區和整頁版面用了同一個 class 名稱，整頁版面的 flex 規則套到了圖表上。整頁版面改名為 `.layout`。
- **圖表的字隨寬度縮放**：時間圖改成圖形拉伸、文字用 HTML 疊在上面，從 360 到 1920 寬都是同一張圖。
- **列裡的按鈕寫成連結**：整列是連結時，列尾按鈕寫成連結會被瀏覽器拆成獨立一列。規則改成列尾一律用按鈕。
- **目錄樹把還沒展開的資料夾畫成檔案**：目錄樹只會有資料夾，還沒讀取的子層顯示成可展開的資料夾。
- **流程段在半寬面板裡被切掉最後一段**：改成換行顯示，不再藏到橫向捲動裡。
