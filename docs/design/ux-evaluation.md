# UX 評估方法與結果（2026-11-07）

「設計好不好」有一套既有的方法，分兩類：沒有真人也能做的（專家審查與量測）、一定要真人的（測試與量表）。這份文件記錄我們用了哪些、數字是多少、哪些要等有可用的前端才做。

## 一、不用真人就能做（本輪全部做了）

| 方法 | 在看什麼 | 怎麼做 | 結果 |
|---|---|---|---|
| 認知走查 Cognitive walkthrough | 新手照著任務點，每一步是否知道要做什麼、做完有沒有回饋 | 六個任務逐步走（`ux-walkthrough.md` 第一節） | 找到 7 個 🔴（頂列告警、列尾動作、部署按鈕、節點失聯卡、節點分頁、備份動作、容器詳情）；前六個已修，容器詳情頁記票 040 |
| 啟發式評估 Heuristic evaluation（Nielsen 10 項） | 可見狀態、符合慣例、一致性、錯誤預防、辨識而非回想、效率、極簡、錯誤復原、說明 | 逐項掃 30 個畫板（`ux-walkthrough.md` 第二節） | 8 項發現；全部修完（頂列、側欄圖示、pill、去空欄、間距、截斷、手機矩陣） |
| 競品對照 Competitive benchmark | 版面慣例是否偏離使用者已習慣的工具 | 1Panel、Komodo、Portainer、Cockpit 的實際畫面與原始碼 | 側欄、頂列、卡片、表格、狀態 badge、列尾動作全部對齊（`ux-walkthrough.md` 第三節） |
| WCAG 2.1 AA 對比 | 每段文字對它實際的底色是否 ≥ 4.5:1（大字 3:1） | 腳本掃 27 個畫板 × 深、淺、360px，含半透明底色合成 | 改前 142 處不合格 → **0** |
| 觸控目標 | 可點元素是否 ≥ 44px（手機）／24px（桌面） | 同一腳本 | 改前 1,141 → **6**（三個頁面各一個次要連結） |
| 可及名稱 | 每個控制項是否有螢幕閱讀器讀得出的名稱 | 同一腳本 | 改前 27 → **0** |
| 版面缺陷掃描 | 文字截斷、表格空欄、元素重疊、過高列 | 同一腳本 | 截斷 177 → 5、空欄 ~200 → 6（States 骨架列，刻意） |
| 文字來源檢查 | 畫面上每一句話是否能由程式產生 | 產生器內建禁字 lint（下一步、建議、可能、無關…） | 改前 11 處綜合判斷句 → **0** |

## 二、要真人才做得到（等票 005／017 有可操作前端後）

| 方法 | 在看什麼 | 怎麼做 | 門檻 |
|---|---|---|---|
| 易用性測試 Usability test（5 人） | 真人做六個任務的完成率、時間、錯誤 | 每人 30 分鐘，放聲思考 | 任務完成率 ≥ 80%，T1（告警→找到原因）≤ 90 秒 |
| SUS 系統易用性量表 | 10 題、0–100 分的整體感受 | 測試後填 | ≥ 70（業界平均 68） |
| 首次點擊測試 First-click | 看到畫面第一下點哪裡 | 給靜態畫面問「要更新套件你點哪」 | 首次點擊正確率 ≥ 70% |
| 樹狀測試 Tree test | 導覽分類找不找得到 | 只給導覽文字找 10 個功能 | 直達率 ≥ 60% |
| 鍵盤走查 | 360px 與桌面只用鍵盤完成日常操作（規格 T-117） | Tab 順序、焦點環、Esc 關閉 | 全部任務可完成 |

## 三、畫面文字的來源規則（本輪新增，寫進 DESIGN.md）

畫面上每一段文字只能是下列四種之一，否則程式做不出來：

1. **欄位值**：時間、數字、名稱、版本、路徑（`最後心跳 03:41:18`）。
2. **固定模板填變數**：每種事件、工作步驟、預檢規則各有一句模板（`節點失聯 · {秒} 秒`、`規則：新增宿主機掛載`）。
3. **原始輸出**：日誌行、錯誤原文、指令輸出、結束碼，用等寬字原樣顯示。
4. **固定動作**：每種事件類型綁定固定的按鈕清單（節點失聯 → 查看節點／SSH 備援）。

禁止的是綜合判斷句：原因推論（「因為 DNS Token 過期」）、建議（「建議改用 HTTP 驗證」）、關聯判斷（「與同時段部署無關」）、安撫（「可能仍在服務」）。規格 UI-011 的「發生什麼、影響什麼、證據、下一步」四段對應到：模板句、依賴圖算出的受影響清單、原始輸出、固定按鈕。
