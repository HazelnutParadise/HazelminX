# UX 走查（2026-11-07）

方法：認知走查（cognitive walkthrough）。先定六個管理員最常做的事，假想從登入後第一屏開始每一步要點哪裡、看哪裡，記下「找不到」「點了沒反應」「要繞路」的地方；再用 Nielsen 十項啟發式掃全部畫板。對照對象是 1Panel 2.x 首頁、Komodo、Portainer、Cockpit 的實際畫面與原始碼（`docs/research/`）。

## 二、啟發式掃描（跨畫面）

| 啟發式 | 發現 | 嚴重度 |
|---|---|---|
| 系統狀態可見 | 觀測時間、搜尋、使用者、主題切換散在側欄與標題列；市面面板全部放在**頂列**（1Panel 頂列：分頁＋版本；Komodo：搜尋＋告警＋更新＋主題＋使用者；Portainer：環境＋通知＋使用者） | 🔴 |
| 辨識而非回想 | 側欄 19 項**沒有圖示**，全靠讀字；1Panel、Komodo、Portainer、Cockpit 側欄每項都有圖示 | 🔴 |
| 一致與標準 | 狀態只有小形狀＋彩色文字，掃描性低；市面用有底色的 badge／pill | 🟡 |
| 美學與極簡 | 表格共用七欄模板，很多表只填四五欄，**右側大片空白**（掃描到 19 個表、約 200 個空格） | 🔴 |
| 美學與極簡 | 標題列、範圍列、分頁列三層堆疊，第一屏被吃掉 150px | 🟡 |
| 彈性與效率 | 表格列整列是連結，但沒有 hover 指示或箭頭；沒有列內快速動作 | 🟡 |
| 錯誤預防 | 危險動作（重啟服務）在系統頁是裸按鈕，沒寫影響 | 🟡（確認框在 States 畫板有） |
| 可讀性 | 自動掃描：桌面 27 處文字被截斷（ghcr.io 映像名、程序名、慢查詢、網域）、手機 150 處；矩陣與 24 格熱格在 360px 被壓扁 | 🔴 |

## 四、這輪改了什麼（對應上面）

1. **頂列**：面包屑／標題、全域搜尋、觀測時間與自動更新、告警鈴（計數）、進行中的工作（計數）、終端機、主題、使用者。側欄只剩導覽。
2. **側欄圖示**：19 項各一個線條圖示（inline SVG，同一套線寬），底部收合鈕。
3. **狀態 pill**：底色 14%、形狀＋文字，一眼掃得到。
4. **表格欄數依內容**：產生器把每張表尾端全空的欄拿掉，模板改成 4／5／6／7 欄；容器與 K8s 工作負載列尾加快速動作（日誌、終端機、重啟、更多）。
5. **間距**：卡片標題列 46px、內距 16px、區塊間 16px、卡片間 12px；名稱第二行允許兩行而不是截斷；排行名稱欄加寬並在手機改成上下排。
6. **缺的入口**：總覽「需要處理」加節點失聯卡；節點詳情頂部加「總覽／系統／容器／終端機／日誌」分頁；專案頁加「部署最新 commit」主按鈕與「回到這版」；備份任務卡加「立即執行」「還原…」「紀錄」；主機工具卡改成連到系統頁。
7. **手機**：矩陣與 24 格熱格改成橫向捲動（第一欄固定），不再壓扁。
