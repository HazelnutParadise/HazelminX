## What it delivers

「從 GitHub 匯入專案」精靈與其他入口共用的來源選擇器，資料全部來自 048.1 的 `/management/v1/github`：

- 選 Repo：搜尋名稱，篩選連線、擁有者、公開／私人、封存；清單每列寫出完整名稱、擁有者、經哪份連線讀到、最後同步時間。
- 同步狀態：「目前已載入」與「已完整同步」分開；同步中、部分失敗（哪個組織、原因）、限流（到何時再試）、授權已變更（舊結果）各有說明；可重新同步。
- 同一個 Repo 經兩份連線讀到時列出兩項並寫出各自的範圍，使用者選定一份；那份失效時顯示原因與重新授權入口，不改用另一份。
- 選來源版本：分支、標籤或指定 commit，顯示固定下來的 SHA；可瀏覽目錄。
- Compose：空 Repo、沒有 Compose、一份、多份分別說明；多份時選工作目錄，顯示 Compose 實際讀取的檔案順序與被忽略的檔案。
- 找不到 Repo 時提供重新同步、檢查授權、新增另一份授權、手動輸入 Repo，不丟掉部署草稿。

## Acceptance criteria

- [ ] 超過一頁的 Repo 可以搜尋到；畫面分開顯示「已載入」與「已完整同步」，部分失敗與限流不顯示成完整（GH-T05、GH-T06 畫面部分）。
- [ ] 同一 Repo 經 App 與 PAT 讀到時分開列出，選定的連線失效後畫面說明原因，不自動改用另一份（GH-T07 畫面部分）。
- [ ] 選分支後顯示固定 SHA；空 Repo、缺 Compose、多 Compose 各有白話說明，多 Compose 可選工作目錄並看見檔案順序（GH-T08 畫面部分）。
- [ ] 封存、私人、需要重新授權、授權已變更的項目可辨認；Token 不出現在畫面、網址或瀏覽器永久儲存。
- [ ] 渲染結果依 DESIGN.md 比對，畫面變更通過 ui-review。

## Notes

設計缺口（畫板 `design/screens/GitHubSource.dc.html` 與 `ImportConfigure.dc.html` 對照 048.1 API）：

- 選 Repo 表格：沒有「經哪份連線讀到」的欄位，也沒有同一 Repo 經兩份連線時的呈現與選擇方式；目前只畫了一個連線（hazelnut 組織）。
- 同步狀態：沒有同步中、部分完成（某組織失敗與原因）、限流到何時再試、授權已變更（舊結果）、從未同步的樣子，也沒有「重新同步」按鈕與「已載入／已完整」的區別。
- 分頁與搜尋：沒有載入更多或分頁的樣子，也沒有搜尋不到時的動作（重新同步、檢查授權、新增授權、手動輸入 Repo）。
- 篩選：沒有擁有者、公開／私人、封存的篩選，也沒有私人與封存的標示。
- 來源版本：只有分支下拉與最新 commit 一行；沒有標籤、指定 commit、commit 清單與固定 SHA 的呈現，也沒有分支在選定後移動時的提示。
- 檔案瀏覽：沒有目錄瀏覽畫面。
- Compose：「偵測」欄畫了「3 份」「子目錄 2 份」「無法部署」，但沒有選工作目錄、看檔案順序（base 再 override）與被忽略檔案的畫面；空 Repo 與沒有 Compose 的白話說明也沒畫。
- 「偵測」欄出現在清單每一列：API 只在選定 Repo 後掃描（每個 Repo 要讀一次 GitHub 檔案樹），清單階段沒有這個資料。若要保留這欄，需要決定是否改成選定後才顯示，或接受每列多一次 GitHub 呼叫與限流風險。
- 「建置方式 Dockerfile（沒有 compose，當成單一服務）」：048.1 只偵測 Compose 檔案，Dockerfile 偵測不在這張票的需求內，需另定歸屬（049 或新票）。
