# 016.1 — 管理員可以用 API 產生、批准並執行變更計畫，內容或資源版本改變時原批准失效

**Epic:** 身分與存取（`epic:iam`）  
**User Story:** 使用者可以安全執行長時間操作  
**Milestone:** M1 單機主機管理  
**Parent:** 016  
**Blocked by:** 008 使用者可以提交工作後關閉頁面，之後仍能查到進度、證據與結果, 010 整合者可以用 /management/v1 的分頁、版本條件與工作回應操作資源  
**規格章節:** 33｜工作引擎：按一次按鈕後，如何可靠完成、36｜管理 API 與事件契約  
**Issue:** [#147](https://github.com/HazelnutParadise/hazelminx/issues/147)  

## What it delivers

Core 的變更計畫：`core/internal/plans` 與 `/management/v1/change-plans` 的產生、列表、讀取、批准、拒絕、撤回、執行。計畫寫出目標的實際名稱、設定差異、受影響服務、預檢、風險、必要批准與有效期限；批准綁定計畫摘要（涵蓋目標與資源版本）與期限；批准與執行時重算計畫，內容或版本變了就讓原批准失效並回傳差異。要走計畫的工作種類不能直接 `POST /jobs`。資源種類各自的計畫內容由各資源票註冊（044、031、039…）。

## Acceptance criteria

- [ ] **IAM-005** 管理員可以批准特定高風險變更計畫。 — 完成條件：批准綁定內容摘要、目標、版本與期限；內容改變必須重新批准。
- [ ] **ENG-005** 管理員可以批准一份明確變更計畫。 — 完成條件：批准綁定計畫摘要、資源版本及期限；內容變更後原批准失效。
- [ ] 批准者要對計畫的每個目標都有該種類的權限；高風險計畫只有擁有者能批准；看不到其中任何目標的帳號拿到與不存在相同的 `404`；被拒的批准寫稽核。
- [ ] 批准、拒絕、撤回、執行、失效的稽核紀錄與狀態變更在同一個交易；稽核寫不進去時狀態不變。
- [ ] 計畫回應帶目標的實際節點／磁碟／環境名稱、設定差異（機密只寫「已變更」）與受影響服務，供 016.2 的畫面呈現 UI-006。
- [ ] 註冊為「必須走計畫」的工作種類，直接 `POST /management/v1/jobs` 會被拒絕；計畫執行建立的工作帶批准者、計畫 ID 與摘要。
- [ ] 兩人同時修改同一設定版本時，第二人收到差異與衝突，不覆蓋第一人：計畫執行前資源版本已變時回 `CHANGE_PLAN_CHANGED` 與前後差異；直接的版本條件寫入回 `412 VERSION_MISMATCH` 並附目前內容與衝突欄位。
