## What it delivers

「程式碼來源／GitHub 連線」的畫面，資料全部來自 047.1 的 `/management/v1/github`：

- 連線清單：GitHub 帳號（名稱與帳號 ID）、方式（PAT、App 個人授權、App 安裝）、授權範圍、可用能力、狀態（可用、已停用、需要重新授權與原因）、到期日；可改名、停用、啟用、重新檢查、輪替 PAT、重新授權、刪除。
- 新增連線：選 GitHub 網頁授權（選 App、授權或安裝）或輸入 PAT；畫面寫出要求哪些權限、誰擁有這份連線。
- App 建立：引導建立（manifest，選擇是否要 Webhook 與狀態回寫）與手動輸入。
- 回呼頁 `/sources/github/callback`：把 GitHub 帶回的 code、state、installation_id 送到 API，顯示成功的帳號與範圍，或依 `details.reason` 顯示失敗原因；GitHub 端取消時呼叫取消 API。不把 code 或 state 存進瀏覽器的持久儲存。
- 可達性：分開顯示瀏覽器回呼與 Webhook 送達的檢查結果；沒有公開位址時說明可用 PAT 與定期檢查。

畫板 `design/screens/GitHubSource.dc.html` 目前只有匯入精靈，上面這些畫面還沒畫，見 Notes 的設計缺口。

## Acceptance criteria

- [ ] 使用者在連線清單看到每份連線的 GitHub 帳號名稱與帳號 ID、方式、授權範圍、能力與狀態，名稱相近的帳號可以分辨（GH-T03 畫面部分）。
- [ ] 使用者完成網頁授權回到平台後看到 GitHub 回報的帳號與授權範圍；取消或失敗時看到原因，原有連線不變（GH-T01、GH-T14 畫面部分）。
- [ ] 使用者輸入 PAT 後畫面不再顯示它，之後的清單、詳情與錯誤訊息都不含 Token（GH-T02 畫面部分）。
- [ ] 需要重新授權的連線顯示原因與重新授權入口；PAT 到期時提示輪替，不顯示成可用（GH-T15 畫面部分）。
- [ ] 管理員可以用引導或手動方式建立 App，畫面列出每項額外權限的用途；只選讀取時說明可用定期檢查（GH-T12、GH-T13 畫面部分）。
- [ ] 可達性檢查分開顯示回呼與 Webhook 結果，沒有公開位址時說明替代方式，不提供自動公開管理頁的選項（GIT-031 畫面部分）。
- [ ] 渲染結果依 DESIGN.md 比對，畫面變更通過 ui-review。

## Notes

設計缺口（畫板 `GitHubSource.dc.html` 只畫了「從 GitHub 匯入專案」精靈，步驟一「連接 GitHub」以已完成狀態出現）：

- 連線清單頁：沒有畫板（欄位、狀態標示、需要重新授權的樣子、動作選單）。
- 新增連線：網頁授權與 PAT 兩條路的選擇畫面、PAT 輸入表單、權限說明。
- App 建立精靈：manifest 引導與手動輸入兩種表單、額外能力的選擇與用途說明。
- 回呼頁：成功、各種失敗原因（過期、已用過、換了工作階段、登錯帳號、安裝不符、GitHub 端取消）與 GitHub 連不上的狀態。
- 可達性檢查結果卡：回呼與 Webhook 兩項各自的狀態。
- 精靈步驟一「連接 GitHub」在還沒有連線、或連線需要重新授權時的樣子。
