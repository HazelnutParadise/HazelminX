# 119 — 使用者可以在畫面上登入、完成首次設定、綁定第二驗證並管理自己的帳號安全

**Epic:** 身分與存取（`epic:iam`）
**User Story:** 使用者不用呼叫 API 就能登入與保護自己的帳號
**Milestone:** M1 單機主機管理
**Blocked by:** 005 使用者可以開啟 React 介面並切換語言與淺深色, 009 擁有者可以登入、建立帳號與角色，未授權的 API 呼叫一律被拒絕, 014 使用者可以設定 TOTP、Passkey、復原碼並檢視與撤銷自己的工作階段
**規格章節:** 無（來自 2026-11-11 之前記在 AGENTS.md 的後續事項）
**Issue:** [#137](https://github.com/HazelnutParadise/hazelminx/issues/137)

**Blocked:** 最後一條驗收要有人用實體驗證器（含手機同步的 Passkey）在網域加 HTTPS 的環境實測，agent 做不到。其他驗收都已通過，這項測完就能移到 `done/`。

## What it delivers

登入、首次設定、第二驗證綁定與帳號安全的畫面。票 009、014 只交 API，票 005 只做了外殼：`/account/security` 目前是空殼頁，帳號選單的「登出」會回到 `/`，但沒有登入頁可以接。設計稿已有 Login、Setup、AccountSecurity、MfaDialogs 畫板。外殼顯示的目前使用者與未登入狀態（`web/src/app/shellStatus.ts`）也由這張票接上資料來源。

## Acceptance criteria

- [x] 未登入時開啟任何頁面會到登入頁，登入成功後回到原本要去的頁面；登出後回到登入頁。
  證據：路由守衛 `web/src/auth/RequireAuth.tsx`；`?next=` 只接受站內路徑（`web/src/auth/nextPath.ts`，`helpers.test.ts` 測了 `//`、`/\`、scheme、控制字元與登入頁本身）。e2e `auth.spec.ts`「any page goes to login…」：開 `/nodes/hazel-tw-01/files?path=%2Fetc` 會到 `/login?next=…`，登入後回到原頁，登出到 `/login`，之後再開頁又要求登入。工作階段在別處失效時，也會帶著原頁回登入頁（`flows.test.tsx`「a session lost elsewhere…」）。
- [x] 第一次啟動時走首次設定流程建立擁有者帳號。
  證據：e2e `first-run.spec.ts` 對全新的 Core 走完：開任何頁面到 `/setup`，錯的設定碼顯示「設定碼不對或已過期」，建立擁有者後到 `/enroll?setup=1` 綁定驗證器（錯碼有提示），存好 10 組復原碼（可下載，勾選後才能繼續），再到「開始使用」與總覽。每個畫面在 1440 深色、360 深色、1440 淺色都通過 axe、對比與版面掃描。
- [x] 登入第二步、綁定 TOTP 與 Passkey、復原碼、強制綁定、重新驗證的畫面依 MfaDialogs 畫板實作，錯誤狀態齊全。
  證據：第二步的驗證器、復原碼（同一組不能再用）、Passkey 都在 e2e `auth.spec.ts` 跑過。錯碼、挑戰逾時、錯太多次倒數、沒有 Passkey 時隱藏按鈕、這個網址不能用 Passkey、沒有可用方式，由 `flows.test.tsx` 覆蓋。Passkey 綁定與第二步登入用 Chromium 虛擬驗證器跑 e2e；用 IP 開面板的提示有 e2e，瀏覽器取消有單元測試。強制綁定：`host_operator` 登入後被帶到 `/enroll`，開其他頁也被擋回，綁定後回原頁（e2e）。重新驗證：密碼錯、驗證碼、取消不變更有單元測試；驗收審查另在真的 Core 把工作階段時間調早，實際觸發過重新產生復原碼與移除 Passkey 前的重新驗證。
- [x] `/account/security` 顯示第二驗證、復原碼、登入中的裝置與閒置設定，可以撤銷其他裝置。
  證據：e2e `auth.spec.ts`「account security」：四個區塊都在；撤銷單一裝置或「登出其他所有裝置」後，另一個瀏覽器立刻要重新登入；閒置時間改成 30 分鐘後重新整理仍保留；擁有者的最後一個第二驗證不能移除。各寬度與深淺色掃描通過。
- [x] 外殼的帳號選單顯示目前使用者，未登入時顯示未登入頂列。
  證據：帳號選單顯示名稱與角色（`TopBar.test.tsx`、e2e「owner · 擁有者」）。登入、設定、綁定畫面用未登入頂列，只有品牌、主題與語言（e2e 掃描與 `TopBar.test.tsx`）。
- [ ] 用真實瀏覽器與實體驗證器（含同步型 Passkey）測過註冊、第二步登入與再次驗證。票 014 的 Passkey 只用軟體驗證器（`core/internal/iam/softauth_test.go`）測過。
  未驗證：只用 Chromium 的 CDP 虛擬驗證器跑過註冊、第二步登入與移除前的重新驗證。

## 設計缺口

實作時發現設計稿缺的畫面、狀態或資料來源，由設計端補畫或決定：

1. **Login**：「以公司帳號登入（OIDC）」按鈕。Core 沒有 OIDC 登入 API，實作沒有放。
2. **Login 第二步**：選了「使用復原碼」後怎麼回到驗證器輸入，畫板沒畫。實作把同一顆按鈕的文字換成「改用驗證器」。
3. **Login 第二步**：帳號只有 Passkey 時復原碼輸入放哪裡，以及「這個網址不能用 Passkey」「沒有可用的二次驗證」兩種提示，畫板都沒有。
4. **Setup 綁定二次驗證**：畫板的 6 位數是單一輸入框，登入第二步卻是 6 格。實作兩處都用 6 格。
5. **Setup「開始使用」**：「hazel-tw-01 已經是第一台主機」需要主機資料，首次設定時沒有來源。實作只寫「接著可以」與三個連結。
6. **強制綁定（MfaDialogs「先設定二次驗證」）**：畫板是外殼上的對話框，但 Core 在綁定前拒絕其他所有 API，外殼沒有資料可畫。實作改成獨立頁 `/enroll`，沿用 Setup 第二步的版面加上兩個提示。畫板也沒有在這裡登出或換帳號的方式，實作在卡片底部加了「目前登入：X · 登出」。
7. **MfaDialogs「新增驗證器」的「名稱」欄位**與 **AccountSecurity 列尾的改名按鈕**：Core 的驗證器沒有名稱，Passkey 也沒有改名 API。實作沒有放。
8. **AccountSecurity 表格**：欄位排序箭頭，以及「復原碼」「登入中的裝置」標題旁的 ⓘ 說明。說明文字還沒定，實作沒有放。
9. **AccountSecurity 復原碼「11/02 產生」**：API 沒有產生時間。實作顯示「剩 N / 10 個」與「已用 N 個」。
10. **AccountSecurity 登入中的裝置**：地點（台北、辦公室）與「已被封鎖 · SSH 失敗 88 次」API 都沒有提供。實作只顯示瀏覽器 · 系統與 IP。
11. **AccountSecurity「危險操作前重新驗證（每次／5 分鐘內免重驗）」**：Core 沒有這個設定，固定 10 分鐘。實作沒有放，面板標題改成「閒置設定」。
12. **AccountSecurity「如果變更管理入口網域」**：畫板沒有輸入新網域的地方，API 需要 `?domain=` 與 `platform:write`。建議放進票 018（SET-003 改網域）的流程。
13. **帳號選單的 email**：Core 的使用者沒有 email 欄位，只顯示名稱與角色。
14. **移除最後一個二次驗證但角色不強制**：畫板只有「移除後還能登入」與「最後一個不能移除」。實作另加「移除後只靠密碼登入」。
15. **新增 Passkey 時瀏覽器不支援**、**驗證器綁定逾時（重新開始）**：畫板沒有這兩個狀態。
16. **重新驗證對話框**：畫板只有密碼與 6 位數。帳號有 Passkey 或只剩復原碼時，實作加了「使用 Passkey」與「使用復原碼」切換；查不到第二驗證時顯示錯誤與重試。
17. **開頁時連不上控制中心**：還不知道誰登入就失敗時沒有畫面。實作用外殼的載入失敗區塊（標題「沒辦法確認登入狀態」加原文）與重新載入。
18. **登出沒有送達控制中心**：畫板沒有。實作在登入頁顯示「沒有確認登出成功，這台裝置可能還在登入狀態」與「再登出一次」。
19. **設定碼錯誤、密碼太短**：Setup 畫板沒有錯誤狀態。實作用輸入框下方的錯誤文字與狀態 pill。
