# 049.1 — 專案管理員可以讓 Compose 單元的來源是 Git，固定到 Core 解析的 commit 抓取並經既有預檢與批准部署

**Epic:** GitHub 來源（`epic:github`）  
**User Story:** 使用者可以從 GitHub 部署  
**Milestone:** M2 容器、Compose 與 GitHub  
**Parent:** 049  
**Blocked by:** 048.1, 044.1, 044.2, 047.1, 011  
**規格章節:** 15｜完整 Compose、GitHub 與環境變數、31｜整體架構：每一部分負責什麼、增補 08 第 56.1、56.2 節  
**Issue:** [#185](https://github.com/HazelnutParadise/hazelminx/issues/185)

## What it delivers

- 單元的來源多一種 `git`。綁定記下：GitHub 連線參照與 Repo ID，或手動 URL 與單元自己的憑證參照（PAT 或 SSH Deploy Key，值只在機密庫）；ref、Core 解析出的 commit SHA、主檔、合併檔、profiles 與工作目錄。
- Core 抓取時只要那一個 commit（決策 0036）：不走磁碟、不執行 hook、不讀 repo 的 `.git` 設定、不跟 submodule；憑證只放在請求的驗證標頭或 SSH 驗證裡，不進 URL、日誌、錯誤或稽核。
- 從抓到的樹取出 compose 檔與它以相對路徑掛進容器的檔案，變成單元內容，交給 044.1 驗證、044.2 部署；不另開部署路徑。
- 樹裡用到 submodule、Git LFS 指標檔、符號連結或 `build:` 時，在預檢明確擋下並寫出原因（049.2 補上）。
- 部署紀錄寫下 repo、ref 與 commit；change plan 的內容綁定來源，連線停用、失去 Repo 權限或來源改變後，部署前重新檢查並拒絕。

## Acceptance criteria

- [ ] **CMP-002** 管理員可以指定 GitHub repo、分支／tag／commit 與 Compose 路徑。 — 完成條件：每次部署固定 commit SHA，不在建置到一半改讀移動中的分支。
- [ ] **CMP-003** 管理員可以使用 HTTPS 憑證、GitHub App 或 SSH Deploy Key 存取私有 repo。 — 完成條件：採最小權限；驗證伺服器指紋／CA；憑證不進 URL、日誌或建置 context。
- [ ] **GIT-009** 使用者可以繼續手動填 Repo URL 並指定個別 PAT 或 SSH 金鑰。 — 完成條件：不必先建立 GitHub App；原有部署不被強制改成帳號瀏覽模式。
- [ ] **GIT-011** 專案管理員可以讓多個部署綁定共用連線。 — 完成條件：保存連線參照而非複製明文 Token；每個專案的 Repo 與環境權限分別驗證。
- [ ] **GIT-038** 使用者可以確認讀取、選擇與部署是同一份來源。 — 完成條件：授權、Repo ID、來源站台、ref、commit 與設定摘要綁定；預覽後權限或來源改變須重新檢查。
- [ ] 讀取、選擇與部署綁定同一份來源，權限或來源改變須重新檢查
- [ ] 不支援的 submodule、LFS、符號連結與建置在預檢明確擋下，不部署缺檔內容
- [ ] 端到端：測試自己架的 Git 伺服器 → 抓取固定 commit → 預檢 → 真的 Docker 引擎部署，部署紀錄寫著該 commit

## Acceptance tests（第 42 章）

- **GH-T09** 不設定 GitHub App，以手動 URL、專案 PAT、SSH Deploy Key 各部署。 → 原有模式能獨立使用，SSH 指紋與個別範圍照常驗證。
