# 030.2 — 維運者可以在儲存與備份頁、主機磁碟頁看到磁碟、掛載、用量分類與容量告警

**Epic:** 磁碟與儲存（`epic:storage`）  
**User Story:** 維運者可以管理儲存  
**Milestone:** M1 單機主機管理  
**Parent:** 030  
**Blocked by:** 030.1 Agent 回報磁碟、分割區、掛載與用量分類，Core 保存並以 API 提供容量告警, 017 使用者可以在主導覽、全域搜尋與工作中心之間完成日常操作  
**規格章節:** 07｜介面與操作體驗、13｜磁碟、儲存與資料位置

## What it delivers

畫板 `design/screens/Storage.dc.html`、`NodeDisks.dc.html` 與 `Overview.dc.html` 的磁碟部分，資料來自 030.1 的 `GET /management/v1/nodes/{id}/storage` 與 `/management/v1/storage/alert-rules`。

## Acceptance criteria

- [x] 主機磁碟頁列出磁碟與分割區（型號、介面、大小、UUID 與標籤、檔案系統、掛載點）；健康與溫度沒有讀到時顯示「尚未讀取」或「不支援」，不顯示「健康」。
  - 證據：主機頁「磁碟」分頁（`web/src/nodes/storage/NodeDisks.tsx`），單元測試 `disks.test.tsx`「lists disks and partitions…」，e2e `host-disks.spec.ts` 真 Agent 與完整狀態兩條。溫度不在 030.1 的接口裡，磁碟一律顯示「尚未讀取」，等 020.3。手機寬度健康與溫度欄收起，摘要列寫「健康尚未讀取」。
- [ ] 掛載清單顯示每個掛載怎麼認磁碟（UUID、標籤、裝置名稱…）、開機時的行為與設定寫在哪（fstab 第幾行、systemd 單元、手動掛上沒有設定）；用裝置名稱掛載的標出警告與「改用 UUID」的入口。
  - 已完成：認磁碟的方式、裝置名稱的警告圖示（其他掛載不加圖示）、開機時行為、`/etc/fstab:第幾行` 或 systemd 單元檔、手動掛上寫「沒有設定」。單元測試與 e2e 都有。
  - 剩下：「改用 UUID」的入口。它要改 fstab，屬於掛載變更（票 031／032），後端還沒有這個動作；入口要跟動作一起做。
- [x] 設定衝突（同一掛載點寫兩次、指向不存在的磁碟、開機該掛卻沒掛上）列在磁碟頁，標出寫在哪個檔案的哪一行。
  - 證據：「設定衝突」表，`/etc/fstab:11 · UUID=…`；單元測試「lists conflicts…」，e2e 完整狀態。裝置名稱掛載不列在這裡，標在掛載列上。
- [x] 用量分段橫條依 DESIGN.md 的六類固定順序與顏色，各段加起來等於已用空間，沒有的類別不顯示；量測不完整時標出「至少」且不畫「其他」。
  - 證據：`model.ts` 的 `breakdown`，單元測試「orders categories the fixed way…」「never draws a partial…」，e2e 完整狀態檢查橫條的無障礙名稱。量測不完整時不畫橫條，只列「至少 X」與原因（幾個目錄讀不到，或掃描到上限），避免看起來像完整結果。
- [ ] 容量告警（可用空間、inode、依 7 天趨勢預估寫滿）標在每個掛載上；告警門檻可以在畫面上設定預設值、單一主機與單一掛載點，並說明哪一條規則生效。
  - 已完成：三種告警標在掛載列與用量卡片上，數字取自掛載本身；每張用量卡片寫出生效的是哪一層規則（內建預設、平台預設、這台主機、所有主機的這個掛載點、這台主機的這個掛載點）。
  - 剩下：在畫面上設定門檻（`PUT`／`DELETE /storage/alert-rules`）。畫板沒有這個畫面，見下方設計缺口。
- [ ] 渲染結果依 DESIGN.md 比對，桌面與手機寬度都檢查。
  - 主機磁碟分頁：e2e 對 1440 與 360、深淺色跑版面與無障礙掃描，四種組合都通過，截圖已人工看過。
  - 剩下：儲存與備份頁（跨主機）與總覽的磁碟卡片還沒做，見 Notes。

## Notes

- 030.1 的 PR 描述列有「設計缺口」，畫面動工前先看設計端補了哪些。
- 儲存與備份頁要跨主機列出資料碟，030.1 只提供單一主機的接口。做這張票時決定是逐台呼叫，或在 Core 加一個依權限篩選主機的彙總接口。
- 2026-11-14：審 PR #181 時看到，Agent 在容器裡會把單一檔案的 bind mount（`/etc/hostname`、`/etc/hosts`、`/etc/resolv.conf`）當成檔案系統回報，主機頁的檔案系統卡片因此多出三列一樣大小的項目。裝了 Docker 的主機也可能有同類雜訊。修正點在 Agent 的清單（掛載點是檔案、不是目錄的略過，或標成另一類），不在畫面；做這張票時一起決定並補測試。
- 2026-11-14（票 030.2 第一段，PR 見分支 `ticket/030.2-storage-screens`）：這次只做主機頁的「磁碟」分頁。還沒做：儲存與備份頁（跨主機的資料碟、最大的儲存卷、備份，見畫板 Storage）、總覽頁的磁碟卡片、告警門檻設定畫面、「改用 UUID」入口、用量卡片的 30 天走勢小圖（要讀 `filesystem.usedBytes` 歷史）。跨主機要逐台呼叫或加彙總接口，上面那條決定仍未做。
- 2026-11-14 決定單一檔案 bind mount 的處理：修在 Agent，不在畫面。真 Agent 在容器裡跑時，`/etc/hostname`、`/etc/hosts`、`/etc/resolv.conf` 同時出現在指標的檔案系統清單（`agent/crates/agent/src/monitor/collect.rs`）和儲存清單的掛載（`agent/crates/agent/src/storage/inventory.rs`），而且都被當成「用裝置名稱掛載」，各自掛著一樣的容量告警（e2e `disks-live` 截圖）。兩處都沒有判斷掛載點是不是目錄。後續要做：Agent 兩個清單都略過掛載點不是目錄的項目（它沒有自己的檔案系統，容量就是來源檔案系統的），補單元測試；畫面照 Agent 回報的顯示，不在前端過濾。
- 用量量測要高權限執行器，e2e 的容器裡沒有，所以真 Agent 那條只驗到「用量還沒量過」。完整、不完整與告警狀態用真 Core 的回應換掉 body 後掃描與截圖（`host-disks.spec.ts` 第二條）。

- 2026-11-14 完整 e2e 有兩條紅燈不在這張票的畫面：`shell-scan.spec.ts`「scan /nodes @360 dark/light en open」，主機清單每列的「More actions」按鈕跑出表格外。只在清單同時有一台還連線中的真 Agent 主機（`host-disks.spec.ts` 的容器還沒關）時出現；拿掉這個 spec 跑 133 條全過，只跑 first-run、host-disks 與這條掃描也全過。問題在主機清單 360 寬英文版的欄寬，不在磁碟分頁；交給負責主機清單的票修，修好前這兩條會紅。
- 獨立審查（程式與畫面、驗收各一個 Opus 子代理）找到並已修正：`/etc/fstab:5` 仍被斷行（選擇器優先順序）、手機寬度表格欄位被擠壓、裝置只列第一個掛載點、摘要整行標紅。修正後重跑單元測試 281 條與磁碟 e2e 4 條全過。
