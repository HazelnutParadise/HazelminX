# 089 — 管理員可以在符合條件時不中斷部署，不符合時看到具體原因與回復選項

**Epic:** 不中斷部署（`epic:deploy`）  
**User Story:** 專案管理員可以安全更新服務  
**Milestone:** M5 多節點、叢集、遷移與發布  
**Blocked by:** 046 管理員可以查看部署版本、三方比較並回到相容舊版, 056 使用者可以建立靜態與反向代理網站、綁定多網域並穩定路由到容器服務, 008 使用者可以提交工作後關閉頁面，之後仍能查到進度、證據與結果  
**規格章節:** 18｜不中斷部署、版本回復與資料變更  
**Issue:** [#88](https://github.com/HazelnutParadise/hazelminx/issues/88)  

## What it delivers

18.1 能力標籤、先建新版不停舊版、健康檢查切換、路由版本與觀察期、長連線排空、映像／設定／資料回復分開、無關服務不重建、自動部署授權範圍、中斷後向 Agent 對帳。

## Acceptance criteria

- [ ] **DEP-001** 管理員可以在部署前知道是否符合不中斷條件。 — 完成條件：顯示不符合的具體原因，不能只有「不支援」或不實的零停機標章。
- [ ] **DEP-002** 平台可以先建置與準備新版，不停止舊版。 — 完成條件：建置、下載或預檢失敗時舊服務不受影響。
- [ ] **DEP-003** 平台可以以健康檢查決定是否切換流量。 — 完成條件：HTTP／業務檢查失敗不切換；只看到程序 running 不算健康。
- [ ] **DEP-004** 平台可以切換路由並保留舊版到觀察期結束。 — 完成條件：切換與路由版本有記錄；異常可在資料相容前提下切回。
- [ ] **DEP-005** 管理員可以設定長連線排空政策。 — 完成條件：WebSocket、SSE、gRPC、上傳與下載各有測試，不以一般 GET 成功代表全通過。
- [ ] **DEP-007** 管理員可以判斷回復程式是否也能回復資料。 — 完成條件：介面分開顯示映像回復、設定回復、資料回復；不可逆時不提供假一鍵回復。
- [ ] **DEP-008** 平台可以避免更新無關服務。 — 完成條件：更新前後比對容器／工作負載 ID 與資料版本；未在計畫中的服務沒有被重建。
- [ ] **DEP-009** 管理員可以安排正式環境核准或自動部署。 — 完成條件：自動範圍不包含未授權的資料刪除、路徑搬移、權限提升或網路公開。
- [ ] **DEP-010** 平台可以在部署中斷後判斷實際狀態。 — 完成條件：不因 Core 沒收到回覆就重跑 migration；先向 Agent／叢集核對已執行步驟。
- [ ] 資料只能獨占寫入時拒絕藍綠；節點失聯不啟動第二個獨占寫入者

## Acceptance tests（第 42 章）

- **T-072** 對健康 HTTP 服務部署壞的新版本。 → 不切流量，舊版本維持。
- **T-073** 對健康 HTTP 服務部署好版本，持續送請求。 → 在定義測試條件下無部署造成的失敗；保留請求數與錯誤證據。
- **T-074** 更新期間有 WebSocket／SSE 長連線。 → 依排空政策處理，超時終止明示，不宣稱永久連線永不斷。
- **T-075** 兩版本同時啟動但資料只能獨占寫入。 → 拒絕藍綠或選用已驗證方法。
- **T-077** 節點失聯，但不確定是否仍在寫共享資料。 → 不啟動第二個獨占寫入者，先隔離舊節點或等待確認。
