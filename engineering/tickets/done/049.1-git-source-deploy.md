**Milestone:** M2 容器、Compose 與 GitHub  
**Parent:** 049

**Issue:** [#185](https://github.com/HazelnutParadise/hazelminx/issues/185)

## What it delivers

- 單元的來源多一種 `git`。綁定記下：GitHub 連線參照與 Repo ID，或手動 URL 與單元自己的憑證參照（PAT 或 SSH Deploy Key，值只在機密庫）；ref、Core 解析出的 commit SHA、主檔、合併檔、profiles 與工作目錄。
- Core 抓取時只要那一個 commit（決策 0036）：不走磁碟、不執行 hook、不讀 repo 的 `.git` 設定、不跟 submodule；憑證只放在請求的驗證標頭或 SSH 驗證裡，不進 URL、日誌、錯誤或稽核。
- 從抓到的樹取出 compose 檔與它以相對路徑掛進容器的檔案，變成單元內容，交給 044.1 驗證、044.2 部署；不另開部署路徑。
- 樹裡用到 submodule、Git LFS 指標檔、符號連結或 `build:` 時，在預檢明確擋下並寫出原因（049.2 補上）。
- 部署紀錄寫下 repo、ref 與 commit；change plan 的內容綁定來源，連線停用、失去 Repo 權限或來源改變後，部署前重新檢查並拒絕。

## Acceptance criteria

- [x] **CMP-002** 管理員可以指定 GitHub repo、分支／tag／commit 與 Compose 路徑。 — 完成條件：每次部署固定 commit SHA，不在建置到一半改讀移動中的分支。 — 已完成：`POST …/compose/git` 以 GitHub 連線＋Repo ID 或 URL 加 ref、mainFile、extraFiles、workingDir 匯入；Core 把 ref 解析成 SHA 後只抓那個 commit。分支之後移動不影響已存的內容，換 commit 是 `PUT …/compose/git`（新單元版本）。證據：`TestGitUnitDeploysTheCommitCoreFixedThroughThePlan`（匯入後推新 commit，部署送出的是舊 commit 的檔案，部署紀錄 `sourceCommit` 是舊 SHA）、真引擎 `TestInteropDeploysAGitCommitThroughTheRealAgentExecutorAndDocker` 第 1、2 段。
- [x] **CMP-003** 管理員可以使用 HTTPS 憑證、GitHub App 或 SSH Deploy Key 存取私有 repo。 — 完成條件：採最小權限；驗證伺服器指紋／CA；憑證不進 URL、日誌或建置 context。 — 已完成：GitHub App 走 047.1 的安裝 token（只要這個 Repo 的 contents:read、metadata:read）；HTTPS token 只放在 Basic 驗證標頭；SSH Deploy Key 必須附上主機公鑰，只接受那一把（RSA 用 SHA-2 簽章）。URL 帶帳密一律拒絕，錯誤訊息會去掉憑證；token 與私鑰只存在機密庫。證據：`TestFetchesExactlyTheResolvedCommitOverHTTPWithTokenInHeaderOnly`、`TestSSHNeedsTheConfiguredHostKey`、`TestGitUnitOverSSHNeedsThePinnedHostKey`，API 測試掃整個資料庫找不到 token 與私鑰，真引擎測試在主機的修訂版目錄、帳本、Agent 狀態與執行器日誌都找不到 token。建置 context 在 049.2；049.1 對 `build:` 一律擋下。
- [x] **GIT-009** 使用者可以繼續手動填 Repo URL 並指定個別 PAT 或 SSH 金鑰。 — 完成條件：不必先建立 GitHub App；原有部署不被強制改成帳號瀏覽模式。 — 已完成：`url` 模式不需要任何 GitHub App 或連線，憑證種類 `none`、`token`（可帶使用者名稱）、`ssh-key`（附主機公鑰），存在單元自己的機密裡。編輯時 `credential: {unchanged: true}` 只在 URL 完全相同時沿用。證據：上列 HTTP 與 SSH 測試、`TestGitUnitTakesWholeMountedDirectories`（不帶憑證）。
- [x] **GIT-011** 專案管理員可以讓多個部署綁定共用連線。 — 完成條件：保存連線參照而非複製明文 Token；每個專案的 Repo 與環境權限分別驗證。 — 已完成：單元只存 `connection_id` 與 Repo ID（`compose_unit_git_sources`），多個單元可以指向同一個連線，token 每次向 047.1 取。匯入要有該專案的 `projects:write`，也只能用呼叫者自己的連線（`GetConnection` 驗擁有者）；指定節點要看得到該節點。證據：`TestGitHubUnitIsRecheckedBeforeDeploying`（不在連線清單裡的 Repo 回 404、安裝 token 不進資料庫）。讓其他成員也能用同一個連線，是 051 的分享授權。
- [x] **GIT-038** 使用者可以確認讀取、選擇與部署是同一份來源。 — 完成條件：授權、Repo ID、來源站台、ref、commit 與設定摘要綁定；預覽後權限或來源改變須重新檢查。 — 已完成：來源列（種類、連線、Repo ID、URL、站台、驗證方式、主機公鑰、ref、commit、取出的檔案）有自己的摘要，和單元版本在同一個交易寫入。部署計畫多一個 `source` 變更項與 `git-source` 檢查，所以內容綁定來源。產生計畫與部署步驟開始前都重新檢查：GitHub 連線停用、需要重新授權、Installation 不再包含這個 Repo，或 URL 來源存下的憑證被撤銷，計畫的檢查會失敗、已批准的計畫因內容改變而作廢，工作以 `GIT_SOURCE_CHANGED` 停止，節點收不到任何步驟。證據：`TestGitHubUnitIsRecheckedBeforeDeploying`、`TestGitUnitDeploysTheCommitCoreFixedThroughThePlan` 的撤銷段落。
- [x] 讀取、選擇與部署綁定同一份來源，權限或來源改變須重新檢查 — 同 GIT-038。
- [x] 不支援的 submodule、LFS、符號連結與建置在預檢明確擋下，不部署缺檔內容 — 已完成：`GIT_SOURCE_REFUSED` 與 `details.refusals[]` 逐一寫出路徑與原因，包含符號連結（檔案本身或上層目錄）、submodule、LFS 指標（含舊的 hawser 格式）、非 UTF-8、本機 `build:`、超過單元上限。掛載的目錄連同裡面的 compose 檔整個取出。證據：`TestGitUnitRefusesContentItCannotDeployCompletely`、`TestGitUnitTakesWholeMountedDirectories`。
- [x] 端到端：測試自己架的 Git 伺服器 → 抓取固定 commit → 預檢 → 真的 Docker 引擎部署，部署紀錄寫著該 commit — 已完成：`TestInteropDeploysAGitCommitThroughTheRealAgentExecutorAndDocker`（git http-backend 加 token、Agent 以 uid 65534 執行、root 執行器、dockerd），本機 Linux 容器 64 秒通過；CI 的 interop 工作以既有的 `-run Interop` 步驟執行。
