# 030.1 — Agent 回報磁碟、分割區、掛載與用量分類，Core 保存並以 API 提供容量告警

**Epic:** 磁碟與儲存（`epic:storage`）  
**User Story:** 維運者可以管理儲存  
**Milestone:** M1 單機主機管理  
**Parent:** 030  
**Blocked by:** 020.1 Agent 回報主機資訊與資源指標，Core 保存有解析度的歷史並以 API 提供  
**規格章節:** 13｜磁碟、儲存與資料位置、增補 03 51.3、51.6  
**Issue:** [#170](https://github.com/HazelnutParadise/hazelminx/issues/170)  

## What it delivers

Agent 透過新能力 `host.storage` v1 回報兩則訊息（契約見 `engineering/contracts/README.md`「儲存清單與用量」）：

- `host_storage`：磁碟與分割區（含檔案系統 UUID、標籤），每個掛載怎麼認磁碟、設定寫在哪（fstab 第幾行或 systemd 單元，沒有設定就是手動掛上），swap，以及設定問題。每 60 秒讀一次，有改變才送。
- `storage_usage`：每個本機檔案系統的用量分類。啟動 5 分鐘後第一輪，之後每 6 小時一輪，以最低 CPU 與 I/O 優先權執行。

Core 以 migration `0015_host_storage.sql` 保存最新一份，`GET /management/v1/nodes/{id}/storage` 把它和最新樣本的容量、inode、7 天成長趨勢與容量告警合在一起提供；告警門檻以 `/management/v1/storage/alert-rules` 設定。畫面在 030.2。

## Acceptance criteria

- [x] **STO-001**（後端）維運者可以查看磁碟、分割區、檔案系統、容量、inode、溫度與健康資訊。 — 完成條件：來源不支援 SMART／溫度時標示不支援，不能顯示健康正常。
  - 證據：`GET /management/v1/nodes/{id}/storage` 列出磁碟與分割區（UUID、標籤、分割區 UUID 讀 udev 資料庫或 `/dev/disk/by-*`，都沒有時是 `null`）、掛載與最新樣本的容量、inode（`inventory_reads_devices_with_identity`、`TestHostStorageOverTheAPI`）。每顆磁碟的 `health.state` 一律是 `notCollected` 並附原因，分割區沒有 `health`，不會顯示健康（`TestHostStorageOverTheAPI`、真 Agent 互通測試）。
  - 不在這張票：SMART／NVMe 健康與每顆磁碟的溫度由 020.3 讀，填進同一個欄位（已寫進 020.3 的驗收條件）。
- [x] 每個掛載標出怎麼認磁碟（UUID、標籤、裝置名稱…）與設定寫在哪；用核心裝置名稱掛載的本機磁碟列為 `deviceName` 問題；同一掛載點兩筆設定、設定指到不存在的裝置、開機該掛卻沒掛上都列出。
  - 證據：`mounts_carry_reference_and_configuration`、`problems_are_reported`、`references_by_spec`（假的 `/sys`、udev、fstab、systemd 單元樹）；`TestHostStorageOverTheAPI` 經 API 讀到 `deviceName /mnt/scratch` 與 `missingDevice /mnt/old`。fstab 與單元裡的密碼不送出（`mount_secrets_are_redacted`）。
- [x] **STO-010**（容量）維運者可以設定容量與健康告警。 — 完成條件：同時檢查可用位元組、inode 與備份暫存需求，不等寫滿才通知。
  - 證據：每個掛載依規則算出 `availableLow`（可用比例或位元組下限）、`inodesLow`、`fullSoon`（7 天趨勢在 N 天內寫滿），還沒寫滿就告警；規則可設預設、單一主機、單一掛載點與兩者，最具體的生效（`TestEvaluateThresholds`、`TestRulePrecedenceAndValidation`、`TestGrowth`、`TestHostStorageOverTheAPI`）。改規則寫稽核紀錄。預設：可用低於 15% 警告、低於 5% 或 2 GiB 嚴重（2 GiB 只用在 20 GiB 以上的檔案系統，小的 `/boot` 只看比例），inode 低於 10% 警告、3% 嚴重，14 天內寫滿警告。
  - 不在這張票：備份暫存需求要等備份工作存在，已寫進 078 的驗收條件（`backupStaging` 現在是 `notApplicable`）；健康告警等 020.3 的健康結果；告警送出通知在 081。
- [x] （使用者 2026-11-12）用量分類不重複計算，各類加起來等於已用空間，所有硬碟共用同一組六類，沒有的類別不列；現在認得出來的分類照實回報，認不出來的算「其他」。
  - 證據：Agent 只量固定的目錄，每個路徑只算一類，巢狀的起點交給內層（`/var/lib/docker/volumes` 只算應用資料），硬連結只算一次，不跨進其他掛載點（`usage_counts_each_path_once_and_adds_up`、`usage_stops_at_mount_points_and_skips_virtual_roots`）。量到的比已用空間多、碰到上限或有目錄讀不到時標 `partial` 且不給「其他」（`usage_over_used_space_is_partial`、`usage_budget_makes_the_round_partial`），Core 拒收加不起來的 `complete`（`TestRecordUsageRejectsCompleteThatDoesNotAddUp`），API 依固定順序列出有位元組的類別（`TestFSUsageOrderAndOther`）。Linux 容器的真 Agent 量到容器映像 3,002,368 位元組（3 MB 檔與它的硬連結只算一次）、應用資料 1,003,520 位元組，加起來等於已用空間。
  - 現在認得的：容器引擎儲存（容器映像）、具名 volume 與平台外的資料庫目錄（應用資料）、容器日誌與作業系統、套件、日誌目錄（作業系統與日誌）。「資料庫」與「備份暫存」要等平台管理資料庫（069）與備份（078），現在一律在「其他」。
- [x] （增補 03 51.6）平台資料磁碟不足時允許的清理類、搬移類工作清單（見下方 Notes），執行在 017。
- [x] 量測目錄大小不超出 `agent/PERFORMANCE.md` 的預算，記錄多久跑一次與成本。
  - 證據：`agent/PERFORMANCE.md`「票 030.1」：`f02278e` 閒置兩輪 0.0200%、0.0133%，峰值 4.82 MiB；一輪量 29,100 筆用 0.13～0.16 秒 CPU、峰值 4.9 MiB。第一輪在啟動 5 分鐘後，之後每 6 小時一輪，nice 19、idle I/O，一輪最多 500 萬筆或 20 分鐘。百萬筆主機的成本是推算，沒有實測。
- [x] 真 Agent 對 Core 的互通測試在 macOS 與 Linux 容器通過。
  - 證據：`TestInteropAgentReportsStorage`，macOS 上沒有 `/proc`，清單是空的並在 `unreadable` 寫出 `/proc/self/mountinfo`；Linux 容器（`hzx-ledger-test:trixie`、aarch64、btrfs）掛 volume 到 `/var/lib/docker` 後量到上面的分類。

## Notes

### 未驗證

- 只在假的 `/sys`、udev、fstab 樹與 OrbStack 的 Linux 容器驗過；實機的 udev 資料、`/dev/disk/by-*`、LVM、RAID、XFS reflink 與 nice／ioprio 實際生效都沒有在真機驗證。
- 容器的 `/` 是 overlay，不在量測範圍內，所以作業系統與日誌這一類只在假的目錄樹驗過，沒有在真的系統碟上量過。
- 百萬筆以上的目錄樹的成本與硬連結記錄的記憶體用量沒有實測。

### 留給後續

- Core 沒有宣告 `host.storage` 時，Agent 照樣每 6 小時量一次用量，只是不送出。成本見 PERFORMANCE.md；若要省，可以等連上宣告能力的 Core 才開始。
- 容器的可寫層和映像層放在引擎的同一個目錄裡，現在都算「容器映像」；要分開需要引擎的 API（040），設計端要決定是否另立一類（PR 的設計缺口）。
- btrfs 子卷各自有裝置號碼，量測以掛載點判斷所屬檔案系統；同一個 btrfs 掛在多個點（bind mount）時，用量列在量到分類的那個掛載點下。

### 平台資料磁碟不足時允許的工作（增補 03 51.6，與 017 共同）

平台資料目錄所在的檔案系統剩不到 5% 或 2 GiB 時（增補 03 第 187 行的降級條件），網頁上只允許下列會釋放或搬走空間的工作，其他新工作與上傳一律擋下。判斷與擋下由 017 的降級機制做，這張票只決定清單：

- 清理類：刪除沒有容器使用的映像與建置快取（041）、截斷或輪替容器日誌（040）、刪除超過保留期限的平台日誌、診斷包與工作紀錄（035）、刪除備份暫存目錄裡沒有對應進行中備份的殘留檔（078）、依保留政策刪除舊的部署版本（046）。
- 搬移類：把應用資料搬到別顆磁碟（033）、把備份暫存目錄改到別顆磁碟（078）。

清理類工作只刪平台能證明可以刪的東西，刪除前照常列出影響；磁碟寫滿到資料庫唯讀時（T-186），網頁上連清理也不能新增，只能用 CLI。
