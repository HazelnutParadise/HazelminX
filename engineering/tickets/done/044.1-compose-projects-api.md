## What it delivers

Core 的 `projects` 套件與 `/management/v1/projects` API（migration 0016）。

- 專案 → 專案環境 → Compose 單元三層，名稱依 52.1（小寫字母開頭，只含小寫字母、數字與 `-`，最多 30 字元）。單元建立時固定 Compose 專案名稱 `<專案>-<專案環境>-<單元>`，之後不變。一個專案環境目前只有一個單元；多個單元與 Kubernetes 單元是 108。
- 單元的來源是上傳或編輯器的一組檔案：路徑相對於專案目錄，原文逐位元組保存，不重新排版。單元指定主檔，再依序加入要合併的檔案（等同多個 `-f`），選要啟用的 profiles。沒有自動選檔。標成機密的檔案（例如 `secrets:` 的 `file:`）內容存進機密庫，API 不回傳內容，只回傳大小與摘要。
- 驗證用 Docker Compose 本身使用的解析器 compose-go，固定版本。解析時用乾淨的環境：不讀 Core 的環境變數，不自動讀 `.env`。結果分成接受、拒絕與提示，每一項寫出檔案、欄位與原因；Compose 規格不允許的鍵拒絕並說明，`x-` 擴充與規格允許但 HazelminX 不處理的鍵保留原文並列出，不靜默刪除。
- 預覽回答部署會做什麼：每個服務的映像或建置來源、profile 是否啟用、Port、掛載（bind 掛載解析後的路徑、命名儲存卷的實際名稱 `<Compose 專案>_<卷>`）、網路（外部網路標出）、替換變數（缺值、用預設值、已提供）、高風險設定（privileged、主機網路或 PID、掛進引擎 socket 或主機根目錄、加 capability、裝置）與目標引擎環境的狀態。主機上沒有可用的 Docker 或 Podman、或沒有 compose 外掛時，預覽寫出原因並標為不可部署，不提供安裝。

替換變數的來源（分層 `.env` 與介面變數）是 045；這張票的預覽沒有任何替換值，所以 `${VAR:?}` 一律列為缺值並擋下，`${VAR:-預設}` 列為使用預設值。

## Acceptance criteria

- [x] **CMP-001**（上傳與編輯器部分）專案管理員可以從上傳檔案與編輯器匯入 Compose。 — 完成條件：支援指定工作目錄、多個 `-f` 檔案、profiles、build context 與外部資源宣告。Git 來源由 049、商店來源由 052 交付。
  - 證據：`POST/PUT …/environments/{envId}/compose` 收 `source`（upload／editor）、`mainFile`、依序的 `extraFiles`、`workingDir`、`profiles`；預覽列出每個服務的 build context 與 Dockerfile、外部網路與儲存卷（`TestMergesFilesInOrderWithProfilesBuildAndRelativePaths`、`TestProjectsEnvironmentsAndComposeUnitsOverTheAPI`）。Git 與商店兩種來源不在這張票。
- [x] **CMP-015** 管理員可以處理不認識的合法 Compose 欄位。 — 完成條件：原文無損保存；執行器不支援時說明，不靜默刪除 security、healthcheck 或 network 設定。
  - 證據：檔案逐位元組保存並原樣讀回（API 測試比對 `compose.yaml` 全文）。Compose 規格不允許的鍵拒絕並寫出鍵名（`TestRefusesWhatComposeRefusesAndSaysWhy`）；`x-` 擴充與 Swarm、`compose watch` 才用的鍵（`deploy.placement`、`develop` 等）列為「保留原文、不套用」並說明原因，`deploy.resources`、`healthcheck`、`security_opt` 不在其中（`TestKeepsSwarmOnlyAndWatchAttributes`）。
- [x] 專案、專案環境與單元的建立、讀取、列表（分頁、排序、篩選）、修改（`If-Match` 版本）與刪除，依專案範圍驗權，看不到的專案回 404，每個變更寫稽核紀錄。
  - 證據：`TestProjectsEnvironmentsAndComposeUnitsOverTheAPI`：他專案的專案管理員讀取回 404、列表是空的；專案管理員不能建立專案（403）、不能指定看不到的節點、預覽不描述看不到的節點；稽核員可讀不可檢查；缺 `If-Match` 回 428、過期回 412；單元的建立、四次修改、刪除各一筆稽核。機密檔內容只在機密庫，表裡是 NULL，回應與稽核都沒有內容也沒有摘要；改內容一次寫入完成（見下方審查 P1）。
- [x] 不需要主機的預檢在預覽列出：缺必要變數、相對路徑跑出專案目錄或指向不存在的上傳檔、高風險設定、目標引擎不可用（CMP-007 的這一部分，其餘在 044.2）。
  - 證據：`TestVariablesUseACleanEnvironment`（Core 自己的環境有 `TAG` 也照樣列為缺值並擋下）、`TestRelativePathsThatLeaveTheUnit`、`TestSecretFilesMustBeMarkedSecret`、`TestLabelFilesStayInsideTheUnit`、`TestHighRiskSettingsAreListed`；預覽在沒設目標、目標不存在、Podman 沒回應時都標為不可部署並寫原因，Docker 有 compose 外掛時可部署。
- [x] 多 Compose 檔案、profiles、build 與相對路徑的解析結果與原生 Compose 一致。
  - 證據：`TestT052AgreesWithNativeCompose` 以同一組檔案跑原生 `docker compose -p … -f … -f … --profile … config`（乾淨環境），比對啟用的服務、映像、build context 與 Dockerfile、Port、掛載（含子目錄裡的 `../shared/ca.pem`）、網路、儲存卷與網路名稱，本機 Docker Compose 5.5.0 通過；CI 上沒有 docker 時這個測試失敗而不是略過。
