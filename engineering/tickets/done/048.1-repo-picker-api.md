## What it delivers

Core 的 `core/internal/github` 與 `/management/v1/github`，建立在 047.1 的連線上：

- Repo 清單：每份連線各自保存一份清單。清單來源分開同步：個人與協作 Repo、每個組織各一份、App 安裝一份，每份有自己的游標與狀態。同一個 Repo 經兩份連線讀到就是兩筆，各自寫出連線。
- 同步：`POST …/connections/{id}/repositories/sync` 每次最多讀 10 頁就回應，狀態分成從未同步、同步中、完整、部分（某來源失敗）、限流（附 `retryAt`）、授權已變更（舊結果）。全部來源都讀完時，下一次從第一頁重來，送出上次的 ETag，GitHub 回 304 就沿用原有資料。
- 限流：依 GitHub 的 `Retry-After`、`X-RateLimit-Reset` 等待；剩餘次數為 0 時提早停下。等待期間這份連線的同步與瀏覽都不呼叫 GitHub，也不換別的連線。
- 授權變更：清單記下同步時連線的授權指紋（帳號、方式、安裝、scopes、權限、可用 Repo、到期日）。指紋不同時標成舊結果、不算完整，下一次同步全部重讀；輪替 PAT 直接清掉舊清單。回應前再套用目前的連線範圍與擁有者。
- 瀏覽：分支、標籤、commit（GitHub 分頁，`cursor` 往下一頁）、目錄內容、把分支或標籤固定成 commit SHA、找 Compose 檔案。只接受該連線清單裡的 Repo；App 安裝連線每次申請只涵蓋那個 Repo、只有讀取權的 Token。Repo 改名或移轉時用穩定 ID 重新讀取。
- Compose：每個目錄依 Docker Compose 的預設順序取一份主檔（`compose.yaml`、`compose.yml`、`docker-compose.yaml`、`docker-compose.yml`），再加同名的 override 檔；同目錄其他主檔列為被忽略。結果分成空 Repo、沒有、一份、多份。
- 資料表在 migration `0013_github_repos.sql`，刪除連線時一併刪除。呼叫 GitHub 一律經 `github.Client` 介面，測試用假 GitHub。

## Acceptance criteria

證據路徑以 `core/` 為根；測試以 `go test -race -count=1 ./...` 執行（2026-11-14，macOS arm64）。服務層用 `internal/github/fake_repos_test.go` 的假 GitHub（分頁、ETag 與 304、限流、組織失敗、改名、空 Repo）；HTTP 客戶端用本機 `httptest` 伺服器測。沒有對真正的 GitHub 測過，見 Notes。

- [x] **GIT-005** 使用者可以瀏覽自己獲授權使用的 Repo。 — 完成條件：列出授權允許的個人、協作與組織 Repo；公開／私人與封存狀態可辨，無權範圍不洩漏。 — 證據：`internal/github/repos_test.go` `TestInventorySpansPagesAndOnlyShowsWhatTheConnectionReaches`（自己的、協作的、組織的 Repo 都在；不屬於的組織不出現；`private`、`visibility`、`archived` 與篩選；別的帳號清單為空，同步、讀狀態、瀏覽都回不存在；回應不含 Token）、`TestSameRepositoryThroughTwoConnectionsStaysBound`（安裝連線只列授權者碰得到的 Repo，清單外的 Repo 回不存在）、`TestInventoryFollowsTheCurrentAuthorization`；API `internal/api/github_repos_test.go` `TestGitHubRepositoryPickerAPI`（專案管理員看不到別人的清單，稽核者不能使用）。
- [x] **GIT-006** 使用者可以搜尋與分頁載入完整可用清單。 — 完成條件：超過一頁仍能找到後續 Repo；部分失敗、限流、同步中與完整狀態分開顯示。 — 證據：`TestInventorySpansPagesAndOnlyShowsWhatTheConnectionReaches`（第二頁的 Repo 可搜尋，大小寫不拘）、`TestSyncStepReadsABoundedNumberOfPages`（每步最多 10 頁，未讀完時是同步中）、`TestRateLimitOnSecondPageShowsPartialResultAndWaits`、`TestOneOrganizationFailingDoesNotHideOthersOrComplete`、`TestInventoryFollowsTheCurrentAuthorization`（授權已變更不算完整）；API 清單用合約的 `limit`／`nextCursor` 分頁。畫面呈現在 048.2。
- [x] **GIT-007** 使用者可以在重複 Repo 項目中選擇使用哪份授權。 — 完成條件：清單合併不合併權限；部署記錄一份明確連線；失敗不偷偷更換身分。 — 證據：`TestSameRepositoryThroughTwoConnectionsStaysBound`（App 安裝與 PAT 都讀到同一 Repo 時各一筆；PAT 被撤銷或到期後呼叫失敗，期間用到的 Token 都是那份 PAT 的）；`TestRateLimitOnSecondPageShowsPartialResultAndWaits`（限流期間只用同一份 Token）。所有瀏覽路徑都在 `/connections/{id}/` 下。部署記錄連線在 049。
- [x] **GIT-008** 使用者可以瀏覽 Repo 的分支、標籤、commit 與 Compose 檔案。 — 完成條件：空 Repo、缺檔案、多 Compose、分支移動及預設分支變更均有明確處理；部署固定 SHA。 — 證據：`TestRefsCommitsAndComposeDetection`（分支、標籤、commit；多份 Compose 的目錄與檔案順序；分支移動後新的解析是新 SHA、先前結果不變；預設分支改了，空 ref 跟著新的預設分支並更新清單；空 Repo；沒有 Compose；目錄瀏覽與拒絕 `..` 等路徑）、`TestComposeProjectsOrder`、`TestRenamedRepositoryIsFollowedByID`；HTTP `internal/github/httpclient_repos_test.go`；API `TestGitHubRepositoryPickerAPI`（`GITHUB_REPOSITORY_EMPTY`、`resolve` 回 SHA）。部署時鎖 SHA 在 049。
- [x] **GIT-034** 系統可以遵守 GitHub API 的版本與限流規則。 — 完成條件：版本由相容層管理；有效分頁、ETag 與重試依據可檢查；不靠切帳號或高頻重試逃避限流。 — 證據：每個請求帶 `X-GitHub-Api-Version: 2022-11-28`（`httpclient.go`）；下一頁依 `Link: rel="next"`（`TestHTTPClientRepositoryPagesETagsAndLimits`）；`TestNextRoundReusesETagsAndFollowsChanges`（沒變的一輪全是 304，送出存下的 ETag；Repo 變少時刪掉不存在的頁；離開組織時刪掉該組織的 Repo）；`TestRateLimitOnSecondPageShowsPartialResultAndWaits`（`Retry-After` 到期前同步與瀏覽都不呼叫 GitHub）、`TestSyncStopsWhenRemainingRateIsZero`；`TestConcurrentSyncStepsDoNotDuplicate`。
- [x] 超過兩頁的 Repo 仍能搜尋到 — 證據：`TestInventorySpansPagesAndOnlyShowsWhatTheConnectionReaches`（使用者來源 152 筆、組織 130 筆，共三頁以上）、`TestRateLimitOnSecondPageShowsPartialResultAndWaits`（250 筆）。
- [x] 某組織失敗不掩蓋其他結果也不標完整 — 證據：`TestOneOrganizationFailingDoesNotHideOthersOrComplete`（SAML 擋下的組織標失敗並寫原因，其他來源完整，整體是部分；連組織清單都讀不到時仍同步個人 Repo，整體是部分）。

## Notes

- 沒有對真正的 GitHub 跑過：`/user/repos?affiliation=owner,collaborator`、`/orgs/{org}/repos`、`/installation/repositories` 的分頁與 ETag、304 是否帶 `Link`（實作不依賴它，沿用存下的 `has_next`）、空 Repo 回 409，都依 GitHub 官方文件實作。
- 同步是有上限的短請求（每次最多 10 頁），不是工作（job）；畫面在狀態為同步中時再呼叫一次。若之後要在背景定期同步，改成工作或排程。
- App 個人授權連線用 `/user/repos` 與 `/user/orgs`，GitHub 只回 App 已安裝且使用者可存取的 Repo。
- 檔案樹讀取沿用 1 MiB 的回應上限；極大的 Repo 會讀不到完整檔案樹，回 `GITHUB_UNAVAILABLE`。GitHub 自己截斷時回 `truncated: true`。
- 清單階段不偵測 Compose（每個 Repo 要多讀一次檔案樹），選定 Repo 後才掃描；畫板的「偵測」欄見 048.2 的設計缺口。
- migration 編號：main 目前到 0012，這張用 0013。票 030、039 若也新增 migration，後合併的一方改號並同步改這裡。
