# 039.1 — Agent 與 Core 偵測並提供每個節點的 Docker、Podman、K3s 狀態與環境

**Epic:** 容器引擎（`epic:containers`）  
**User Story:** 管理員可以管理容器引擎  
**Milestone:** M2 容器、Compose 與 GitHub  
**Parent:** 039  
**Blocked by:** 019 管理員可以用一次性註冊碼加入節點，並看到離線、過期、維護與撤銷狀態, 012 維運者可以執行需要高權限的固定動作，而 Agent 主程序維持低權限  
**規格章節:** 09｜節點加入、自動偵測與多節點、增補 02「同一台主機上的多個引擎環境」  
**Issue:** [#165](https://github.com/HazelnutParadise/hazelminx/issues/165)  

## What it delivers

高權限執行器的唯讀動作 `engine_inspect`（權限 `host.engines.read`）以 root 讀取 Docker、Podman、K3s 的程式、版本、systemd 單元、Docker CLI 外掛（compose、buildx），以及每個引擎 socket 對 `GET /version`、`GET /info` 的回答。Agent 收到 Core 的 `engines_probe`（能力 `host.engines` v1）就把授權憑證轉給執行器，報告原樣轉回。Core 在節點連上時、連線期間每 5 分鐘、以及 `POST /management/v1/nodes/{id}/engines/refresh` 時詢問，只保存最新一份報告與最新一次失敗（migration 0013），以 `GET /management/v1/nodes/{id}/engines` 提供。通道訊息寫在 `engineering/contracts/README.md`「容器引擎」。安裝在 039.2，畫面在 039.3。

## Acceptance criteria

- [x] **NOD-003**（後端）管理員可以看到各引擎的安裝、執行、版本與可管理能力。 — 完成條件：分開顯示 Docker、Podman、Kubernetes／K3s、Swarm 與相關 runtime，不重複計數同一工作負載。
  - 證據：報告固定列出 docker、podman、k3s 三種，各帶狀態、程式與版本、systemd 單元、compose／buildx 外掛；環境帶 Swarm `LocalNodeState`、cgroup 驅動與容器數（`podman_docker_socket_is_podman_and_rootless_envs_stay_apart`、`TestHostEnginesOverTheAPI`）。同一個 socket 經 `/var/run` 與 `/run` 兩條路徑只列一次，容器數不會算兩次（同一測試）。「可管理能力」目前以狀態與 `kindConfirmed` 表示，管理動作在 039.2、040。
- [x] **NOD-004**（後端）管理員可以管理不同 Linux 使用者的 rootless Podman 環境。 — 完成條件：明示擁有者與 socket；甲使用者容器不誤顯示為乙使用者資源。
  - 證據：擁有者取自 socket 檔案的 uid，名稱取自 `/etc/passwd`，且執行器以 `SO_PEERCRED` 確認回答的程序就是該 uid（`a_socket_served_by_another_uid_is_not_believed`）。Linux 容器內真 Agent＋真執行器：uid 1000 的 Podman 與 uid 1001 的 Docker 分成兩個 rootless 環境，容器數各自正確（`TestInteropRealAgentReportsEnvironmentsApart`）。
- [x] **ENV-001**（後端）每個節點列出所有環境（引擎＋擁有者＋連接端點），同種引擎多個時各自一列。
  - 證據：`GET /management/v1/nodes/{id}/engines` 的 `environments`，`id` 為 `env:<解析後端點>`（`TestHostEnginesOverTheAPI`、互通測試）。
- [x] **ENV-002** 以端點實際回應的引擎判斷種類（`podman-docker` 的 docker.sock 辨識為 Podman）。
  - 證據：`kind` 取自 `GET /version` 的回答；`docker.sock` 由 Podman 回答時為 Podman，互通測試以真執行器驗證；`podman-docker` 的 `docker` 包裝程式不算 Docker 已安裝（`podman_docker_wrapper_is_not_docker_and_ids_stay_put`）。
- [x] 狀態分開：未安裝、已停止、不相容、無權限、無回應、讀不到 systemd 各自一種狀態，不把全部問題當成沒安裝（INS-008 的狀態部分；INS-008 由 039.2 擁有）。
  - 證據：`engine_states_are_told_apart`、`old_engine_is_incompatible_and_silent_socket_is_not_responding`；沒有 systemd 時是 `unknown` 並列在 `uninspected`，不當成已停止。
- [x] 讀不到的值是 `null`，看不到的範圍列在 `uninspected`，不猜。
  - 證據：`empty_host_reports_every_engine_not_installed`、`a_users_link_to_another_socket_is_not_followed`；Core 拒收含控制字元、隱形格式字元或超長字串的報告（`TestValidateRefusesWhatTheDecoderLetsThrough`）。
- [x] 使用者的 `/run/user/<uid>/` 路徑連到別處或不屬於該使用者時，執行器不連線。
  - 證據：`a_users_link_to_another_socket_is_not_followed`；連上後再以 `SO_PEERCRED` 比對 uid，擋下檢查後才換成連結的競態。

## Acceptance tests（第 42 章與增補 02）

- **T-051** 同主機有 Docker、rootful 與兩個 rootless Podman。 → 分開辨識四個環境與使用者，不混淆容器。
- **T-149** 同一台有 rootful Docker 與 tim 的 rootless Docker。 → 辨識為兩個 Docker 環境，擁有者與 socket 分開。
- **T-150** 裝了 `podman-docker`，`/var/run/docker.sock` 指向 Podman。 → 辨識為 Podman 環境，不顯示成 Docker。
- **T-156** 一個 Docker 環境的 socket 消失（服務停了）。 → 只有該環境標為無法連線，同節點其他環境照常。

### Acceptance tests 結果

- T-051、T-149：互通測試以 rootful 加兩個不同使用者的 rootless 環境驗證分開辨識；同一台同時有 rootful Docker 與 rootless Docker 的組合由單元測試 `podman_docker_socket_is_podman_and_rootless_envs_stay_apart` 涵蓋。真實 Docker／Podman 引擎沒有在實機測過，用的是回答 Engine API 的替身 socket（CI 的 x86_64／arm64 runner 有真 Docker 時，互通測試改驗它被辨識為 rootful Docker）。
- T-150：通過（單元與互通）。
- T-156：部分。socket 還在但服務沒回應時，只有該環境是 `not_responding`，其他環境照常（`podman_docker_wrapper_is_not_docker_and_ids_stay_put`）。服務停止並刪掉 socket 時，該環境從清單消失，不會標成「無法連線」；要標出來需要 Core 記住上次看到的環境，列為剩餘項目。

## Notes

剩餘與審查留下、這次不修的項目：

- T-156 的 socket 被刪掉的情況（見上方）：Core 比對前一份報告，把消失的環境標為無法連線。歸 039.3 一起做，畫面才用得到。
- 沒開 API socket 的 rootless 引擎（Podman 不常駐）看不到，報告在 `uninspected` 寫明。要看到需進入各使用者的 session 執行 `podman info`，屬 039.2 或 040 的範圍。
- 使用者的 systemd user unit（`podman.socket --user`）沒有讀。
- `POST .../engines/refresh` 會等探測完成（最多約一分鐘，已有探測在跑時最多兩分鐘），沒有改成工作（job）。它是唯讀、各節點串行，並受 `nodes:write` 限制；若畫面需要非同步，039.3 改成工作。
- Core 不再等待時，Agent 轉給執行器的那次檢查不會被取消；執行器的 socket 探測總長已限 30 秒。
- `GET .../engines` 不標示節點現在是否在線；節點狀態由節點 API 提供，畫面合併顯示。
- `busy` 每個指紋一把鎖，不回收（數量等於節點數）。
- `host_engines` 以 `ON DELETE RESTRICT` 參照 `nodes`，與 `host_facts` 一致；日後做刪除節點時要一併刪除這些列。
