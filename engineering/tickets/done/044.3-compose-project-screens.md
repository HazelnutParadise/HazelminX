# 044.3 — 專案管理員可以在專案頁匯入、編輯、驗證 Compose 並看到部署預檢

**Epic:** Compose 部署（`epic:compose`）  
**User Story:** 專案管理員可以部署完整 Compose  
**Milestone:** M2 容器、Compose 與 GitHub  
**Parent:** 044  
**Blocked by:** 044.1, 044.2, 017 使用者可以在主導覽、全域搜尋與工作中心之間完成日常操作  
**規格章節:** 15｜完整 Compose、GitHub 與環境變數  
**Issue:** [#178](https://github.com/HazelnutParadise/hazelminx/issues/178)

## What it delivers

畫板 Projects、ProjectDetail、ComposeEditor、ComposeCompat、DeployCheck 的實作，資料來自 044.1 與 044.2 的 API：專案與環境列表、匯入與編輯 Compose 檔案、驗證結果（接受、拒絕、保留但不處理的鍵）、部署預覽與預檢、部署進度。

## Acceptance criteria

- [x] 畫面依 DESIGN.md 與上列畫板，以渲染結果比對。 — 證據：`web/e2e/projects.spec.ts` 對真的 Core 截下專案列表、無環境、編輯器、單元、計畫、批准、部署成功、部署失敗 8 個畫面的 1440／360 深淺色，每張都通過 `e2e/scan.ts` 的 axe、對比與版面掃描；截圖逐張看過，獨立 UI 審查的意見已修正。畫板上 API 沒有的資料列為設計缺口，寫在 PR 描述。
- **UI-008**（圖形化與原始編輯切換）已移到 044.4（[#189](https://github.com/HazelnutParadise/hazelminx/issues/189)）。這張票交付的原始編輯器逐字保存檔案，不認識的鍵不會被刪掉（e2e 讀回核對）。

## Notes

### 交付了什麼（2026-11-14）

- 專案列表（`/projects`）、專案頁的環境分頁外框、新增專案與環境、Compose 編輯器（上傳或貼上原文、主檔與 `-f` 順序、profiles、工作目錄、部署到哪台主機的哪個引擎環境）、檢查結果（擋下、高風險、警告、保留不處理與變數）、服務的唯讀圖形檢視、部署預檢、主機預檢工作、部署計畫（建立、批准、執行、看進度）與部署紀錄。程式在 `web/src/projects/`。
- 失敗的部署照實寫出：沒有自動回滾，已更新的容器維持新版、上一版檔案留在主機上；主機預檢失敗且主機沒變更時不顯示這段。
- 證據：`web/src/projects/pages.test.tsx` 11 條單元測試；`web/e2e/projects.spec.ts` 對真的 Core 跑，含版面與無障礙掃描（1440／360、深淺色），以及在真的 Docker 引擎（容器內 dockerd＋高權限執行器＋以 uid 65534 執行的 Agent）完成一次成功部署與一次建置失敗的部署。

### 從 016.2 拿來的範圍

只做部署需要的最小計畫畫面，放在專案頁的環境裡：計畫摘要、目標的真實名稱與版本、預檢、受影響服務、變更清單、批准確認框（寫出主機與環境、列出高風險與警告、要輸入環境名稱）、需要擁有者時非擁有者看到鎖住的按鈕與原因、撤回、計畫失效時列出哪個目標從哪一版變成哪一版並可重建計畫、執行與工作進度。016.2 其餘範圍（獨立的計畫頁、工作中心的等待批准清單、兩人同時修改的並列比對畫面）仍歸 016.2。
