**Epic:** GitHub 來源（`epic:github`）  
**User Story:** 使用者可以從 GitHub 部署  
**Milestone:** M2 容器、Compose 與 GitHub  
**Parent:** 047  
**Blocked by:** 009 擁有者可以登入、建立帳號與角色，未授權的 API 呼叫一律被拒絕, 011 管理員可以安全保存機密，且主金鑰可輪替並驗證舊備份仍可解密, 010 整合者可以用 /management/v1 的分頁、版本條件與工作回應操作資源

## What it delivers

Core 的 `core/internal/github` 與 `/management/v1/github`：

- GitHub App：用 manifest 引導建立，或手動輸入 App ID、Client ID／Secret、私鑰與 Webhook Secret。手動輸入時用私鑰簽 JWT 問 GitHub 這把鑰匙屬於哪個 App，對不上就拒絕。
- 連線：PAT、App 個人授權、App 安裝三種，屬於建立它的 HazelminX 帳號，其他帳號一律 404。以 GitHub 回報的穩定帳號 ID 辨認身分，可命名、停用、啟用、重新授權、輪替與刪除。
- 瀏覽器授權：一次性 state（資料庫只存雜湊）、綁定登入工作階段與帳號、10 分鐘期限、回呼位址只用設定的 `--public-origin`。個人授權帶 PKCE。回呼帶回的 installation ID 要向 GitHub 核對兩件事：安裝屬於這個 App，而且剛授權的使用者看得到這個安裝。
- Token：PAT 到期就標成需要重新授權；App 個人 Token 依 GitHub 回傳的期限用 refresh token 更新，同一連線同時只更新一次，失敗後等待再試；安裝 Token 依回傳期限快取在記憶體，可縮小 Repo 與權限範圍。
- 可達性：分開回報「GitHub 會把瀏覽器送回哪個位址」與「GitHub 對 App Webhook 的送達紀錄」，兩者都沒有時仍可定期檢查。
- 秘密（私鑰、Client Secret、Webhook Secret、PAT、Access／Refresh Token）都經 011 的機密儲存加密保存，只有 Core 讀得到，不出現在回應、稽核紀錄或 GitHub 相關資料表。
- 資料表在 migration `0012_github.sql`。呼叫 GitHub 一律經 `github.Client` 介面，測試用假 GitHub 取代。

## Acceptance criteria

## Notes

- 沒有對真正的 GitHub 跑過：manifest 轉換、安裝時同時要求使用者授權（`request_oauth_on_install`）帶回的 `code` 與 `installation_id`、PKCE 在 GitHub App 個人授權的實際行為，都依 GitHub 官方文件實作，假 GitHub 照文件回應。需要有一個測試用 GitHub 帳號與 App 才能實測。
- 安裝流程不帶 PKCE：GitHub 的安裝網址沒有 `code_challenge` 參數，改靠 state、工作階段綁定與向 GitHub 核對安裝來防偽造。
- PKCE verifier 不存資料庫，由請求 ID 與每次啟動產生的金鑰算出；Core 重啟後，進行中的授權要重新開始。
- 連線的四種權利分開授權、共享給專案或團隊（GIT-012、GIT-017）在 051；目前只有建立者能看與使用。
- 獨立審查（diff-review、security-scan，2026-11-14）的確認問題都已修正並補測試：安裝 Token 縮到授權者碰得到的 Repo；檢查失敗不先改回可用；重新安裝恢復連線且不重複建立個人授權連線；更新 Token 後的寫入不受呼叫端取消影響、寫不進去就標成需要重新授權；系統改狀態寫稽核；輪替 PAT 與刪除連線要帶 If-Match；同連線的安裝 Token 不並行重複申請。
- 審查留下、這次不修：(1) refresh 只在單一 Core 程序內排隊，Core 若跑多個副本共用同一個資料庫，要改成資料庫層的鎖；目前架構只有一個 Core。(2) `GITHUB_REJECTED` 的訊息帶 GitHub 回的 `message`（截到 200 字），目前沒有看到會帶憑證的情況。(3) 輪替 PAT 先換機密值再改資料列，資料列更新失敗時機密已是新值、到期日等欄位還是舊的，下次檢查會更正。(4) 每個連線的鎖與 Token 快取只在刪除時清掉。
- migration 編號 0012：0011 由票 020 使用，store 要求編號連續，020 合併前本分支的 CI 會因缺 0011 失敗。
