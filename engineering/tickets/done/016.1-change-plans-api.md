# 016.1 — 管理員可以用 API 產生、批准並執行變更計畫，內容或資源版本改變時原批准失效

**Epic:** 身分與存取（`epic:iam`）  
**User Story:** 使用者可以安全執行長時間操作  
**Milestone:** M1 單機主機管理  
**Parent:** 016  
**Blocked by:** 008 使用者可以提交工作後關閉頁面，之後仍能查到進度、證據與結果, 010 整合者可以用 /management/v1 的分頁、版本條件與工作回應操作資源  
**規格章節:** 33｜工作引擎：按一次按鈕後，如何可靠完成、36｜管理 API 與事件契約  
**Issue:** [#147](https://github.com/HazelnutParadise/hazelminx/issues/147)  

## What it delivers

Core 的變更計畫：`core/internal/plans` 與 `/management/v1/change-plans` 的產生、列表、讀取、批准、拒絕、撤回、執行。計畫寫出目標的實際名稱、設定差異、受影響服務、預檢、風險、必要批准與有效期限；批准綁定計畫摘要（涵蓋目標與資源版本）與期限；批准與執行時重算計畫，內容或版本變了就讓原批准失效並回傳差異。要走計畫的工作種類不能直接 `POST /jobs`。資源種類各自的計畫內容由各資源票註冊（044、031、039…）。

## Acceptance criteria

證據路徑以 `core/` 為根；測試以 `go test -race ./...` 執行（2026-11-12，macOS arm64）。測試用的計畫種類在測試檔內（`plans/helpers_test.go` 的 `config.update`、`api/change_plans_test.go` 的 `setting.update`）；正式的計畫種類由各資源票註冊。

- [x] **IAM-005** 管理員可以批准特定高風險變更計畫。 — 完成條件：批准綁定內容摘要、目標、版本與期限；內容改變必須重新批准。 — 證據：`internal/plans/service_test.go` `TestApproveBindsDigestAndDeadline`（批准記下摘要與期限）、`TestDigestIsStableAndCoversContent`（同內容同摘要；參數或目標版本不同就不同）、`TestApproveWithAnotherDigestIsRefused`（送錯摘要回 `ChangedError`，計畫不變）、`TestTargetChangedBeforeApprovalInvalidatesPlan`（批准前目標從第 7 版變第 8 版，計畫失效並回前後差異，之後不能執行）、`TestSecretChangesAreMaskedButDigested`（只改機密也會讓摘要不同；機密在批准後輪替，執行被擋下）。
- [x] **ENG-005** 管理員可以批准一份明確變更計畫。 — 完成條件：批准綁定計畫摘要、資源版本及期限；內容變更後原批准失效。 — 證據：`TestTargetChangedAfterApprovalBlocksExecution`（批准後版本變了，執行回差異、計畫失效、沒有建立工作）、`TestExpiredPlanCannotBeApprovedOrRun`（過期後不能批准或執行，等待清單不再列出）、`TestDeadlineRaceAnswersExpired`（寫入時才到期也回已過期並寫稽核）；API：`internal/api/change_plans_test.go` `TestChangePlanAPIFlow`、`TestChangePlanAPIExpiry`。
- [x] 批准者要對計畫的每個目標都有該種類的權限；高風險計畫只有擁有者能批准；看不到其中任何目標的帳號拿到與不存在相同的 `404`；被拒的批准寫稽核。 — 證據：`TestApproverNeedsPermissionOnEveryTarget`（稽核者被拒並寫 `denied` 稽核）、`TestHighRiskNeedsOwner`（平台管理員與提出者都不能批准高風險計畫）、`TestPlanWithInvisibleTargetIsNotFound`（讀取、批准、拒絕、撤回、執行、建立都回與不存在相同的錯誤）、`TestUnregisteredKindDoesNotRevealHiddenPlan`（種類沒註冊時也先回 404）、API `TestChangePlanAPIPermissions`（訊息與不存在的計畫相同、列表不洩漏、`details.reason: owner-required`）。
- [x] 批准、拒絕、撤回、執行、失效的稽核紀錄與狀態變更在同一個交易；稽核寫不進去時狀態不變。 — 證據：`TestAuditInSameTransaction`（觸發器擋下稽核寫入，批准不生效；請求取消後狀態與稽核仍一致）、`TestConcurrentApprovalsOnlyOneWins`（8 個並行批准只有 1 個成功、1 筆稽核）、`TestExecuteRestoresApprovalWhenSubmitFails`（工作建不起來時退回已批准並寫 `failed` 稽核）。拒絕呼叫的稽核寫入失敗時記錯誤日誌（`iam.Service.RecordDenied`）。驗收審查另以探針測過拒絕、撤回、執行、失效、過期在稽核寫不進去時狀態都不變。
- [x] 計畫回應帶目標的實際節點／磁碟／環境名稱、設定差異（機密只寫「已變更」）與受影響服務，供 016.2 的畫面呈現 UI-006。 — 證據：`TestCreateDescribesTargetsChangesAndApproval`（`nodeName`、`environment`、`version`、差異前後值、受影響服務）、`TestSecretChangesAreMaskedButDigested`（機密變更只有 `secret: true`，值不在回應也不在資料庫）。
- [x] 註冊為「必須走計畫」的工作種類，直接 `POST /management/v1/jobs` 會被拒絕；計畫執行建立的工作帶批准者、計畫 ID 與摘要。 — 證據：API `TestJobsRefuseKindsThatNeedAPlan`（409 `CHANGE_PLAN_REQUIRED`，偽造的 `approver`、`changePlanId` 欄位被拒）、`TestExecuteSubmitsJobOnceWithPlanFields`（同 requestId 重送回同一個工作，換 requestId 被拒）、`TestExecuteRefusesTakenRequestIDBeforeClaiming`、`TestConcurrentExecuteWithSameRequestIDReplays`、`TestJobCreatedButNotRecordedStaysExecuted`（工作已建立、只是計畫沒記到工作 ID 時，計畫維持已執行，換 requestId 被拒，不會跑兩次）、`TestExecuteWithoutJobHandlerIsUnavailable`、`TestAutoApprovedJobSaysSo`；`internal/jobs/plan_test.go` `TestSubmitCarriesChangePlan`、`TestRequestHashWithoutPlanIsUnchanged`（沒有計畫的請求雜湊不變）；`TestChangePlanExecuteRespectsPlatformDegradation`（平台降級時執行被擋，計畫保持已批准）。
- [x] 兩人同時修改同一設定版本時，第二人收到差異與衝突，不覆蓋第一人：計畫執行前資源版本已變時回 `CHANGE_PLAN_CHANGED` 與前後差異；直接的版本條件寫入回 `412 VERSION_MISMATCH` 並附目前內容與衝突欄位。 — 證據：`TestChangePlanAPIConflictKeepsFirstChange`（`targets` 寫第 7 版變第 8 版、`current` 是第一人的值、沒有建立工作）、`TestUserUpdateConflictShowsCurrentContent`（帳號顯示名稱：`current`、`yours`、`conflictingFields`，第一人的值保留）、`TestStaleNodeAndRoleWritesShowCurrentContent`（節點名稱與群組、角色指派也一樣）、`TestUserConflictIgnoresTrimmedSpaces`。
