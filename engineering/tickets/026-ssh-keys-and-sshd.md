# 026 — 維運者可以管理 SSH 公鑰、sshd 設定與主機指紋

**Epic:** SSH 與終端機（`epic:ssh`）  
**User Story:** 維運者可以安全管理遠端登入  
**Milestone:** M1 單機主機管理  
**Blocked by:** 012 維運者可以執行需要高權限的固定動作，而 Agent 主程序維持低權限  
**規格章節:** 11｜SSH、金鑰、主機指紋與終端機  
**Issue:** [#26](https://github.com/HazelnutParadise/hazelminx/issues/26)  

## What it delivers

authorized_keys 管理（保留未接管項目）、金鑰產生／匯入與私鑰獨立加密、sshd Port／密碼／root 規則與語法檢查、known_hosts 與指紋變更核對、批次授權與撤銷、sshd 故障時經 Agent 修復。

## Acceptance criteria

- [ ] **SSH-001** 維運者可以為指定 Linux 帳號新增、標記、停用與移除公鑰。 — 完成條件：正確更新該帳號 authorized_keys，保留未接管項目與註解，避免重複金鑰。
- [ ] **SSH-002** 使用者可以產生或匯入自己需要的金鑰。 — 完成條件：私鑰不預設留在平台；需要伺服器使用的私鑰有獨立加密保存與權限。
- [ ] **SSH-003** 維運者可以調整 sshd 的 Port、密碼登入及 root 登入規則。 — 完成條件：套用前檢查語法；確認替代登入可用；設定失敗不停止原可用服務。
- [ ] **SSH-004** 維運者可以查看主機金鑰指紋與 known_hosts。 — 完成條件：主機指紋改變需明確核對，不自動接受以消除錯誤。
- [ ] **SSH-005** 管理員可以批次授權與撤銷指定節點公鑰。 — 完成條件：每台節點回報結果；離線節點顯示待處理，不能顯示全部已撤銷。
- [ ] **SSH-008** 維運者可以在 sshd 故障時透過仍可用的 Agent 修復。 — 完成條件：Agent 不依賴 SSH 常駐登入；面板清楚顯示使用的救援通道。
- [ ] 關密碼登入但沒有可用金鑰時阻擋或要求先驗證替代登入

## Acceptance tests（第 42 章）

- **T-035** 修改 sshd 成無效設定。 → 語法檢查阻擋，原連線方式可用。
- **T-036** 關密碼登入但沒有可用金鑰。 → 阻擋或要求先驗證替代登入，不能鎖死管理員。
