# 039.3 — 管理員可以在容器頁看到各引擎與環境狀態，並從未安裝畫面走完安裝流程

**Epic:** 容器引擎（`epic:containers`）  
**User Story:** 管理員可以管理容器引擎  
**Milestone:** M2 容器、Compose 與 GitHub  
**Parent:** 039  
**Blocked by:** 039.1, 039.2, 017 使用者可以在主導覽、全域搜尋與工作中心之間完成日常操作  
**規格章節:** 09｜節點加入、自動偵測與多節點、39｜跨功能流程：從按鈕到真正完成  
**Issue:** [#167](https://github.com/HazelnutParadise/hazelminx/issues/167)  

## What it delivers

畫板 `design/screens/Containers.dc.html` 與 `ContainersEmpty.dc.html` 的實作：每個引擎的狀態、版本、外掛與環境列表（擁有者、端點、模式），以及沒有容器引擎時的選擇卡、預檢、變更計畫與安裝流程。資料來自 039.1 與 039.2 的 API。

## Acceptance criteria

- [ ] NOD-003、NOD-004、ENV-001 的畫面：Docker、Podman、K3s 分開顯示，每個環境一列，擁有者與 socket 明示。
- [ ] 選到沒有容器引擎的節點時，Docker／Podman 頁顯示未安裝狀態：Docker、Podman 選擇卡與導向 Kubernetes 頁的 K3s 卡；選定後顯示預檢、變更計畫（套件、服務、網路與防火牆、daemon.json、群組、下載量與時間）與安裝流程（畫板 ContainersEmpty）。
- [ ] 未安裝、已停止、不相容、無權限、無回應各有不同的畫面狀態與下一步。
- [ ] `uninspected` 的範圍顯示在頁面上，不讓「沒列出」看起來像「沒有」。

## Delivery record

需求 ID → 變更 → 測試環境 → 正常與失敗案例 → 證據 → 未驗證部分，依規格第 46.4 節填寫於 PR。
