# 127 — 管理員可以讓成員用公司帳號登入，本機登入與救援不受影響

**Epic:** 身分與存取（`epic:iam`）  
**User Story:** 擁有者可以控制誰能做什麼  
**Milestone:** M1 單機主機管理  
**Blocked by:** 014 使用者可以用二次驗證登入並管理自己的工作階段, 015 擁有者可以管理使用者、角色、資源範圍與有期限的 API Token, 011 管理員可以安全保存機密，且主金鑰可輪替並驗證舊備份仍可解密  
**規格章節:** 增補 10｜用公司帳號登入（OIDC）（第 58 章）、05｜誰能用、誰能做什麼  
**Issue:** [#179](https://github.com/HazelnutParadise/hazelminx/issues/179)  

## What it delivers

OpenID Connect 授權碼流程加 PKCE 的公司帳號登入：平台設定裡的設定與測試登入、邀請與第一次登入的綁定、群組到角色的對應與預覽、二次驗證與工作階段期限、登入服務出問題時的行為，以及登入頁的按鈕。IAM-010 從票 015 移到這張票。增補 10 目前是草案，動工前要先由使用者核定。

## Acceptance criteria

- [ ] **IAM-010** 管理員可以選配外部身分登入，仍保留本機救援帳號。 — 完成條件：外部登入服務故障時，不會永久失去管理能力；角色對應有預覽。
- [ ] **OID-001**（增補 10）擁有者可以用發行者網址、用戶端 ID 與密鑰設定公司帳號登入。 — 完成條件：端點由探索文件讀出；密鑰存機密庫且不回傳；回呼網址可複製；連不到時說明是 DNS、TLS 或逾時。
- [ ] **OID-002** 啟用前必須成功測試登入一次。 — 完成條件：測試結果顯示穩定識別碼、email、是否已驗證、群組與會得到的角色；沒有成功測試不能啟用。
- [ ] **OID-003** 被邀請的人第一次用公司帳號登入時完成綁定，之後只認穩定識別碼。 — 完成條件：email 相同且已驗證才綁定；綁定後對方改 email 仍可登入；同一 email 的另一個識別碼不能登入成他。
- [ ] **OID-004** 沒被加入的公司帳號不會得到平台帳號。 — 完成條件：自動建立預設關閉；打開時必須設定允許的網域與角色對應；不符合的人看到說明，不建立帳號。
- [ ] **OID-005** 群組可以對應到角色與資源範圍，並有預覽。 — 完成條件：多條取聯集；不能對應出擁有者；儲存前列出誰的權限會變；每次登入重新計算。
- [ ] **OID-006** 二次驗證預設由平台做，可以改成由公司帳號負責。 — 完成條件：改成由公司帳號負責時要求 `amr` 或 `acr` 符合設定；不符合時退回平台的二次驗證。
- [ ] **OID-007** 公司帳號登入的工作階段有最長期限。 — 完成條件：預設 12 小時、可設 1～24 小時；到期要重新走登入服務；平台停權立即生效。
- [ ] **OID-008** 登入服務出問題時，本機登入與救援不受影響。 — 完成條件：登入頁永遠有本機表單；最後一個本機擁有者不能被刪除、停權或改成只用公司帳號；錯誤原因進稽核、不給未登入者看。
- [ ] **OID-009** 登入流程驗證 `state`、`nonce`、PKCE、回呼網址與 ID Token。 — 完成條件：重放、換掉 `state`、錯的 `aud` 或 `iss`、過期、`none` 或對稱式簽章、任意轉址都被拒絕並記錄。
- [ ] **OID-010** 改發行者網址前列出受影響的帳號。 — 完成條件：確認後才儲存；舊綁定保留但不能登入，直到重新綁定。
- [ ] 平台設定頁「公司帳號登入」區塊、測試登入結果與角色對應預覽有畫板，登入頁按鈕顯示設定的名稱；沒設定時不顯示按鈕。

## Acceptance tests

- **T-276** 填入發行者網址，但控制中心解析不到那個網域。 → 設定頁寫「解析不到 login.example.tw」，不能儲存成啟用。
- **T-277** 設定完成、還沒測試登入就按啟用。 → 被擋下，提示先測試登入。
- **T-278** 邀請 mei@example.tw（公司帳號），登入服務回傳同一個 email 且已驗證。 → 綁定成功並登入；稽核記一筆綁定。
- **T-279** 同上，但登入服務回傳 `email_verified: false`。 → 不綁定、不登入，說明 email 尚未驗證。
- **T-280** mei 在公司改了 email 後再登入。 → 仍然登入成原本的平台帳號。
- **T-281** 沒被邀請的 bob@example.tw 用公司帳號登入，自動建立是關的。 → 看到說明，沒有新帳號。
- **T-282** 新增對應 `admins` → 擁有者。 → 不能儲存，說明擁有者只能手動指派。
- **T-283** 登入服務停機，使用者打開登入頁。 → 公司帳號按鈕下方寫目前不能用；本機帳號照常登入。
- **T-284** 把回呼請求的 `state` 換成另一次登入的值，或重送同一個回呼。 → 兩者都被拒絕並寫進稽核。
- **T-285** 嘗試停權最後一個本機擁有者。 → 被擋下，說明至少要保留一個本機擁有者。

## Notes

- 測試不能連真的登入服務；用可以替換的假發行者（探索文件、JWKS、權杖端點）。票 047.1 的 GitHub 授權來回（`core/internal/github/authorize.go`）是同一種流程的現成做法：`state` 只存雜湊、綁定工作階段、只能用一次。
- 畫板：`design/screens/OidcSetup.dc.html`（設定、測試登入、誰可以登入、群組對應與權限變化預覽、二次驗證與登入期限，以及六個狀態）。登入頁 `Login.dc.html` 的按鈕改成顯示設定的名稱。還沒畫：邀請時選「公司帳號」之後對方第一次登入的綁定過程、自動建立帳號打開時的表單。
