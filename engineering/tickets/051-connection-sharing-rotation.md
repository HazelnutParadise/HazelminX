# 051 — 管理員可以分開授權連線的查看、瀏覽、使用與管理，並安全輪替、撤銷與斷開

**Epic:** GitHub 來源（`epic:github`）  
**User Story:** 使用者可以從 GitHub 部署  
**Milestone:** M2 容器、Compose 與 GitHub  
**Blocked by:** 049 專案管理員可以從 GitHub 以固定 commit 隔離抓取、建置並部署，手動 URL／PAT／SSH 模式照常可用, 016 管理員可以預覽並批准高風險變更計畫，內容改變時原批准失效  
**規格章節:** 15｜完整 Compose、GitHub 與環境變數、35｜平台資料儲存、機密與復原包、39｜跨功能流程：從按鈕到真正完成  
**Issue:** [#51](https://github.com/HazelnutParadise/hazelminx/issues/51)  

## What it delivers

四項可分開授權能力、個人授權與組織機器授權區分、授權健康與重新授權入口、輪替計畫、權限變更後快取失效、Repo 改名／移轉／重建處理、斷開前依賴預覽、稽核、個別憑證匯入、還原後重新核對、停權後工作處理、重新授權保留草稿、連線不作他用。

## Acceptance criteria

- [ ] **GIT-012** 管理員可以分開授予查看、瀏覽、使用與管理連線的權限。 — 完成條件：未授權者無法藉 API、搜尋、快取、匯出、事件或猜 ID 得知私人資源及秘密。
- [ ] **GIT-017** 管理員可以分辨個人授權與組織機器授權。 — 完成條件：個人清單使用共同權限；組織安裝共享需明確批准，離職／停權不混同全組織撤銷。
- [ ] **GIT-021** 管理員可以看到授權健康與重新授權入口。 — 完成條件：過期、撤銷、暫停、組織批准、SSO、限流、斷網及未知原因分開顯示，不偽造根因。
- [ ] **GIT-022** 管理員可以一次輪替連線，供依賴專案繼續使用。 — 完成條件：先檢查新授權涵蓋範圍；使用穩定連線 ID，歷史部署保留當時秘密版本而不保存明文。
- [ ] **GIT-023** 系統可以在權限改變後使相關快取失效。 — 完成條件：已收到撤銷事件即處理；新抓取與副作用前再次驗權；回傳清單依目前平台權限過濾。
- [ ] **GIT-024** 使用者可以安全處理 Repo 改名、移轉、刪除與重建。 — 完成條件：同名不同 ID 不自動接管；移轉擁有者暫停自動部署並要求重新確認來源。
- [ ] **GIT-026** 管理員可以知道共享授權及程式碼的實際風險。 — 完成條件：UI 說明可部署者可能接觸程式碼與產物；仍依原規則阻擋新特權掛載及正式秘密外流。
- [ ] **GIT-028** 使用者可以在 GitHub 暫時失聯時保有現有服務。 — 完成條件：既有網站不停止；新抓取清楚等待／失敗，舊清單有時間標示，不以舊權限冒充已驗證。
- [ ] **GIT-029** 管理員可以在移除連線前預覽依賴與撤銷範圍。 — 完成條件：列出專案、Hook 與排程；本機移除、遠端撤銷及暫時無法撤銷分開回報，不誤刪共用資源。
- [ ] **GIT-030** 稽核者可以追蹤帳號連接與部署來源的變更。 — 完成條件：記錄操作者、授權 ID、Repo ID、批准及版本；不記原始 Token／驗證碼，歷史不因斷線被刪。
- [ ] **GIT-032** 管理員可以匯入既有專案的個別憑證。 — 完成條件：預設保留原範圍；轉成共用連線先預覽批准；不從兩份相同 Token 推斷可跨人共享。
- [ ] **GIT-033** 管理員可以還原平台後重新核對 GitHub 連線。 — 完成條件：還原的秘密先驗證有效性，Hook 與自動部署預設待確認；不重播舊 push，也不誤信舊授權。
- [ ] **GIT-035** 專案管理員可以變更部署所用的連線。 — 完成條件：先查同 Repo 的實際讀取與來源權限、列受影響環境，再批准切換；既有服務不重建。
- [ ] **GIT-036** 管理員可以決定停權後已排隊或已開始工作如何處理。 — 完成條件：未開始與新副作用被阻擋；不可中斷步驟按安全點處理，歷史內容不被假稱已遠端抹除。
- [ ] **GIT-037** 使用者可以保留已填的部署設定並完成重新授權。 — 完成條件：錯誤或取消不丟 `.env` 參照、Compose 路徑及節點選擇；不把秘密留在網址或瀏覽器持久儲存。
- [ ] **GIT-039** 管理員可以使用來源授權而不讓它變成其他用途的萬用鑰匙。 — 完成條件：GitHub 連線、GHCR 映像登入、雲端備份、平台更新授權分開；沒有批准不共用永久秘密。
- [ ] **GIT-040** 維護者可以以真實 GitHub 測試驗收多帳號部署。 — 完成條件：以經授權的個人／組織／私人 Repo 驗收正常與撤銷流程，沒有實際測試的組合保持未驗證。
- [ ] 未分享者無法藉 API、搜尋、快取、匯出、事件或猜 ID 得知私人資源
- [ ] 真實 GitHub 個人／組織測試環境執行主要流程並留下遮罩證據

## Acceptance tests（第 42 章）

- **GH-T11** 未被分享的人猜連線 ID、Repo ID、快取查詢與事件入口。 → 清單、名稱、檔案、總數、下載與事件均不洩漏；後端拒絕。
- **GH-T16** App 能讀 A、B，使用者只能讀 B、C，再測組織明確共享 A。 → 個人模式只有 B；共享 A 必須走獨立批准與平台權限，不偷借安裝權限。
- **GH-T20** 組織待批准、SSO 未完成、403／404、斷網及 App 暫停。 → 按證據顯示已知或未知原因，不一律說 Repo 不存在，不擅自改權限。
- **GH-T21** 輪替一份被多個專案使用的 Token，新的少一個 Repo 權限。 → 切換前列出受影響專案，未批准不破壞舊綁定；符合範圍者不需改 Compose。
- **GH-T22** Repo 權限撤銷、平台使用者停權，舊瀏覽器仍有清單。 → 快取與回應驗權更新，新的抓取／副作用被阻擋；現有網站繼續服務。
- **GH-T23** Repo 改名、移轉組織，再建立同名但不同 ID 的 Repo。 → 同 ID 改名可追溯；移轉暫停確認；同名新 Repo 不接續原部署。
- **GH-T25** 共享部署權給另一人，Repo commit 新增 root 掛載或秘密外送。 → 顯示共享內容風險；部署計畫依原安全規則阻擋越權變更。
- **GH-T27** GitHub 故障時重新整理清單、要求新部署。 → 可見歷史標過期；新操作等待／失敗有證據，不停止既有服務。
- **GH-T28** 移除被多專案共用的連線，GitHub 撤銷 API 暫時不可達。 → 先列依賴，不誤刪共用 Hook；本機與遠端狀態分開，保留待處理報告。
- **GH-T29** 管理 UI 只有內網可達，GitHub 無法送入 Webhook。 → 區分瀏覽器回呼與事件入口；PAT／polling 可用，不自動公開管理頁。
- **GH-T30** 匯入原有每專案個別 Token，再嘗試合併成共享連線。 → 原範圍不變；共享需要批准，不因秘密相同就跨使用者共享。
- **GH-T31** 以舊平台備份在新 Core 還原，內含過期 Token 與舊 push。 → 重新驗權、回呼與 Hook 待確認，不重播歷史部署；秘密仍受加密保護。
- **GH-T32** PAT 連線切換計畫產生後，來源權限、Repo 身分或平台設定改變。 → 原批准失效或重新預檢，實際部署記錄同一來源與有效授權版本。
- **GH-T33** 撤銷個人授權時一個工作排隊、一個正在不可中斷資料變更。 → 排隊停止；進行中到安全點處理，不強殺資料庫；組織機器授權依明確政策。
- **GH-T34** 以已授權真實 GitHub 個人／組織測試環境執行上述主要流程。 → 留遮罩證據、版本與結果；未取得測試條件者標未驗證，不以模擬取代全部實測。
