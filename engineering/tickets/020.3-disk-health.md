# 020.3 — 使用者可以看磁碟健康與 SMART，讀不到時明示原因

**Epic:** 主機管理（`epic:host`）  
**User Story:** 維運者可以掌握主機狀態  
**Milestone:** M1 單機主機管理  
**Parent:** 020  
**Blocked by:** 020.1 Agent 回報主機資訊與資源指標，Core 保存有解析度的歷史並以 API 提供, 012 系統以 Rust 高權限執行器執行宿主機變更，只接受固定動作與結構化參數  
**規格章節:** 29｜監控、GPU、事件與告警  
**Issue:** [#157](https://github.com/HazelnutParadise/hazelminx/issues/157)  

## What it delivers

SMART 與 NVMe 健康要 root 才讀得到，經高權限執行器的唯讀動作（smartctl／nvme）讀取；結果併入 020.1 的磁碟資訊。磁碟延遲、I/O、容量與分類已在 020.1 交付。

## Acceptance criteria

- [ ] **MON-003**（健康）使用者可以看磁碟健康。 — 完成條件：區分實體磁碟、RAID、虛擬碟與網路掛載；USB bridge 不提供 SMART 時明示。
- [ ] USB bridge 不提供 SMART 時明示
- [ ] 溫度清單加入 smartctl／nvme 與 IPMI 讀得到的感測器，標來源與各自的臨界溫度。
- [ ] （票 030.1 交過來）讀到的健康結果填進 `GET /management/v1/nodes/{id}/storage` 每顆磁碟的 `devices[].health`（目前一律是 `notCollected`），狀態加上 `ok`、`warning`、`failing`、`unsupported`，並附每顆磁碟的溫度；讀不到時寫原因，不顯示健康。
