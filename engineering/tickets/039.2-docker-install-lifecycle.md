# 039.2 — 管理員可以在預覽與批准後，由工作透過高權限執行器安裝、啟停與移除 Docker

**Epic:** 容器引擎（`epic:containers`）  
**User Story:** 管理員可以管理容器引擎  
**Milestone:** M2 容器、Compose 與 GitHub  
**Parent:** 039  
**Blocked by:** 039.1, 016 管理員可以預覽並批准高風險變更計畫，內容改變時原批准失效, 113 平台對主機的每個變更都寫進變更帳本，並在安裝時記錄安裝前快照  
**規格章節:** 09｜節點加入、自動偵測與多節點、39｜跨功能流程：從按鈕到真正完成、增補 07 第 55.1 節  
**Issue:** [#166](https://github.com/HazelnutParadise/hazelminx/issues/166)  

## What it delivers

安裝 Docker 是一個 change plan 種類（票 016.1 的 `core/internal/plans`）：預檢（ENV-006 衝突、既有引擎、套件來源、磁碟）、變更計畫（套件、服務、網路與防火牆、daemon.json、群組、下載量與時間）、批准後建立工作，步驟經高權限執行器的固定動作執行，每個變更寫進主機變更帳本（擁有權：平台安裝），並定義移除方式。安裝後驗證 Engine、Compose、Buildx 與 socket 權限，再以 039.1 的偵測確認。已安裝引擎的停止、啟動、重新安裝、移除也在這裡。

## Acceptance criteria

- [ ] **INS-008** 管理員可以在 Docker、Podman 或 K8s 頁面安裝缺少的元件。 — 完成條件：顯示未安裝、已停止、不相容與無權限的不同狀態；不把全部問題當成沒安裝。
- [ ] **ENV-006** 安裝或建立環境前檢查與既有環境的 Port、網段、cgroup 驅動、防火牆後端、containerd 衝突，列出佔用者，不自動停用任一方。
- [ ] 安裝計畫走 change plan：預覽內容改變時原批准失效；批准後才建立工作，回 `202` 與工作 ID。
- [ ] 執行器新增的安裝動作只接受固定參數，定義帳本內容（變更前後狀態、擁有權）與移除方式；沒寫帳本就拒絕。
- [ ] 安裝後驗證 Engine、Compose、Buildx 與 Socket 權限。
- [ ] 已有 K3s 的 containerd 不自動移除。
- [ ] 失敗時不自動關閉防火牆、停掉另一個引擎或把 Socket 改成所有人可寫。
- [ ] 已安裝的引擎可以停止、啟動、重新安裝、移除；移除先列出受影響容器與資料目錄，選擇保留到哪一層（只停用／移除套件保留資料／連資料一併移除，後者先備份）並輸入名稱確認。
