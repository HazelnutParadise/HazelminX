# 016.2 — 使用者修改設定前可以在畫面上看差異、受影響服務與預檢，並在工作中心批准或拒絕計畫

**Epic:** 身分與存取（`epic:iam`）  
**User Story:** 使用者可以安全執行長時間操作  
**Milestone:** M1 單機主機管理  
**Parent:** 016  
**Blocked by:** 016.1 管理員可以用 API 產生、批准並執行變更計畫，內容或資源版本改變時原批准失效, 017 使用者可以在主導覽、全域搜尋與工作中心之間完成日常操作  
**規格章節:** 07｜介面與操作體驗、33｜工作引擎：按一次按鈕後，如何可靠完成  
**Issue:** 待建立  

## What it delivers

變更計畫的畫面：計畫頁（變更、目標、受影響服務、預檢、差異、替換方式，畫板 `design/screens/DeployCheck.dc.html`）、批准確認對話框（寫出實際目標名稱並要求輸入環境名稱，畫板 `DeployConfirm.dc.html`）、工作中心的「等待批准」清單（畫板 `WorkCenter.dc.html`）、內容改變後原批准失效與版本衝突的畫面（畫板 `ChangeSafety.dc.html`）。資料全部來自 016.1 的 `/management/v1/change-plans`。

## Acceptance criteria

- [ ] **UI-006** 使用者修改設定前可看差異與受影響服務。 — 完成條件：高風險操作顯示實際節點／磁碟／環境名稱，不能只有「確定嗎」。
- [ ] 兩人同時修改同一設定版本時第二人看到差異與衝突，不覆蓋第一人：畫面並列「你的版本」與「目前的版本」，提供放棄、載入目前版本再改；計畫失效時寫出哪個目標從哪一版變成哪一版。
- [ ] 工作中心列出等待批准的計畫，只列這個帳號看得到全部目標的計畫；過期的計畫不在等待清單。
- [ ] 高風險計畫在批准確認對話框寫出每一項高風險與警告，需要擁有者批准時，非擁有者看到停用的按鈕與原因。
