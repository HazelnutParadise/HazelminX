# 078 — 使用者可以備份應用、資料庫、目錄與平台設定，含一致性、多目的地、保留與加密

**Epic:** 備份與還原（`epic:backup`）  
**User Story:** 管理員可以備份並真正還原  
**Milestone:** M4 資料庫、AI、備份與監控  
**Blocked by:** 077 管理員可以建立本機、S3、SFTP、WebDAV、雲端硬碟與 NAS 備份目的地並測試讀寫, 069 管理員可以安裝或接管資料庫服務，管理帳號、連線、健康與對外開放, 046 管理員可以查看部署版本、三方比較並回到相容舊版  
**規格章節:** 27｜備份內容、一致性、保留與還原  
**Issue:** [#77](https://github.com/HazelnutParadise/hazelminx/issues/77)  

## What it delivers

備份種類與排除預覽、一致性方法、共同時間點、多目的地各自結果、增量／壓縮／加密／保留、完整性分級、金鑰復原包、資源限制、失敗後解除停寫、不可變副本、可攜匯出、manifest 防竄改、網站備份關係。

## Acceptance criteria

- [ ] **BKR-001** 使用者可以選應用、資料庫、目錄、平台設定與支援的快照備份。 — 完成條件：備份清單列出包含與排除項目，排除規則可預覽。
- [ ] **BKR-002** 管理員可以選擇一致性方法。 — 完成條件：運行中資料庫不能單純複製 Volume 就標成一致；需要 dump、備份協定、協調快照或停寫。
- [ ] **BKR-003** 管理員可以協調應用檔案與資料庫的共同時間點。 — 完成條件：若做不到共同時間點，備份標為個別一致而非整套一致；明示還原風險。
- [ ] **BKR-004** 使用者可以將一份備份傳至多個目的地。 — 完成條件：每個目的地各自有結果；預先指定必需與選配副本，不能一個成功就隱藏其他失敗。
- [ ] **BKR-005** 管理員可以設定增量、壓縮、加密與保留政策。 — 完成條件：增量鏈相依正確；刪除前確認仍有可用復原鏈；不把壓縮當加密。
- [ ] **BKR-006** 管理員可以設定保留份數、天數與長期保留點。 — 完成條件：只清理完成且依政策可清理者；新備份失敗不刪掉最後一份可還原副本。
- [ ] **BKR-007** 管理員可以檢查備份完整性。 — 完成條件：分成已產生、已傳輸、校驗通過、還原測試通過，不混為一個成功標記。
- [ ] **BKR-011** 管理員可以管理備份解密資料。 — 完成條件：主機全毀後以獨立復原包可解密；金鑰不只存在被備份的同一資料庫裡。
- [ ] **BKR-012** 管理員可以限制備份使用的 CPU、I/O、頻寬與暫存空間。 — 完成條件：不因備份把正式資料庫壓垮；空間不足在可預測階段停止並告警。
- [ ] **BKR-013** 管理員可以查看失敗後是否已解除停寫或維護狀態。 — 完成條件：即使備份失敗，必要的恢復服務步驟仍執行並回報結果。
- [ ] **BKR-014** 管理員可以設定不可變與異地副本。 — 完成條件：依目的地實際能力驗證；不支援鎖定者不顯示防竄改保證。
- [ ] **BKR-015** 使用者可以下載與攜出備份及其說明。 — 完成條件：備份格式、版本、清單、校驗與必要還原步驟可攜，不綁定雲端帳號登入。
- [ ] **DAT-003** 管理員可以備份平台設定與秘密。 — 完成條件：備份包含足夠版本與索引；復原金鑰另存，能在乾淨主機成功還原。
- [ ] **WEB-012** 使用者可以備份網站檔案、設定、憑證與相關資料庫。 — 完成條件：記錄相互關係與還原順序；不把只備份 HTML 當成完整動態網站備份。
- [ ] 新備份失敗不刪最後一份可還原副本與增量基底
- [ ] （票 030.1 交過來）**STO-010** 的備份暫存需求：每個備份工作的暫存目錄所在檔案系統，容量告警要把下一次備份需要的暫存空間算進去（`GET /management/v1/nodes/{id}/storage` 的 `backupStaging` 從 `notApplicable` 改成實際檢查），空間不夠時在備份開始前告警；暫存目錄在用量分類裡只算「備份暫存」（`hoststorage`／Agent `storage::usage::ROOTS` 加上這個目錄）。

## Acceptance tests（第 42 章）

- **T-107** 一份備份傳兩個必要目的地，其中一個失敗。 → 整體非完整成功，分別顯示與可重試。
- **T-108** 備份時資料庫持續寫入。 → 使用一致性方法，還原後驗證資料關係。
- **T-109** 新備份失敗，但保留政策準備清舊檔。 → 不刪最後一份可還原備份與必要增量基底。
- **T-110** 有加密備份但沒有復原金鑰。 → 明確不可還原，不提供虛假解密或成功。
