# 030.3 — 管理員可以管理快照與檔案備份，兩者清楚區分

**Epic:** 磁碟與儲存（`epic:storage`）  
**User Story:** 維運者可以管理儲存  
**Milestone:** M1 單機主機管理  
**Parent:** 030  
**Blocked by:** 030.1 Agent 回報磁碟、分割區、掛載與用量分類，Core 保存並以 API 提供容量告警, 078 使用者可以備份應用、資料庫、目錄與平台設定，含一致性、多目的地、保留與加密  
**規格章節:** 13｜磁碟、儲存與資料位置、27｜備份內容、一致性、保留與還原  
**Issue:** 待建立  

## What it delivers

依檔案系統的實際能力（Btrfs、ZFS、LVM thin）提供快照，和 078 的檔案備份分開列出與管理。

## Acceptance criteria

- [ ] **STO-011** 管理員可以管理快照與檔案備份，但清楚區分。 — 完成條件：快照不被宣稱為異地備份；沒有快照能力的檔案系統不顯示已完成快照。

## Delivery record

需求 ID → 變更 → 測試環境 → 正常與失敗案例 → 證據 → 未驗證部分，依規格第 46.4 節填寫於 PR。

## Notes

- 030.1 的 `host_storage` 已帶每個掛載的檔案系統類型（`mounts[].fsType`）與 device-mapper 的上下層（`devices[].holders`），判斷有沒有快照能力可以從這裡開始；LVM thin pool 要另外讀 `lvs`，需要 root，走高權限執行器。
- 快照的建立與刪除是宿主機變更，要寫主機變更帳本並定義移除方式。
