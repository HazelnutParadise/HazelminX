# 118 — 有密碼的攻擊者不能靠持續送錯的第二驗證碼把帳號擁有者擋在外面

**Epic:** 身分與存取（`epic:iam`）
**User Story:** 帳號擁有者在被攻擊時仍然可以用第二驗證登入
**Milestone:** M3 網站入口與安全防護
**Blocked by:** 065 管理員可以為每個入口設定可信代理模式，Cloudflare Tunnel 流量取得正確訪客 IP
**規格章節:** 無（來自 2026-11-11 之前記在 AGENTS.md 的後續事項）
**Issue:** [#136](https://github.com/HazelnutParadise/hazelminx/issues/136)

## What it delivers

第二步的失敗計數（`#2fa:`）目前按帳號計、不分來源，持有密碼的攻擊者可以讓第二步一直處於冷卻，與 IAM-012 衝突。使用者已決定票 014 先合併、另外修。候選改法有兩個：接上可信代理後改成「帳號＋來源」計數，再加較高的帳號總上限；或讓 Passkey 成功不受這個計數影響。動工時先選定做法並寫成決策紀錄。

## Acceptance criteria

- [ ] 選定的做法寫進 `/engineering/decisions/`。
- [ ] 攻擊者從一個來源持續送錯的第二驗證碼時，帳號擁有者從另一個來源仍然可以完成第二步登入。
- [ ] 單一來源的猜測次數仍然受冷卻限制，帳號總嘗試數有上限。
- [ ] 來源位址只採用可信代理送來的值（票 065）。
