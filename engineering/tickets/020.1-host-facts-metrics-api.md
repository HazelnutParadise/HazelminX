# 020.1 — Agent 回報主機資訊與資源指標，Core 保存有解析度的歷史並以 API 提供

**Epic:** 主機管理（`epic:host`）  
**User Story:** 維運者可以掌握主機狀態  
**Milestone:** M1 單機主機管理  
**Parent:** 020  
**Blocked by:** 019 管理員可以用一次性註冊碼加入節點，並看到離線、過期、維護與撤銷狀態  
**規格章節:** 10｜主機、套件、服務與網路、29｜監控、GPU、事件與告警、38｜效能、資源與可觀測品質要求、增補 03 51.3「ROB-009 指標」  
**Issue:** [#155](https://github.com/HazelnutParadise/hazelminx/issues/155)  

## What it delivers

Agent 每 10 秒從 Linux 的 `/proc`、`/sys` 與 `statvfs` 收集一次指標，連線後與變動時回報主機資訊；Core 收下、保存、標出缺口，並以 `/management/v1/nodes/{id}/host`、`/metrics/latest`、`/metrics/history` 提供。通道訊息與能力 `host.metrics` v1 寫在 `engineering/contracts/README.md`。畫面在 020.4。

保存規則：

- 原始樣本：解析度是 Agent 的採樣間隔（預設 10 秒），保留 48 小時。
- 5 分鐘彙總：每條序列的平均、最小、最大與樣本數，保留 90 天。
- 缺口：相鄰兩點相隔超過兩個採樣間隔就是缺口，API 以 `gaps` 列出，不補點、不補零。Agent 暫存滿了丟掉的樣本，以 `droppedSamples` 回報並列成缺口。

## Acceptance criteria

- [ ] **SYS-001** 維運者可以查看 OS、核心、架構、開機時間、時區與時間同步狀態。 — 完成條件：來源與更新時間可查；未知欄位顯示未提供，不填零或猜測。
- [ ] **MON-001** 使用者可以看 CPU 每核心、記憶體、swap、負載、磁碟與網路。 — 完成條件：指標單位、採樣時間與來源固定；快取記憶體不誤算成完全不可用。
- [ ] **MON-005**（後端）使用者可以查看即時與歷史趨勢。 — 完成條件：缺少資料保留缺口；歷史彙總標示解析度，不用補零製造跌幅。
- [ ] **MON-003**（延遲、I/O、容量與分類）磁碟回報延遲、IOPS、吞吐、使用率與容量，並區分實體磁碟、RAID、虛擬碟、網路掛載。健康與 SMART 在 020.3。
- [ ] **ROB-009**（指標）主機 PID 使用率（分母 `pid_max`）、檔案描述元（分母 `file-max`）、記憶體壓力（PSI `some avg60`，不支援標「不支援」、停用標「未啟用」）、inode（沒有固定總數的檔案系統標「不適用」）、唯讀掛載都有回報。告警在 081，容器的部分在 040。
- [ ] 缺值以 `null` 回報並在 API 標未提供，不填零；歷史缺口保留缺口。
- [ ] 溫度列出 hwmon 與 thermal zone 讀得到的每個感測器，附各自的臨界溫度與來源；smartctl／nvme／NVML／IPMI 來源在 020.2、020.3。
- [ ] 監控迴圈加入後，依 [`agent/PERFORMANCE.md`](/agent/PERFORMANCE.md)「重新量測」在 2 核心 Linux 上量 `hazelminx-agent` 至少兩輪：每 10 秒監控一次時，空閒平均 CPU 低於單核心 2%、常駐記憶體低於 200 MiB，結果與受測 commit 記錄進 `agent/PERFORMANCE.md`。
