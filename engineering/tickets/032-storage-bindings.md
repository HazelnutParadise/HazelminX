# 032 — 管理員可以設定資料位置並以裝置身分綁定，掛錯磁碟時服務不啟動

**Epic:** 磁碟與儲存（`epic:storage`）  
**User Story:** 維運者可以管理儲存  
**Milestone:** M1 單機主機管理  
**Blocked by:** 031 維運者可以分割、格式化、掛載磁碟並管理 LVM、RAID、LUKS 與網路儲存, 008 使用者可以提交工作後關閉頁面，之後仍能查到進度、證據與結果  
**規格章節:** 13｜磁碟、儲存與資料位置  
**Issue:** [#32](https://github.com/HazelnutParadise/hazelminx/issues/32)  

## What it delivers

每節點應用資料預設位置、每服務／掛載資料位置、裝置穩定識別綁定、受保護工作負載的啟動前置檢查（含掛載前置的主機服務）、磁碟使用者查詢。

## Acceptance criteria

- [ ] **STO-005** 管理員可以設定每個節點的應用資料預設位置。 — 完成條件：與面板安裝目錄分離；不同節點可使用不同磁碟。
- [ ] **STO-006** 應用管理員可以指定每個服務與每個掛載的資料位置。 — 完成條件：可選現有資料夾、受管理 Volume 或合適的網路儲存；安裝腳本同步使用實際路徑。
- [ ] **STO-007** 管理員可以用裝置穩定識別資訊綁定重要資料。 — 完成條件：換插槽後仍找得到；掛錯磁碟、UUID 衝突或裝置缺席會阻止依賴服務啟動。
- [ ] **STO-008** 維運者可以查磁碟被哪些服務、容器與程序使用。 — 完成條件：顯示已確認使用者與未知風險；不能宣稱已發現所有可能的外部使用者。
- [ ] 指定資料碟未掛載重開機後，依賴容器不會在系統碟建空資料
- [ ] 既有 restart: always 未經批准不偷改，也不標成已具備保護

## Acceptance tests（第 42 章）

- **T-046** 指定資料碟未掛載，重新開機。 → 依賴容器不能藉 Docker restart policy 在系統碟建空資料。
- **T-047** 用另一顆磁碟掛到相同路徑。 → 裝置身分不同，拒絕啟動受保護服務。
