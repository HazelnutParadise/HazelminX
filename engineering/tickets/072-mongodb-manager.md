# 072 — 使用者可以管理 MongoDB 實例、集合、文件與索引

**Epic:** 資料庫（`epic:database`）  
**User Story:** 使用者可以在平台內管理資料庫  
**Milestone:** M4 資料庫、AI、備份與監控  
**Blocked by:** 069 管理員可以安裝或接管資料庫服務，管理帳號、連線、健康與對外開放  
**規格章節:** 24｜資料庫管理中心  
**Issue:** [#71](https://github.com/HazelnutParadise/hazelminx/issues/71)  

## What it delivers

基線 MongoDB 能力、文件瀏覽與編輯（型別保留）、索引預覽、備份還原、不支援能力明示。

## Acceptance criteria

- [ ] **MDB-001** 管理員可以管理基線 MongoDB 實例與連線。 — 完成條件：保留原有安裝、設定、帳號、備份與狀態能力，TLS 與認證來源清楚。
- [ ] **MDB-002** 使用者可以瀏覽授權資料庫、集合與文件。 — 完成條件：分頁與大小上限有效，ObjectId、日期、二進位等型別不被普通 JSON 誤改。
- [ ] **MDB-003** 授權使用者可以新增、編輯及刪除指定文件。 — 完成條件：使用可靠識別、併發衝突檢查與範圍限制，不意外更新整個集合。
- [ ] **MDB-004** 管理員可以查閱索引及基線提供的結構管理。 — 完成條件：變更有預覽與影響；新建高成本索引不阻塞管理介面。
- [ ] **MDB-005** 管理員可以備份及還原 MongoDB。 — 完成條件：依版本與拓樸選一致性方法，還原測試含必要帳號與索引。
- [ ] **MDB-006** 使用者可以辨識實例或驅動不支援的能力。 — 完成條件：顯示實際限制，不以空資料或假成功取代。

## Acceptance tests（第 42 章）

- **T-129** MongoDB 文件含 ObjectId、日期與二進位內容。 → 瀏覽、修改、匯出及還原保留正確型別。

## Delivery record

需求 ID → 變更 → 測試環境 → 正常與失敗案例 → 證據 → 未驗證部分，依規格第 46.4 節填寫於 PR。
