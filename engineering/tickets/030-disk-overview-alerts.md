# 030 — 維運者可以查看磁碟、分割區、檔案系統、健康與容量告警

**Epic:** 磁碟與儲存（`epic:storage`）  
**User Story:** 維運者可以管理儲存  
**Milestone:** M1 單機主機管理  
**Blocked by:** 019 管理員可以用一次性註冊碼加入節點，並看到離線、過期、維護與撤銷狀態, 020 維運者可以查看主機資訊、資源指標與歷史趨勢  
**規格章節:** 13｜磁碟、儲存與資料位置  
**Issue:** [#30](https://github.com/HazelnutParadise/hazelminx/issues/30)  

## What it delivers

磁碟與分割區清單、容量與 inode、SMART／溫度（不支援時明示）、快照與檔案備份的區分、容量與健康告警（含備份暫存需求）。

2026-11-14 拆成三張子票。驗收條件由子票交付，子票都完成時這張票才完成：

| 子票 | 交付 | 擁有的需求 |
|---|---|---|
| 030.1 | Agent 回報磁碟、分割區、掛載與用量分類，Core 保存並以 API 提供容量告警 | STO-001、STO-010 |
| 030.2 | 儲存與備份頁、主機磁碟頁與總覽的磁碟畫面 | 無（畫面） |
| 030.3 | 快照與檔案備份分開管理 | STO-011 |

SMART、NVMe 健康與磁碟溫度由票 020.3 讀取，結果填進 030.1 的 `GET /management/v1/nodes/{id}/storage` 的 `devices[].health`。

## Acceptance criteria

- [ ] **STO-001** 維運者可以查看磁碟、分割區、檔案系統、容量、inode、溫度與健康資訊。 — 完成條件：來源不支援 SMART／溫度時標示不支援，不能顯示健康正常。（後端 030.1，健康與溫度 020.3，畫面 030.2）
- [ ] **STO-010** 維運者可以設定容量與健康告警。 — 完成條件：同時檢查可用位元組、inode 與備份暫存需求，不等寫滿才通知。（030.1；備份暫存需求 078，通知送出 081）
- [ ] **STO-011** 管理員可以管理快照與檔案備份，但清楚區分。 — 完成條件：快照不被宣稱為異地備份；沒有快照能力的檔案系統不顯示已完成快照。（030.3）
- [ ] （增補 03 51.6）設計時決定並寫進本票：平台資料磁碟不足時允許的清理類、搬移類工作清單（與 017 共同）。（030.1）
- [ ] （使用者 2026-11-12）磁碟用量的分類不能重複計算：每個路徑只算進一類，各類加起來等於已用空間。資料庫實例的資料目錄只算「資料庫」，不再算進「應用資料」；備份暫存目錄只算「備份暫存」；認不出是誰的算「其他」。用硬連結或共用層的映像只算一次。所有硬碟共用同一組分類（應用資料、資料庫、備份暫存、容器映像、作業系統與日誌、其他），每類在每顆硬碟上同名同色，沒有的類別不顯示。（資料 030.1，畫面 030.2）
