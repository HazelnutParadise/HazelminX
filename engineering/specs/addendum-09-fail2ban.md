# 規格增補 09｜Fail2ban 管理

- **狀態**：已核定。2026-11-08 使用者要求平台也要管理 Fail2ban 這類工具。
- **位置**：本增補是第 57 章，接在增補 08（第 56 章）之後。v1.1 原檔與 `SHA256SUMS.txt` 不改。需求 ID 以 `F2B-` 開頭，驗收案例從 `T-268` 開始編號。
- **細化的既有需求**：SYS-011（「維運者可以管理 FTP／SFTP、Fail2ban、防毒等基線既有工具」）、T-134、增補 03 的 ROB-010（管理路徑變更）與 ROB-014（多個防火牆）。
- **為什麼要細化**：SYS-011 只有一行，沒寫能管什麼。1Panel v2.4.1 的 Fail2ban 頁只管 SSH 一個 jail：封鎖時長、最大嘗試次數、比對時間、日誌路徑、受保護 Port，以及封鎖清單解封。本章以它為下限，補上多 jail、和平台防火牆對齊、不把自己鎖在外面，以及設定錯誤時不讓服務停擺。

## 57.1 範圍

- **一台主機一個 Fail2ban**：平台管理主機上既有或平台安裝的 Fail2ban（套件安裝，systemd 服務 `fail2ban.service`）。沒有安裝時，依 SYS-011 顯示安裝入口與會裝哪些套件。
- **管的東西**：服務狀態、全域預設值、每個 jail、允許清單、封鎖清單與歷史、篩選規則。
- **不管的東西**：Fail2ban 本身的程式碼與版本選擇；平台不另外實作一套暴力破解防護取代它。

## 57.2 設定怎麼寫

- **只寫 `.local` 與 `jail.d/`**：平台的設定寫在 `/etc/fail2ban/jail.d/hazelminx.local` 與 `/etc/fail2ban/filter.d/hazelminx-*.conf`，不改發行版提供的 `jail.conf`。寫入記進主機變更帳本（增補 07）。
- **管理員手寫的設定**：其他 `.local` 檔裡的 jail 標「控制者：作業系統」，照增補 03 機制一可以檢視與修改；改動寫回原檔並記帳本。
- **套用前檢查**：每次套用先跑 `fail2ban-client -t`。檢查失敗時不重新載入，畫面顯示原始錯誤（檔名與行號），目前執行中的設定不受影響。
- **套用後**：`fail2ban-client reload`；重新載入失敗或服務沒有起來時，自動回到上一版設定並再載入一次。
- **版本**：每次套用都是一個版本，可以比較、回到上一版（同增補 03「先比較才回滾」）。

## 57.3 Jail

| 欄位 | 說明 | 預設 |
|---|---|---|
| 啟用 | 開或關 | — |
| 日誌來源 | 檔案路徑或 systemd journal（`backend = systemd` 加篩選條件） | 依 jail |
| 篩選規則 | 內建（sshd、recidive）、平台提供（`hazelminx-zentinel`、`hazelminx-panel`）或自訂 | — |
| 受保護 Port | 封鎖時要擋的 Port | 依 jail |
| 最大嘗試次數（maxretry） | 在比對時間內失敗幾次就封鎖 | 5 |
| 比對時間（findtime） | 計算失敗次數的時間範圍 | 10 分鐘 |
| 封鎖時長（bantime） | 封鎖多久；可以設遞增（`bantime.increment`） | 1 小時，遞增上限 1 週 |
| 封鎖方式（banaction） | 寫進哪個防火牆 | 跟平台目前負責寫入的防火牆一致（ROB-014） |

- **平台提供的 jail**：
  - `sshd`：SSH 登入失敗。
  - `hazelminx-zentinel`：讀 Zentinel 的存取日誌，對 401／403 爆量與掃描路徑封鎖來源 IP。封鎖對象是「Zentinel 判定的真實來源 IP」，不是 Cloudflare 或上游代理的 IP（第 19 章可信 Header 規則）；經 Cloudflare Tunnel 進來的流量，在主機防火牆擋不到，改由 Zentinel 的封鎖清單處理並在畫面說明。
  - `hazelminx-panel`：管理入口登入失敗（與 IAM-012 的帳號鎖定並存，Fail2ban 擋的是來源 IP）。
  - `recidive`：被封鎖多次的 IP 長期封鎖。
- **自訂 jail**：選日誌來源、寫篩選規則（failregex／ignoreregex），存檔前可以拿最近 1,000 行日誌試跑（`fail2ban-regex`），顯示會命中幾行與前 20 個命中範例。

## 57.4 不把自己鎖在外面

- **允許清單自動包含**：
  - 目前操作者的連線來源 IP（第一次開啟這頁時提示加入）。
  - SET-003 的管理入口允許來源。
  - 控制中心與其他節點的 IP（Agent 通道）。
  - 本機（127.0.0.1、::1）。
- **自動加入的項目**標「平台加入」，使用者可以看到原因；移除時警告會影響什麼。
- **改到 sshd 或 hazelminx-panel jail 的設定**時，若新設定會讓目前操作者的來源 IP 在下一次失敗就被封鎖（例如允許清單移除了自己），套用前擋下並說明。

## 57.5 封鎖清單

- **一份清單**：安全防護頁的「封鎖與例外」把 Fail2ban、手動封鎖、WAF 與 Zentinel 的封鎖放在同一張表，每列標來源（哪台主機、哪個 jail 或誰手動）、原因、開始時間、剩多久。
- **動作**：解封（只解這台或所有主機）、延長、改成永久、加進允許清單。
- **跨主機**：預設各主機各自封鎖。可以開「一台封鎖，所有主機一起封鎖」，同步用平台的工作送出；主機沒有回應時排隊。
- **歷史**：保留 30 天的封鎖與解封紀錄，可以依 IP、jail、主機查詢。查到某個 IP 時，連到流量分析與 SSH 登入紀錄。

## 57.6 需求

| ID | 使用者需求 | 完成條件 |
|---|---|---|
| F2B-001 | 維運者可以看到每台主機的 Fail2ban 狀態，沒安裝時可以安裝。 | 顯示服務狀態、版本、jail 數、目前封鎖數；安裝前列出會裝的套件；寫入記帳本。 |
| F2B-002 | 維運者可以管理多個 jail 與全域預設值。 | 涵蓋 57.3 表中所有欄位，以 1Panel 的封鎖時長、最大嘗試、比對時間、日誌路徑、受保護 Port 為下限；平台設定只寫 `.local` 與 `jail.d/`。 |
| F2B-003 | 套用前先檢查，失敗不影響執行中的設定。 | `fail2ban-client -t` 失敗時不重新載入並顯示檔名與行號；重新載入失敗自動回到上一版；每次套用是可比較、可回到的版本。 |
| F2B-004 | 封鎖方式跟平台負責寫入的防火牆一致。 | 依 ROB-014 選定的防火牆決定 banaction；兩者不一致時標出並提供改正。 |
| F2B-005 | 平台提供 Zentinel、管理入口與 recidive 的 jail。 | Zentinel jail 封鎖真實來源 IP；經 Tunnel 的流量改由 Zentinel 封鎖並說明原因。 |
| F2B-006 | 自訂篩選規則可以先試跑。 | 用最近 1,000 行日誌試跑，顯示命中數與前 20 個範例。 |
| F2B-007 | 允許清單自動包含操作者來源與管理路徑，套用前擋下會把自己鎖在外面的設定。 | 自動加入的項目標原因；移除時警告；57.4 的情況套用前擋下。 |
| F2B-008 | 所有封鎖放在同一張清單，可以解封、延長、改永久、跨主機同步。 | 來源、原因、剩餘時間；解封可選單台或全部；跨主機同步預設關，開啟後經工作送出；保留 30 天歷史。 |
