# 規格增補 10｜用公司帳號登入（OIDC）

- **狀態**：草案，待使用者核定。2026-11-14 使用者在畫布上問「OIDC 的連接方法是否有規劃」並要求規劃。
- **位置**：本增補是第 58 章，接在增補 09（第 57 章）之後。v1.1 原檔與 `SHA256SUMS.txt` 不改。需求 ID 以 `OID-` 開頭，驗收案例從 `T-276` 開始編號。
- **細化的既有需求**：IAM-010（「管理員可以選配外部身分登入，仍保留本機救援帳號」）。也受 IAM-002、IAM-003、IAM-009、IAM-011、IAM-012 約束。
- **為什麼要細化**：IAM-010 只有一行，沒寫用哪種協定、怎麼設定、誰可以登入、角色怎麼對應、公司的登入服務掛掉時怎麼辦。登入頁的畫板已經有「以公司帳號登入」按鈕，但後端沒有對應的 API，票 119 因此沒有實作這顆按鈕。

## 58.1 範圍

- **做**：OpenID Connect（授權碼流程加 PKCE）。這是 Okta、Microsoft Entra ID、Google Workspace、Keycloak、Authentik、Logto 都支援的方式，設定只需要一個發行者網址、用戶端 ID 與用戶端密鑰。
- **不做**：SAML、LDAP 直接綁定、同時設定多個登入服務、由登入服務主動通知登出（back-channel logout）、SCIM 自動同步帳號。之後要做再另開增補。
- **不變**：本機帳號（密碼加二次驗證）永遠存在。API Token 與公司帳號登入無關，不受影響。

## 58.2 設定

位置在「平台設定 › 管理入口與安全 › 公司帳號登入」，只有擁有者可以改。

- **要填的**：
  - 發行者網址（issuer），例如 `https://login.example.tw`。平台從 `<發行者網址>/.well-known/openid-configuration` 讀出其他端點，不要求使用者逐一填寫。
  - 用戶端 ID 與用戶端密鑰。密鑰存進機密庫，畫面與 API 都不回傳。
  - 按鈕上顯示的名稱，例如「Hazelnut 帳號」。登入頁的按鈕寫「以 Hazelnut 帳號登入」。
- **平台給的**：回呼網址 `https://<管理入口>/auth/oidc/callback`，可以複製，貼到登入服務那一邊。管理入口有多個網址時列出每一個。
- **啟用前一定要測試**：按「測試登入」會開新視窗走一次完整流程，成功後顯示平台讀到的資料（穩定識別碼、email、是否已驗證、群組），以及「這個人登入後會得到什麼角色」。沒有成功測試過就不能啟用。
- **要求的範圍**：`openid`、`email`、`profile`。群組用的 claim 名稱可以設定，預設 `groups`。
- **對外連線**：控制中心要連得到發行者網址。連不到時，設定頁寫出是 DNS、TLS 還是逾時，不寫成「設定錯誤」。

## 58.3 誰可以登入

- **預設只有已經被邀請的人**。管理員在邀請時選「公司帳號」，填對方的 email。對方第一次用公司帳號登入時，登入服務回傳的 email 相同且標示已驗證，才把這個平台帳號和登入服務的穩定識別碼綁在一起。
- **綁定之後只認穩定識別碼**（發行者網址加 `sub`），不再看 email。對方在公司改了 email 不影響登入，也不會因為別人拿到同一個 email 而登入成他的帳號。
- **自動建立帳號預設關閉**。打開時必須同時設定「允許的 email 網域」與至少一條角色對應，否則不能儲存。
- **沒被邀請、也不符合自動建立條件的人**：登入服務那邊登入成功，回到平台時看到「這個公司帳號還沒有被加入 HazelminX」與管理員的聯絡方式，不建立任何帳號。

## 58.4 角色對應

- 一條對應是「群組名稱 → 角色與資源範圍」，例如 `ops` → 維運者（全部主機）。
- 一個人符合多條時，權限取聯集。
- **擁有者角色不能透過對應給出**，只能由現有的擁有者在平台上手動指派。
- **預覽**：設定頁可以輸入一個群組清單，或直接用最近一次測試登入讀到的群組，顯示「會得到哪些角色」。儲存對應之前，列出目前已綁定的帳號裡誰的權限會變多、誰會變少。
- **每次登入重新計算**。對方在公司被移出群組後，下次登入就失去對應的角色。手動指派的角色不受對應影響。

## 58.5 二次驗證與工作階段

- **二次驗證預設由平台自己做**：用公司帳號登入後，仍然要過平台的 TOTP 或 Passkey，高權限角色尤其如此（IAM-002、IAM-011）。
- **可以改成由公司帳號負責**：擁有者可以選「登入服務已經做過二次驗證就不再問」。這時平台要求 ID Token 的 `amr` 或 `acr` 表明做過多因子驗證，值可以設定。沒有帶或不符合時，退回平台自己的二次驗證，不直接放行。
- **工作階段**：公司帳號登入的工作階段最長 12 小時（可設定 1～24 小時），到了就要重新走一次登入服務。這是對方在公司被停用之後，平台最晚多久會擋下他。要立刻擋，管理員在平台上停權（IAM-009）。
- 平台不保存登入服務的存取權杖與更新權杖，登入完成後就丟掉。

## 58.6 公司的登入服務出問題時

- **本機登入永遠可用**。登入頁永遠保留帳號密碼的表單，不提供「只允許公司帳號」的開關。
- **至少要有一個本機擁有者帳號**（密碼加二次驗證）。最後一個本機擁有者不能被刪除、停權或改成只用公司帳號。
- 登入服務連不上、回應錯誤或簽章驗不過時，登入頁在按鈕下方寫「公司帳號登入目前不能用」，不影響本機登入。原因記在稽核紀錄，不顯示給未登入的人。
- 離線救援（IAM-008）不受影響。

## 58.7 安全要求

- 每次登入都帶一次性的 `state`、`nonce` 與 PKCE；`state` 綁定發起登入的瀏覽器，只能用一次，10 分鐘過期。
- 回呼網址完全比對，不接受登入服務回傳的任意轉址。登入後要去的頁面只接受站內路徑。
- 驗 ID Token 的簽章、`iss`、`aud`、`exp`、`nonce`。只接受 RS256、ES256、EdDSA，不接受 `none` 與對稱式演算法。時鐘誤差容許 60 秒。
- 簽章金鑰從登入服務的 JWKS 取得並快取；遇到沒看過的金鑰編號時重新抓一次，並限制重抓頻率。
- 公司帳號登入一樣受登入次數限制（IAM-012），回呼端點另外限流。
- 稽核紀錄：設定變更、測試登入、每次登入成功與失敗（含原因）、綁定、角色對應造成的權限變化。
- **改發行者網址**：已經綁定的帳號是綁在舊的發行者上，改了之後這些人不能用公司帳號登入，要重新綁定。儲存前列出受影響的帳號並要求確認。

## 58.8 需求

| ID | 需求 | 完成條件 |
|---|---|---|
| OID-001 | 擁有者可以用發行者網址、用戶端 ID 與密鑰設定公司帳號登入。 | 端點由探索文件讀出；密鑰存機密庫且不回傳；回呼網址可複製；連不到時說明是 DNS、TLS 或逾時。 |
| OID-002 | 啟用前必須成功測試登入一次。 | 測試結果顯示穩定識別碼、email、是否已驗證、群組與會得到的角色；沒有成功測試不能啟用。 |
| OID-003 | 被邀請的人第一次用公司帳號登入時完成綁定，之後只認穩定識別碼。 | email 相同且已驗證才綁定；綁定後對方改 email 仍可登入；同一 email 的另一個識別碼不能登入成他。 |
| OID-004 | 沒被加入的公司帳號不會得到平台帳號。 | 自動建立預設關閉；打開時必須設定允許的網域與角色對應；不符合的人看到說明，不建立帳號。 |
| OID-005 | 群組可以對應到角色與資源範圍，並有預覽。 | 多條取聯集；不能對應出擁有者；儲存前列出誰的權限會變；每次登入重新計算。 |
| OID-006 | 二次驗證預設由平台做，可以改成由公司帳號負責。 | 改成由公司帳號負責時要求 `amr` 或 `acr` 符合設定；不符合時退回平台的二次驗證。 |
| OID-007 | 公司帳號登入的工作階段有最長期限。 | 預設 12 小時、可設 1～24 小時；到期要重新走登入服務；平台停權立即生效。 |
| OID-008 | 登入服務出問題時，本機登入與救援不受影響。 | 登入頁永遠有本機表單；最後一個本機擁有者不能被刪除、停權或改成只用公司帳號；錯誤原因進稽核、不給未登入者看。 |
| OID-009 | 登入流程驗證 `state`、`nonce`、PKCE、回呼網址與 ID Token。 | 重放、換掉 `state`、錯的 `aud` 或 `iss`、過期、`none` 或對稱式簽章、任意轉址都被拒絕並記錄。 |
| OID-010 | 改發行者網址前列出受影響的帳號。 | 確認後才儲存；舊綁定保留但不能登入，直到重新綁定。 |

## 58.9 驗收案例

| 編號 | 情境 | 預期 |
|---|---|---|
| T-276 | 填入發行者網址，但控制中心解析不到那個網域。 | 設定頁寫「解析不到 login.example.tw」，不能儲存成啟用。 |
| T-277 | 設定完成、還沒測試登入就按啟用。 | 被擋下，提示先測試登入。 |
| T-278 | 邀請 mei@example.tw（公司帳號）。她用公司帳號登入，登入服務回傳同一個 email 且已驗證。 | 綁定成功並登入；稽核記一筆綁定。 |
| T-279 | 同上，但登入服務回傳 `email_verified: false`。 | 不綁定、不登入，說明 email 尚未驗證。 |
| T-280 | mei 在公司把 email 改成 mei.lin@example.tw 後再登入。 | 仍然登入成原本的平台帳號。 |
| T-281 | 沒被邀請的 bob@example.tw 用公司帳號登入，自動建立是關的。 | 看到「這個公司帳號還沒有被加入 HazelminX」，沒有新帳號。 |
| T-282 | 新增對應 `admins` → 擁有者。 | 不能儲存，說明擁有者只能手動指派。 |
| T-283 | 登入服務停機，使用者打開登入頁。 | 公司帳號按鈕下方寫目前不能用；本機帳號照常登入。 |
| T-284 | 攻擊者把回呼請求的 `state` 換成另一次登入的值，或重送同一個回呼。 | 兩者都被拒絕並寫進稽核。 |
| T-285 | 嘗試停權最後一個本機擁有者。 | 被擋下，說明至少要保留一個本機擁有者。 |
