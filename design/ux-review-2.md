# 第二輪無脈絡審查（2026-11-08）

## 怎麼做的

- **審查者**：三位全新對話的審查者（Opus 5.5），沒看過規格、設計說明或這次的討論。扮演同一種人：全端工程師，專案放 GitHub、repo 裡有 `docker-compose.yml`，平常在主機上 `git pull` 再 `docker compose up -d`，用過 Portainer、1Panel、Zeabur。
- **素材**：73 個畫板的可點 HTML，以及 1440 與 360 寬的截圖。三人各看一區：第一次使用與主機、部署與應用、資料安全與管理。
- **要找的東西**：小地方，而且要指得到元素。分七類：
  - A 文字不清楚
  - B 字太多
  - C 不方便
  - D 不知道怎麼用
  - E 頁與頁接不起來或資料對不上
  - F 邏輯死角
  - G 缺的需求
- **結果**：約 200 條，其中「擋住」13 條。

## 根本原因與共用修正

大部分問題來自同一條規則沒守住，所以改在共用元件或寫成規則，一次修掉一整類。規則寫在 DESIGN.md「情境與動作要一致」。

| 問題 | 例子 | 修正 |
|---|---|---|
| 主機分頁跳到別台 | 失聯的 jp-02 點「系統」打開 tw-01；系統頁標 tw-01 卻是 jp-02 的 Debian 資料 | 系統頁改成 tw-01 的實際資料（Ubuntu 24.04、核心 6.8）；主機沒有回應時分頁停用，不跳台 |
| 失聯主機的按鈕照樣能按 | jp-02 的終端機、檔案、SSH、安全更新 | 停用並寫原因；能排隊的寫「排入，恢復後套用」 |
| ⌘S 觸發部署 | 環境變數頁的主要鈕是「儲存並重新部署 ⌘S」 | 主要鈕一律是「儲存」，部署另一顆 |
| 分頁列數字和畫面對不上 | 「顯示 1–9 / 17 · 每頁 50」 | 分頁元件依畫面列數算每頁筆數；上一頁改向左箭頭 |
| 部署的圖例套到別的東西 | 告警規則、資料變更、稽核都用「成功／失敗／回滾」 | 時間軸分部署、告警、排程三種圖例；每格都有提示 |
| Git 來源的檔案改了去哪不清楚 | compose 編輯器、檔案頁的 .env | 存檔時選覆寫層、開 PR 或新分支；變數組產生的檔案警告會被蓋回 |
| 同一件事多種叫法 | 節點／主機、Core／控制中心、狀態過期／沒有回應／失聯、第二驗證／二次驗證 | 全站統一 |

## 這輪新增的畫板

- **物件儲存**：預設 RustFS，可以管理 bucket、存取金鑰、瀏覽物件、分享連結，也能遷移既有的 MinIO（規格增補 08）。
- **專案 › 自動部署**：
  - 每個環境聽一個分支、分支樣式或標籤樣式，觸發方式是 Webhook 或定期檢查。
  - 可以設路徑篩選、略過標記，處理連續 push，回寫狀態到 GitHub。
  - 顯示 Webhook 最近收到的事件，以及最近每次觸發的結果。
- **部署前檢查（compose 寫法）**：
  - 以 n8n-stack 為例，列出外部網路、container_name 衝突、資料目錄不存在、寫死的機密、Port 開到所有位址。
  - 也列出跨專案依賴與掛載路徑。
- **Fail2ban**：
  - 每台主機的服務狀態，可以管多個 jail。
  - 套用前先檢查，失敗就沿用上一版設定。
  - 篩選規則可以先試跑。
  - 允許清單會自動加入操作者自己，不會把自己鎖在外面。
  - 封鎖清單和 WAF、手動封鎖合成一張表（規格增補 09）。
- **還原備份**：見上表。
- **機密庫**：
  - 列出每個機密誰在用、多久沒輪替、哪天到期。
  - 可以輪替。
  - 從平台設定的分頁進入。
