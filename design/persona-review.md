# 五種使用者實際操作審查

2026-11-08。五位審查者沒有看過設計討論，各自扮演一種使用者，把所有畫面走過一遍，並完成同一組十二個任務。這份文件記錄他們卡在哪裡、介面怎麼改，以及還需要決定的事。

## 方法

| 身分 | 背景 |
|---|---|
| 咖啡店老闆 | 完全沒有工程背景，只用過 Shopify、WordPress 後台 |
| 前端工程師 | 會用 React、git，沒架過伺服器，沒用過部署工具 |
| 習慣 Zeabur 的全端工程師 | 平常用 Zeabur、Vercel、Railway，會用 Docker，不熟 Linux 管理 |
| 資深 SRE | 不靠面板也能部署，只在面板比命令列快、準時才用 |
| 用賈伯斯的標準看產品 | 在意簡單、專注、第一眼看到什麼 |

- 審查素材：每個畫面的可點 HTML 設計稿，加上 1440 與 360 寬的截圖。素材另外放在一個獨立資料夾，五位都沒有改動。
- 十二個任務：
  1. 第一次登入。
  2. 加一台主機。
  3. 從 GitHub 部署網站，並設定網址和 HTTPS。
  4. 半夜處理主機失聯。
  5. 改 `.env`。
  6. 找出變慢的容器並重啟。
  7. 擋掉對外的資料庫 Port。
  8. 設定備份並確認能還原。
  9. 套用安全更新。
  10. 新增排程。
  11. 開一個唯讀帳號。
  12. 把全部畫面看過一遍。
- 審查模型：Claude Opus 5.5，每位各開一個新的對話。原本要先派 agy 的 Opus 和 Codex 的 sol：agy 的 Opus 額度已用完，Codex 沒有符合條件的 sol 模型。

個別審查者提到、也已經處理的：

- **資深 SRE**：防火牆範例的 `nft add rule inet filter DOCKER-USER` 不會生效，因為 Docker 的 DOCKER-USER 鏈在 iptables 的 filter 表。範例改成 `iptables -I DOCKER-USER … -m conntrack --ctorigdstport`。
- **賈伯斯**：頂列「工作」圖示和側欄重複，已拿掉。總覽的「表格檢視」連錯頁，改成「全部主機」。
- **咖啡店老闆、Zeabur 使用者**：排程時間撞到備份與維護時段時，畫面會提醒。新增備份前若已有同一個資料庫的任務，也會提醒。
- **SRE、賈伯斯**：Nextcloud 安裝預設重用正式的 shop-db，改成預設新建專用資料庫。
- **前端工程師、SRE**：容器的「重啟」改成「重啟這個副本」和「滾動重啟 2 個副本」兩個按鈕。

## 已決定不做

- **不寫 Dockerfile 也能部署（自動偵測框架）**：2026-11-08 決定不做，維持規格 CMP-008：只支援 compose 與 Dockerfile。倉庫兩個都沒有時，畫面說明缺什麼。
- **簡易模式（隱藏進階選單）**：2026-11-08 決定不做，側欄維持同一套。

## 待決定

這幾項會改動產品範圍或規格，沒有直接動手：

1. **用 Email 重設密碼**：規格 IAM-008 禁止匿名的網頁重設入口，目前改由管理員重設，或在主機上用救援指令。
2. **不用打指令就能加主機**（例如輸入 SSH 帳密讓平台代裝）：規格目前只有註冊碼加安裝指令。
3. **總覽區塊太多**：賈伯斯認為總覽只該放「需要處理」和主機狀態，圖表移到各自的頁面。目前保留圖形為主的總覽，只調整手機版的順序。

## 還沒處理

- **術語**：Zentinel、漂移、無鎖、引擎環境等詞，畫面上還是沒有白話說明。
- **主機概況資訊過量**：主機概況的溫度感測器、GPU 規格等細節還沒收合。
- **主機分頁的「容器」**：點了會跳到全站的容器頁，離開這台主機的工作區。
- **只畫一份的詳細頁**：同類型的詳細頁只畫了一個例子，例如每個容器都連到 shop-api-1。這是設計稿的限制，實作時每列連到自己的頁面。
